# User Stories

## Preamble
These user stories are using the Gherkin Given, When, Then format. More [here](https://cucumber.io/docs/gherkin/reference) and [here](https://testsigma.com/blog/behavior-driven-development-bdd-with-gherkin/)

## Use case specifics: Who is SIEVE for?
Given that I don't have enough footage for training, when I use SIEVE, then I can quickly get behavioral annotations on a strong signal.

Given that I'm unsure about a project's feasibility, when I use SIEVE, then I can assess the difficulty of the project with benchmarks.

Given that I have poor recording footage, when I use SIEVE, then I can extract research data from footage that is otherwise incompatible with other programs that have stricter quality requirements.

Given that I have a weak computer, when I use SIEVE, I can leverage my university's HPC resources.

Given that I am inexperienced in computer vision, when I use SIEVE, I can utilize it to learn signal processing basics interactively.

Given that I am experienced in computer vision, when I use SIEVE, I can leverage my knowledge to compose complex signal transformations.

Given that I have low storage availability, when I use SIEVE, the program adapts to the limit I set on cache availability.

Given that I have high storage availability, when I use SIEVE, I can leverage that to use SIEVE to quickly explore many options by aggressively setting checkpoint nodes.

Given that I am familiar with other CV approaches, when I use SIEVE, I can compare and contrast the different approaches and test different assumptions.

Given that I have low compute availability, when I use SIEVE, I can downsample or time sample to see the scale of the signal required.
