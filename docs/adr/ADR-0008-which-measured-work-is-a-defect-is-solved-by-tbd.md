An instrument produces numbers and nothing in a number says whether it is a
price or a mistake. Dense optical flow costs what it costs and that figure is
information; a frame decoded twice is wrong on any hardware. Which categories
are finite and drivable to zero — and whether the ones this tree named are —
has candidates and no measurement.

What the tree does now: cost is reported because it decides what a machine can
offer and is never a list of things to fix; waste is counted and its target is
zero. The four named are a frame decoded twice, a fetch a declaration predicted
(ADR-0006), a value recomputed that was already stored, and a render of a
superseded state.

Two clauses carry most of the weight. Work discarded on purpose is cost, not
waste — a coarse preview thrown away for a better one later is a choice with a
stated reason, and counting it buries the count in noise. And unattributed
elapsed time is not by itself waste: a large remainder reads as *the instrument
is incomplete*, not as a performance problem.

The product constraint — a graph refills faster than the video plays — is not a
budget. The source's frame period is the unit cost classes are measured in
(ADR-0007), not a target anything is held to; falling outside it produces a
class and a deliberate fallback, not a defect report. Where the account
surfaces is the walked step's own pane, position three on the right (ADR-0003),
with a small indicator where the work is.

## Candidates

Poppendieck's seven wastes of software development (*Lean Software
Development*, 2003) — Ohno's muda ported to software as a named taxonomy of
categories each driven to zero, with no target on the work that adds value.
Would have to be measured on the claim this tree already made: that the four
named categories are finite and reach zero. `predicted` is the one ADR-0006
targets at zero and the orchestrator shelf already counts, so the experiment
exists in outline.

Muratori's non-pessimization — the line between optimization, which chases a
target and has diminishing returns, and simply not doing work that never needed
doing, which is neither. Closest to the wording here, and would have to be
checked against the speculation carve-out above, which Lean would classify as
overproduction and this does not.

Brooks's essential and accidental complexity (*No Silver Bullet*, 1986) — the
same split one level up, at design rather than at runtime. Listed because it is
the ancestor and probably loses: it names the distinction and gives an
instrument nothing to count.

## Rejected

A fixed performance budget cautionary tale: RAIL's 100 ms response and 16 ms
frame are figures content growth exceeds, so the practice manufactures
optimisation work with no terminating condition. Here a figure would be
exceeded by longer footage, higher resolution, one more step, or a weaker
machine — of which three move the cost class, which is what a class is for,
and longer footage never reaches it at all, because a refill is over a window
and a window does not grow with the file.

Google SRE's toil budget cautionary tale: it names the waste category
correctly — manual, repetitive, automatable, devoid of enduring value — and
then holds it under 50% rather than to zero. Right taxonomy, wrong refusal:
a waste category with a budget is a category somebody has agreed to keep
producing.

Cost-as-a-target cautionary tale: it contradicts ADR-0007, where a cost class
belongs to the pairing and is measured where it runs, so a slower machine
falls back deliberately rather than chasing a figure set on someone else's
hardware.
