# Session record — 2026-08-02 — hardening dissolved

Status: Frozen

A primary record (tier 3). It holds the argument that removed hardening
as owed debt from the PAR class: acceptance is a readiness judgment, a
deliberate attack session is a route to it convened at judgment, and
nothing owes a hardening session. PAR-0001's Status and session-kind
passages were rewritten from this argument in the same commit.

## Exchange 1 — The occasion

A skeptic review of the distill-plan rewrite flagged that the plan's
acceptance choreography leaned on acceptance-as-event while PAR-0001
carried Kendrick's standing doubt against hardening's necessity (logged
2026-08-02, `SESSION-2026-08-02-template-convention.md` Exchange 2).
Asked whether the review's hard questions hid real ambiguity, the
assessment was: the only item with lasting effects was that doubt, and
it was already filed where it should be, cheap to act on whenever it
resolved. It resolved immediately.

## Exchange 2 — The resolution

Verbatim:

> "yeah genuinely hardening shouldn't be a required debt of anything,
> it shouldn't exist as anything but a case alternative to a PAR that
> can't be implemented without being accepted, and there should
> already be the inbetween where the PARs exist as effectively
> implemented but open to argued improvement, which is basically every
> PAR since they're living documents. I just don't want that to be
> interpreted in any scenario as an excuse to update the PAR for free:
> you just added the argumentation for why PAR needs to be updated,
> the session log for that is right here, it lands as an update and
> reference within the PAR itself and everything is unblocked"

Three moves, compressed:

1. **Hardening is never owed.** It survives only as a route to
   acceptance for a record that cannot be trusted to govern without
   surviving an attack — convened at the author's judgment, the same
   human-read tipping point as friction confirmation and template
   owing. Not a lifecycle stage, not debt, no trigger.
2. **The in-between state already existed.** "Effectively implemented
   but open to argued improvement" is not a new status — it is what
   Accepted already means for a living record. The hardening overlay
   had made Accepted mean "survived attack," which parked records in
   Proposed against a session nothing actually required.
3. **The guard: a decision never moves for free.** Dropping the
   hardening gate must not license free rewrites. The discipline is
   the existing primary-filing rule applied to edits: an edit that
   changes what a record decides carries its argument — the session
   that argued the change files its record and the rewrite cites it.
   This landing is the demonstration: the argument is this file, and
   PAR-0001 cites it.

## What lost

- **The trigger machinery.** The `DEFERRED.md` entry ("due when the
  decision is truly load-bearing"), the status line as un-hardened
  debt marker, and "Accepted means it survived a session that attacked
  it." The grep derivation of Proposed records survives with a new
  meaning — records not yet governing — because that state is real
  regardless of what a record awaits.
- **PAR-0001's named exception.** "Accepted while still owing its
  hardening session" dissolves with the debt it named; the founding
  record is simply Accepted.
- **The counterweight, absorbed rather than refuted.** The
  template-convention session had recorded: hardening is timing
  insurance — organic challenges probe what usage happens to touch,
  while the trigger front-runs the moment where being wrong is
  expensive. Under the resolution the insurance is still purchasable:
  when load approaches, the author convenes the attack. What changes
  is who calls it and when — judgment, not a standing trigger — which
  is how every other tipping point in this repo already works. The
  residual exposure is named and accepted: a judgment can be late
  where a trigger would have fired.
- **The standing Challenges entry.** The doubt's entry comes out of
  PAR-0001 — a doubt that breaks is not an entry; the record is
  rewritten and this file holds the history.
