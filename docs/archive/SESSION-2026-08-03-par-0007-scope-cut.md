## Exchange 1 — The filter the rationale states against itself

PAR-0007's Context contains an admission rule: the rationale holds
"exactly the claims whose cost of being wrong later is a rewrite or a
migration of stored results, and nothing else." Applied section by
section against the Decision, three did not survive it.

The yardstick section — a tool declares what its output means, never a
verdict — settles a declaration surface whose only consumer is the
harness, which is deferred behind a trigger no operation can fire yet.
The rationale had already argued, twenty lines earlier, that a declared
list of inputs was refusable precisely because "adding an argument
after tools exist rewrites every tool; adding a declaration later adds
to them." A yardstick is a declaration. The rationale refuted its own
section without noticing.

The Step/Task section states a naming already settled at Exchange 2 and
already cited in `ARCHITECTURE.md`. Vocabulary is free to change.

The method-placement section defended itself with "it costs nothing
today, since cropping and downsampling have no method choice at all,"
which argues cheap *adoption*. The filter asks about cheap *reversal*.

## Exchange 2 — Two findings that were not scope

Separate from the filter, two claim-versus-tree contradictions. First,
PAR-0007 fixes `lower(self, p, inputs)` while `src/sieve/tools/base.py`
carries `lower(self, p)` under a docstring calling its signatures
quotations from the settled record; the Consequences amended
`ARCHITECTURE.md` and `README.md` and never named the code marker, so
acceptance would have made a live marker's quotation false through a
channel the automatic ledger cannot see — the marker enumerates fine,
it is merely wrong.

Second, the Consequences claimed `PLAN-TOOL-CONTRACT.md` Phase 3's
first gate was "settled here" while `DEFERRED.md` still recorded the
tool-to-dispatch-table bridge as open. What PAR-0007 supplies is that
inputs are typed and eligibility is answerable from the tool's class;
what the gate asks for is the bridge, which the plan itself says the
record cannot arbitrate.

## Exchange 3 — The correction that survived review

The review's first pass grouped method placement with the failures.
That was wrong on the axis: misplacing a knob is a schema migration
plus a changed hash for every result that used it, which is exactly
what the filter admits. The section keeps its place; only its argument
was restated. The initial claim that "roughly half the Decision fails"
was also too broad — the filter governs which new rulings a rationale
settles, not which arguments it makes about rulings already settled
elsewhere, which is what keeps the violation-detector section and the
Context's evidence in the file.

## Exchange 4 — The straddle nobody caught

PAR-0007's acceptance was set to correct `ARCHITECTURE.md`'s GUI
sentence from "generated by walking the tool's `Params`" to "combines
the tool's settings with those of the chosen operation" — while
conceding in the same bullet that "the rule itself is PAR-0013's."

That is a rule owned by an unwritten rationale, resting on a
method-settings decision the same document called costless today,
landing in tier 1 under a different rationale's acceptance. It is the
same straddle that had already forced the PAR-0020 split, caught there
and not here. Resolution: strike only the false narrowing. Tier 1 says
the panel is generated from the declared settings without saying whose,
and PAR-0013 rules what replaces it.

## Exchange 5 — The diagram forbidden by its own bullet

The Consequences reject a second run diagram — "two diagrams sharing
parts would have to be kept consistent by hand" — in the same document
that contains one. Both figures were kept, because they do different
work: `ARCHITECTURE.md`'s is dataflow, PAR-0007's labels who performs
each arrow, which the rationale states outright. What changed is the
repair: the tier-1 diagram gains only the chosen-method attachment and
deliberately *not* the performer labels, so the two never have to agree
edge for edge.

## Exchange 6 — Kendrick's ruling

> "What you said to change, agree. I genuinely believe in the verbatim
> thing at the top of the PAR, and if anything I think it's a pretty
> clear signal that if everything else has to change around it then the
> tool contract should have been written first :')"

The epigraph survived the cut untouched, and the two sections that
implement its claim — the violation detector and the diagram's
names-something-unbuilt edge — both stayed.

On written-first the position was split rather than accepted. The
*decisions* could not have come first: PAR-0007's graph return type
presupposes op-as-value, its absent preferences argument is PAR-0006's
mechanism, and its yardstick section exists only because PAR-0005
routed one there. Written at position 5 it would have had to invent all
of that, and the claim it would most likely have guessed wrong is the
return type, which is the one door that cannot be walked back.

The *boundary* is a different matter, and there the position holds.
What the review found being corrected — `ARCHITECTURE.md`'s GUI
sentence, `base.py`'s signature quotation, PAR-0005 routing a
declaration to a rationale that would refuse it — are not wrong
decisions. They are documents filling a vacuum because nobody had
claimed the territory, which is the epigraph's own claim arriving as
evidence.

## Exchange 7 — What that produced

The fix was already in the tree and unnoticed: PAR-0020's stub states
Owns, Borders and an itemized never-list at filing, while PAR-0008
through PAR-0019 hold a marker and nothing else. The difference is not
content — PAR-0019's marker carries as much border material as
PAR-0020's body — but *position*. Rule v2 permits one marker per file,
so anything stuffed into marker text becomes a single run-on line, and
nobody scanning for "does someone already own this?" reads marker
prose.

> "Agreed, lets adopt that from par20. Lets cite it as evidence for the
> template PAR"

Two limits were stated with the adoption rather than discovered later.
A border statement would not have stopped `ARCHITECTURE.md:99` or
`base.py`; what it buys is that the territory is greppable while still
unsettled, so an assertion into it is visible rather than silent. And
borders are backfilled when a stub is next touched, never in a sweep,
because most stubs would be inventing a border today — PAR-0019's seam
against PAR-0012 is genuinely its first open question.

acceptance itself — the roll-up amendments this record now specifies —

## What lost, and why it is kept

**Compressing the evidence section.** The review recommended cutting
PAR-0007's four-class comparative argument to the boundary paragraph
and the v1 exhibit. Kendrick never agreed, and the later drafting
how-to makes the four-class sweep a required step, so the
recommendation is withdrawn rather than deferred. What survives of it
is the reading that the *sweep* belongs in the session file and the
*transfer statement* is what reaches the rationale.

**Blocking acceptance until Phase 4's worked examples exist.** Raised
and rejected: Phase 2's gate 2 is waiting on PAR-0007's graph return
type, so blocking acceptance on Phase 4 inverts the dependency.
