# Benchmark gate measures nothing

`bench/budgets.py:check()` had no call site outside its own unit test.
Non-negotiable #4 — a budget miss is a defect, not a tradeoff — was therefore
enforced by one hand-run measurement recorded in a document, and CI reported
green on a session that skipped all 181 tests.

Two checks now call `check()` against a real `VideoPlayer` driving the real
decode thread: open → first frame, and scrub release → exact frame. The second
issues `scrub()` then `seek()` with no wait between them, because the worst
case `scrub_settle` covers is one in-flight decode that cannot be cancelled
plus the exact one, and a release measured against an idle decoder measures the
wrong thing.

They run in both sessions. `nox -s tests` passes `--benchmark-disable`, which
drops the timing rounds but still executes the body — so the assertion fires on
every change, not only when someone remembers to run the benchmark session.

## Checked by mutation

- Lowering `open_to_first_frame` and `scrub_settle` to 1 ms fails both checks
  with the measured overage in the message.
- Running the benchmark session with everything deselected exits 5 and fails
  the session, which is the behaviour the old `success_codes` forgave.

## The numbers are not comparable to the findings

The fixture is 160x120; the reference footage is 5312x2988. 13 ms and 23 ms
here say nothing about the 213 ms and 68 ms recorded in `docs/findings/`. The
job is catching a regression that blows past a ceiling by an order of
magnitude, not certifying the reference hardware — and a gate that needed the
reference clip would be a gate that never ran in CI.
