# Build the CLI

## What the item was actually for

`SCAFFOLD.md` calls the CLI "the canonical run path — built and tested before
GUI", and this repo built the GUI first, so the literal ordering was already
lost. What was recoverable is the reason: the executor is supposed to be the
single execution path, and the GUI is a poor witness to that because it can put
a frame on screen through a decode thread, a coalescer, and a display proxy
without `pipeline/executor.py` being involved at all. `tests/integration/
test_cli_run.py` is the first test in the repo that cannot pass unless the
shared path ran.

## The scope that was cut, and why it is not a deferral

SCAFFOLD lists five command modules. Three of them — `preview_cmd`,
`materialize_cmd`, `hpc_cmd` — each wrap a `pipeline/` module that does not
exist yet. Writing them now would mean inventing the interface of the thing
underneath from the outside, which is the direction that produces a command
whose flags the eventual module has to be contorted to fit. They are not in
`LATER.md` either: they are not deferred work with a trigger, they are the
visible half of items that already have their own gating (`pipeline/preview.py`
gates on the representative-clip range; materialization gates on Zarr layout).

What `sieve run` does refuse is worth stating plainly, because it is the one
place a user meets a gap rather than a feature: a project with `outputs` is
rejected with the sinks named. The alternative was to run the graph, report
success, and write nothing — and the whole of `cache_key.py`'s asymmetry
argument is that a wrong answer nobody can see costs more than an obvious
refusal.

## What was checked by mutation

Four deliberate breakages, four distinct failures:

1. **`inspect` stops calling `discover()`** and reads `REGISTRY` directly.
   Only `test_the_listing_finds_a_filter_in_a_process_that_imported_nothing`
   fails, and only because it shells out — run in-process, every test in the
   file passes, because by then the suite has imported `sieve.filters` for its
   own reasons. This is why that one test is a `subprocess.run` and the rest are
   `CliRunner`: the user's `sieve inspect` is a fresh interpreter, and no
   in-process test can be made to be one.
2. **The store moves inside the per-replicate loop.**
   `test_two_replicates_run_and_the_second_reuses_the_first` fails on the second
   replicate's line reporting four computed rather than four from cache. Nothing
   else notices, which is the point — the frames are identical either way.
3. **The sink refusal is bypassed.**
   `test_declared_outputs_are_refused_rather_than_ignored` fails; the run
   otherwise completes successfully and writes nothing.
4. **`--dry-run` falls through to the container for a clipless project.**
   `test_a_dry_run_never_opens_the_video` fails on its second invocation. The
   first invocation does not catch it, because a project *with* a clip never
   reaches that branch — which is exactly the case a regression would slip
   through on.

## What changed outside the item's scope

`.importlinter` gained `sieve.cli` in two contracts beyond removing its
parentheses from the layer stack. The headless contract is the load-bearing
one: the layers contract puts `sieve.gui | sieve.cli` at the same layer, so it
is structurally unable to say that one of them may import PySide6 and the other
may not. The opencv addition is cheaper — the CLI has no reason to touch `cv2`
directly, and the contract's own rationale (one module driving `VideoCapture`
is one decoder identity no cache key knows about) reaches a front end exactly
as it reaches `sieve.gui`.

`inspect` reads parameters out of `params_model.model_json_schema()` rather
than out of `model_fields`. The reason is `factor`'s `ge=2, le=64`: pydantic
stores constraints as `annotated_types` objects, and unpacking their reprs
would mean this module learning a representation that belongs to a dependency.
The schema is the model's own canonical self-description and is what a GUI
parameter panel would build widgets from, so both front ends end up reading one
thing.
