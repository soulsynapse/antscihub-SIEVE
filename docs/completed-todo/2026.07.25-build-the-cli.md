decisions:
  - what: one `MemoryFrameStore` spans the whole invocation, not one per replicate
    why: replicates in one equivalence group share keys, so the second computes nothing
  - what: a project declaring sinks is refused, not run
    why: no writer exists; running and writing nothing is a silent wrong answer
  - what: a dry run stats the footage but never opens it
    why: it is the only test `plan.py`'s no-codec claim has ever had
  - what: the span flag is `--frames START:END`, half-open, one option
    why: the two numbers are one quantity, and an inclusive end here would be the
      one place in the system where a range means something else
  - what: one `--backend` names every node's, defaulting to CPU
    why: a per-node mapping is what `ExecutionPlan` takes, but choosing per node
      needs a preference walk over the kernel shelf that belongs in `dispatch.py`
  - what: sieve.cli added to the headless and opencv-containment contracts
    why: the CLI is the front end whose point is running where Qt is not installed,
      and the layers contract cannot say so — it sits at `sieve.gui`'s layer

rejected:
  - what: the preview, materialize, and hpc commands SCAFFOLD lists under `cli/`
    why: each needs a module that does not exist (`pipeline/preview.py`,
      `pipeline/materialize.py`, a job-script writer); a command wrapping nothing
      is a command whose shape is guessed rather than derived
  - what: JSON output on `inspect`
    why: no consumer; the machine-readable form the HPC handoff wants is the
      project YAML, which already exists
  - what: writing sink outputs
    why: no writer exists (`pipeline/results.py` is unwritten), and it is its own
      item rather than a subclause of this one
