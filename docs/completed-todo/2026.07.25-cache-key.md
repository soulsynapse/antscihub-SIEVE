decisions:
  - what: node_key takes a Node and a Replicate, never a params dict
    why: applies resolved_params itself, so there is no argument position Node.params fits
  - what: the key is per node, folding in upstream keys, not per graph
    why: siblings share only their ancestors' keys, so guardrail §5 is structural
  - what: decoder identity folds into source_key, backend identity into every node
    why: one decoder per run reaches every node through ancestry; backends can differ per node
  - what: the replicate's ROI enters at source_key, not on the root node
    why: the graph never observes an uncropped frame — the crop is a property of what the fan-out handed it
  - what: params are validated against params_model before hashing
    why: canonical, not merely deterministic — an omitted field and its default are one key
  - what: upstream keys are sorted before hashing
    why: with no named ports on Edge a node's inputs are a set; edge declaration order must not invalidate
  - what: NotCacheableError rather than a returned None
    why: no key means no upstream hash downstream, so uncacheability propagates without anyone computing it
  - what: HASH_VERSION seeds every digest
    why: the only way to correct a derivation that was missing an input, short of touching every input
  - what: source_identity is path + size + mtime_ns
    why: content-hashing a multi-gigabyte video on every project open is in no budget

rejected:
  - what: hashing Node.params
    why: it is the default unconfigured replicates inherit and moves on every edit — twelve invalidations for a change one arena saw
  - what: a whole-graph keys_for() in cache_key.py
    why: needs a topological sort, which is dag.py's, and a second traversal is a second answer about what the graph is
  - what: clip range, checkpoints, sink paths, replicate_id in the key
    why: each changes which frames run, where a result lives, or what it is called — never what a frame is
  - what: a content hash of the source video
    why: a full read of the footage every time a project opens; the mtime failure mode requires deliberate effort to produce

# Cache key

`H(upstream_hash, filter_id, version, canonical_params_json, backend_id unless
backend_agnostic)`, as the TODO item specified, with two things the item did not
say out loud and one thing it left to be discovered.

## What the item did not say

**The signature is the guardrail.** The item's warning — "build it from
`pipeline_model.resolved_params`, never from the node's dict" — is a rule a
caller can break. Taking `Node` and `Replicate` and resolving inside `node_key`
makes it a rule nobody can reach: there is no parameter of type `dict[str, Any]`
to pass the wrong dict to. The documented version of this rule already exists in
three places; a fourth would have been the one that eventually drifted.

**Guardrail §5 is not checked, it is structural.** Nothing in `cache_key.py`
asks whether an edit touched a sibling. A key folds in its upstreams' keys and
nothing else, so two branches share their common ancestors and have no other
channel between them. The mutation below is what proves that claim is doing
work: adding one project-wide input to the digest breaks it while every other
test in the file still passes.

## What was checked by mutation

Four deliberate breakages, each caught by exactly one test and each a mistake
someone could plausibly make:

| Mutation | Caught by |
| --- | --- |
| hash `node.params` instead of `resolved_params(node, replicate)` | `test_a_pinned_replicate_ignores_the_default_moving_under_it` |
| hash the ROI's extent but not its origin | `test_the_crop_separates_two_otherwise_identical_replicates` |
| always include `backend_identity`, ignoring `backend_agnostic` | `test_backend_identity_leaves_the_key_only_when_the_filter_claims_agreement` |
| also fold in the replicate's whole `overrides` map | `test_editing_one_branch_leaves_its_sibling_valid` |

The last one is the one worth keeping. Folding in `overrides` is a reasonable
sounding instinct — the replicate's deviation is surely part of what it runs
with — and it is wrong precisely because it is not *this node's* deviation. It
made pinning a parameter on `b` invalidate `c`, which is guardrail §5 failing in
the form the guardrail was written to describe.

## What changed outside the item's scope

`.importlinter` gained `sieve.pipeline` in the `headless` contract as well as
losing its parentheses in the layer stack. The layer contract alone would not
have caught `pipeline/` importing PySide6 directly, only importing `sieve.gui`;
AUTO-GUARDRAILS §1 says "pipeline/ and bench/ import no Qt" and that sentence
had no machine-checked form until now.

`docs/TODO.md` gained rule 8 — build the checklist before the first edit — at
the user's request, and the DAG item gained a sentence saying it owns the walk
this module declines to carry.

## The one thing left open

`source_identity` is the weakest part of the derivation and knowingly so. Path,
size, and mtime is what build systems settle for, and it is wrong for a file
edited in place without changing either. The alternative is reading the whole
video on every project open, which is in no budget on this footage. If it ever
matters, the fix is a hash of the first and last megabyte plus the size, not a
full read — but nothing has needed it yet, and a partial hash that is *nearly*
content-addressed is arguably worse than a mtime nobody mistakes for one.
