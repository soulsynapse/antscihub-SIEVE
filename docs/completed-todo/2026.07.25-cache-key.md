# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: node_key takes a Node and a Replicate, never a params dict
    why: applies resolved_params itself, so there is no argument position Node.params fits
  - what: the key is per node, folding in upstream keys, not per graph
    why: siblings share only their ancestors' keys, so guardrail §5 is structural
  - what: decoder identity folds into source_key, backend identity into every node
    why: one decoder per run reaches every node through ancestry; backends can differ per node
  - what: the replicate's ROI enters at source_key, not on the root node
    why: the graph never observes an uncropped frame — the crop is a property of what the fan-out handed it
  - what: params are validated against params_model before hashing
    why: canonical, not merely deterministic — an omitted field and its default are one key
  - what: upstream keys are sorted before hashing
    why: with no named ports on Edge a node's inputs are a set; edge declaration order must not invalidate
  - what: NotCacheableError rather than a returned None
    why: no key means no upstream hash downstream, so uncacheability propagates without anyone computing it
  - what: HASH_VERSION seeds every digest
    why: the only way to correct a derivation that was missing an input, short of touching every input
  - what: source_identity is path + size + mtime_ns
    why: content-hashing a multi-gigabyte video on every project open is in no budget

rejected:
  - what: hashing Node.params
    why: it is the default unconfigured replicates inherit and moves on every edit — twelve invalidations for a change one arena saw
  - what: a whole-graph keys_for() in cache_key.py
    why: needs a topological sort, which is dag.py's, and a second traversal is a second answer about what the graph is
  - what: clip range, checkpoints, sink paths, replicate_id in the key
    why: each changes which frames run, where a result lives, or what it is called — never what a frame is
  - what: a content hash of the source video
    why: a full read of the footage every time a project opens; the mtime failure mode requires deliberate effort to produce
