# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: validation happens in Dag.build or not at all — no is_valid() on a constructed graph
    why: a checked and an unchecked graph would be one type, and the executor one forgotten call from walking a cycle
  - what: three rejections in a fixed order — unresolved filters, then cycles, then edge types
    why: a graph naming filters that do not exist has no meaningful cycle to describe, and ordering the type check needs the sort
  - what: UnresolvedFilterError reports every missing filter, deduplicated by (id, version)
    why: a project from another machine is missing a set; naming them one build at a time turns one install into four
  - what: CycleError carries the whole unorderable leftover, not a minimal cycle
    why: Kahn leaves the cycle and its descendants, and the set to look at is more useful than the shortest one
  - what: Kahn's algorithm with declaration position as the tiebreak, re-sorting the ready set
    why: the order is a property of the document, not of when a node happened to be freed — two runs of one project must be comparable
  - what: node_keys omits a node it cannot key rather than raising
    why: one non-deterministic filter would otherwise cost the eleven cacheable nodes around it their entries
  - what: a root's input type is unchecked
    why: what feeds it is the decoder's output, and checking it would put a codec dependency under a module whose point is running without one
  - what: parameters are not validated at build time
    why: cache_key.node_key validates them against params_model where they enter a hash; a second pass is a second answer

rejected:
  - what: a Graph type in core/ with dag.py as a validator over it
    why: core is deliberately not registry-aware, and resolution is most of what this does
  - what: DFS with a colour marking for cycle detection
    why: gives a minimal cycle and no topological order; Kahn gives the order and the leftover set from one pass
  - what: reporting the first missing filter and stopping
    why: the user's next action is an install, and an install wants the whole list
