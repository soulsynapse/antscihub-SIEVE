# Executor

## Why three files and not one

The TODO named `pipeline/executor.py`. What landed is `plan.py`, `cache.py`,
and `executor.py`, split not by noun but by what each can be tested without.
`ExecutionPlan` builds on a machine with no codec and no CUDA, which is the
property `dag.py` and `filter_base.py` were already split to preserve — and
three callers want it without a run: `sieve run --dry-run` and `sieve inspect`
(the next item), `pipeline/preview.py`, which SCAFFOLD already assigns the
warmup handling, and the storage HUD. A private `_lead_in` inside the executor
would have left preview reimplementing it.

## The monotonicity that removes the path enumeration

The TODO said "the executor has to decide that a node's lead-in is the maximum
over its paths", which is true and reads as an instruction to enumerate paths.
It is not necessary. `need ↦ ceil(need / rate) + warmup_frames` is monotone
non-decreasing in `need`, so propagating a maximum backwards node-by-node over
`Dag.order` gives the same number in one pass — where a diamond chain has
exponentially many paths.

That equivalence is invisible in the code, so `tests/property/test_warmup.py`
checks the walk against brute-force enumeration on random DAGs, and
`plan.root_paths` exists as the definition the walk is checked against rather
than living in the test file where the code could drift from it.

## What was checked by mutation

Executor loop, against `tests/unit/test_executor.py` and
`tests/integration/test_executor_run.py` — all six caught:

| breakage | caught by |
| --- | --- |
| yield the lead-in frames too | lead-in test's yielded-index list |
| let `select` use its default GPU-first preference | backend-pinning test |
| skip the ROI crop at the root | crop test's output shape |
| never look in the store | warm-cache test |
| never write to the store | warm-cache test |
| bind kernels lazily instead of up front | windowed test's `not source.reads` |

Warmup arithmetic, against `test_warmup.py` and `test_plan.py`:
max→sum over downstreams **caught**, max→sum over roots **caught**, drop the
rate conversion **caught**, drop the node's own warmup **caught**.

**`floor` for `ceil` survived, twice, and that is the finding of the exercise.**
The property test cannot catch it — both the walk and the brute-force reference
call `input_warmup_frames`, so mutating it moves both sides equally. Worse, the
first example fixtures could not catch it either: every decimator has a rate of
`1/n`, and `need / (1/n)` is `need * n`, always exact. A suite of decimators
never divides inexactly no matter how many graphs it draws. Closed by adding an
interpolator at rate `3/2` to `test_filter_contract.py` and an example asserting
the round-up; the property generator gained `2/3` and `3/2` for the same reason.

## What changed outside the item's scope

`source_warmup_frames` is now a fold over the extracted `input_warmup_frames`.
Same results — its existing tests were untouched and still pass — but the
single-step conversion is public, because the DAG walk needs the step without
the path.

`tests/unit/test_filter_contract.py` gained an `InterpolateParams` fixture and
the rounding example above. That is a gap that predates this item: the rounding
in `source_warmup_frames` has never been exercised, because until now every
rate in the suite divided exactly.

## Two things that did not fit and are worth knowing

**A GPU plan cannot be built on a machine without cupy.** `backend_identity`
refuses to name a version it cannot read, which is correct of it — an identity
that guessed would be an identity that collides. The consequence is that the
mirror-image of the backend-pinning test cannot exist here, so that test fakes
`runtime_available` and registers two kernels instead.

**The integration test cannot use the fixture's intensity ramp to identify a
frame**, despite `tests/integration/test_decode.py`'s docstring claiming that
is how frame identity is asserted (it in fact asserts `frame.index`). `mp4v` is
lossy and returns ~46 where 50 was written — a larger error than the 5 that
separates adjacent frames — so any tolerance wide enough to accept the codec
also accepts the neighbouring frame. It compares byte-for-byte against the same
three operations performed by hand instead.
