# Filter contract

The split the last commit argued for, now built: `core/` holds what is knowable
about a filter without running it, `filters/` will hold the kernels. Nothing in
either new module imports cv2, cupy, or Qt, and `lint-imports` keeps it that
way.

## Where the type parameter mattered

`register_filter` returns `type[ParamsT]`, not `type[ParamsBase]`. Erasing the
subclass would cost every filter's own fields their static types at the exact
place they are guaranteed to be read — the decorated class is what the GUI
builds widgets from and what the CLI parses flags into.

`__filter_spec__` is a `ClassVar[FilterSpec | None]` declared on `ParamsBase`
rather than an attribute the decorator invents. Pydantic leaves dunder names
out of field collection, the name is too long to mangle, and declaring it makes
the assignment type-check instead of needing a pyright suppression.

## What was checked by mutation

Each mutation applied to `src/`, `tests/unit/test_filter_contract.py` run, the
mutation reverted. All seven were caught, each by exactly one test:

| `latest` orders by version string | `test_versions_coexist_and_latest_is_numeric` |

| `extra="forbid"` dropped from `ParamsBase` | `test_unknown_parameter_is_rejected` |

## What is deliberately not here

No `filters/` package, no discovery scan, no kernel decorator. Discovery is the
next item's job and needs something to discover; `@kernel` belongs in
`backend/`, which is above `core/` in the layer order precisely so that device
policy cannot leak downward. The registry holds specs and nothing else.
