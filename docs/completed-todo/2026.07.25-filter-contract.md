summary: >
  `core/` now holds the filter contract as data — `FilterSpec`, `ParamsBase`,
  `ArraySpec`, `Mode`, and a registry keyed by `(filter_id, version)` — so a
  saved pipeline can be validated structurally with no filters installed and no
  codec present.

decisions:
  - what: 'registry key is `(filter_id, version)`, not `filter_id`'
    why: 'a pipeline saved against 1.0.0 must keep reproducing 1.0.0 after 1.1.0 ships, so versions coexist rather than the newer shadowing the older'
  - what: '`ArraySpec` fields are allowed-sets with empty meaning "any", and `admits` rejects only provable disjointness'
    why: 'a stride-indexing kernel genuinely does not care about dtype; rejecting the unprovable would make declaring `dtypes` at all a liability'
  - what: 'no `ndim` on `ArraySpec`'
    why: 'rank is determined by channel layout, and a second field that can contradict the first eventually will'
  - what: '`backend_agnostic` without `deterministic` raises rather than warning'
    why: 'bit-for-bit agreement across backends is strictly stronger than agreement with itself, and the pair would drop backend identity from the cache key of the one filter whose output nothing can reproduce'
  - what: '`primary_params` names are checked against `params_model.model_fields` at construction'
    why: 'the failure mode of a stale name is a widget that silently stops appearing — nothing raises, the GUI is just short a control'
  - what: '`CostEstimate` is per megapixel, not per frame'
    why: 'the same kernel on 4K and on a 256x256 crop differ by two orders of magnitude, so a per-frame number is wrong for every resolution but the one it was measured at'
  - what: 'semver is `MAJOR.MINOR.PATCH` only, no pre-release or build metadata'
    why: 'a version is a cache-key input before it is a label, and ordering `1.0.0-rc1` against `1.0.0` is a question this system never needs answered'
  - what: '`canonical_json` lives on `ParamsBase`'
    why: '`pipeline/cache_key.py` composes it rather than owning a second definition of what canonical means'

rejected:
  - what: 'pydantic model for `FilterSpec` itself'
    why: 'it holds a `type[ParamsBase]`, which pydantic validates awkwardly, and the spec is constructed in code rather than parsed from YAML — frozen dataclasses match `core/types.py` and cost nothing'
  - what: 'allowing an identical duplicate registration to pass silently'
    why: 'the failure it would hide is a filter module copy-pasted without changing its id, and two kernels sharing cache entries is worse than a module that cannot be re-imported without `clear()`'
  - what: 'a `register(spec)` call as the only registration path'
    why: 'the class decorator supplies `params_model` from the decorated class, which is the one field a spec cannot be written without — and it makes non-negotiable #3''s "one class" literal'
