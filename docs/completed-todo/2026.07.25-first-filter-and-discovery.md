# First filter and discovery

## What was checked by mutation

Each mutation was caught by exactly one test, and by the one that claims it:

| Mutation | Failing test |
| --- | --- |
| `frame.data[::stride, ::stride]` (drop the multiple-of-factor bound) | `test_both_paths_agree_on_shape_when_the_factor_does_not_divide` |
| delete `src/sieve/filters/downsample.md` | `test_every_discovered_filter_has_guidance_markdown` |
| add `from sieve.filters import downsample` to `filters/__init__.py` | `test_discovery_imports_no_filter_module` |

The third is the one worth keeping. Every other test in that file passes with
the manual import present — the registry ends up populated either way, so
nothing that inspects the *result* of discovery can tell a scan from a list.
Only reading the import list distinguishes them, which is why that test parses
the package's own AST rather than asserting on `REGISTRY`. It reads the AST and
not the text because the module's docstring has to be free to name the mistake
it warns about.

`test_canonical_params_are_stable_across_processes` was not mutation-checked,
because the thing it guards against cannot be introduced by editing this
package: `hash()` on a str is salted per process, so any test living inside one
interpreter passes whether or not a params model leaked one into its canonical
form. It runs a subprocess for that reason alone, and it is the only check in
the suite that would catch such a leak before a cache silently stopped hitting.

## What changed outside the item's scope

**The declared cost was wrong by 6x and is now measured.** It shipped at
`seconds_per_megapixel=0.002`, written from memory. The real figure is 0.33
ms/MP with anti-aliasing and 0.14 ms without. `CostEstimate`'s docstring
tolerates a factor of two, not six. `downsample.md` had inherited the same bad
number and also claimed the two paths cost the same in practice; they differ by
2.4x. Both corrected. This is not a `docs/findings/` entry — it is a filter's
own constant being right rather than something true about the system that
outlives the code.

**`.importlinter` gained two source modules on the headless contract.** The
layers contract only governs imports *within* `sieve`, so de-parenthesising
`sieve.filters` and `sieve.backend` did not by itself stop either from importing
PySide6. They are now named in the forbidden contract alongside `bench` and
`decode`, which is where the "runs without a GUI toolkit" claim is actually
enforced.

## What this leaves for the cache key

`canonical_params_json` has something to read: `DownsampleParams` is a real
params model with a JSON round trip under test. `backend_identity` exists and
is keyed on the backend `select` reports, so the "unless `backend_agnostic`"
branch has both halves available. Nothing in this item hashes anything.

## What `backend/` still does not have

`namespace.py` — array-API namespace resolution and host/device transfer — is
absent by choice, not oversight. It has one caller in principle (a GPU kernel)
and none in fact. `runtime_available` is likewise a module-presence check
standing in for the device-count probe that belongs there the day something can
run against a device. Both are named in `SCAFFOLD.md`, and neither should be
written before the first `@kernel(..., Backend.GPU)` gives it a shape to fit.
