decisions:
  - what: "`@kernel` names its filter by params class, not by an id string"
    why: an id repeated in the kernel can be copy-pasted onto the wrong filter, which crosses two filters' cache entries silently
  - what: backend absence is resolved in `dispatch.select`, never in a filter
    why: a filter with no GPU kernel is complete, and an `if cupy` per module is how §3 dies
  - what: fallback applies to an unexpressed preference only — a pinned backend raises
    why: a cross-backend equivalence test pins GPU to compare against CPU; silent fallback would make it compare a result with itself
  - what: "`runtime_available` is `find_spec`, not a device count"
    why: importing cupy on a broken driver raises rather than returning False, and this is on a hot path
  - what: both kernel paths slice to a multiple of `factor` so shapes agree
    why: a bare `[::factor]` rounds up where INTER_AREA rounds down, making `anti_alias` change output *size*
  - what: stride path returns `ascontiguousarray`, not the view
    why: a stride view retains the whole source frame, defeating the point of downsampling one frame at a time
  - what: "`accepts` declares only INTER_AREA's dtypes, though the stride path takes any"
    why: a static declaration has to hold for every setting of every parameter

rejected:
  - what: "`backend/namespace.py` (numpy vs cupy resolution)"
    why: no GPU kernel exists to resolve a namespace for; writing it now fixes a signature before anything needs it
  - what: a WINDOWED kernel protocol alongside the streaming one
    why: nothing declares WINDOWED yet, and guessing its signature locks the wrong one into every kernel written against it
  - what: "`backend_agnostic=True` on downsample"
    why: the claim requires an equivalence test and there is no second backend to equate against
