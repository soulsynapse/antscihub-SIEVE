summary: >
  A plan now carries a backend per node rather than one for the whole graph,
  and derives each node's cache key from the backend that will actually produce
  it — so a chain containing one CPU-only filter can still run its other nodes
  on GPU.

decisions:
  - what: ExecutionPlan.backends is a Mapping[str, Backend], not a Backend
    why: dispatch.py holds a CPU-only filter is complete; one backend per plan makes it deficient
  - what: build() accepts either a Backend or a mapping
    why: the single value is the whole of what a caller wants until a graph spans two
  - what: a mapping missing a node raises KeyError
    why: defaulting it runs on the wrong device under a correct key — a performance bug with no symptom
  - what: Dag.node_keys takes the same union
    why: keys must come from the backend that produced the node, or the pinning is decorative

rejected:
  - what: resolving the mapping from the kernel shelf inside build()
    why: needs a policy (fastest per node vs fewest transfers) that only a residency model can settle — see docs/LATER.md
