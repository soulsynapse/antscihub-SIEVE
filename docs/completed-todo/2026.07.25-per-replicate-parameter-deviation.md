# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: "overrides live on `Replicate`, keyed by node id"
    why: on `Node` instead, twelve arenas make one node carry twelve dicts and the fan-out stops being a fan-out
  - what: sparsity is per *key*, not per node
    why: one arena can pin its threshold and still follow a later edit to a blur radius nobody varied
  - what: the pinned set is diffed against what the replicate resolved to *before* the edit
    why: lets a GUI form submit its whole field set without every edited replicate acquiring a full override
  - what: "`Node.params` is documented as the moving default and is never hashed alone"
    why: a project where every replicate overrides never reads it, and hashing it would invalidate all twelve entries whenever it moved
  - what: "`resolved_params` is a module function, `Project.params_for` a lookup that delegates to it"
    why: a second definition of effective params is how a preview and a batch run stop agreeing, invisibly
  - what: an override naming a node that does not exist is refused by `Project`
    why: same staleness class as a checkpoint, and it would survive every save until a new node was handed the dead id

rejected:
  - what: recording which replicate was visited when, to drive inheritance
    why: interaction history in the artifact — an un-overridden replicate must resolve to a value stored in the document
