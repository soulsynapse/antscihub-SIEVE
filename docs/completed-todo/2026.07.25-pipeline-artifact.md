# Pipeline artifact

Non-negotiable #2 now has something to be true about. Given this document and
the video it names, any executor performs the same run and writes the same
files, and `extra="forbid"` throughout is what makes AUTO-GUARDRAILS §2
cost something to break: persisting zoom or panel layout requires editing
`core/pipeline_model.py`, which is the review the rule exists to force.

Guardrail §2's stated check — GUI serialize, CLI deserialize, execute, diff — is
not yet runnable, because neither the CLI nor the executor exists. What is
checked here is the half that can be: the artifact's purity, its round trip, and
its refusal of anything that is not part of a reproducible run.

## The first draft was written without reading VISION properly

Worth recording because the correction was the substance of the item. The first
pass had nodes, edges, replicates, and a source path — a faithful reading of the
TODO item, which is what it says. Checked against VISION afterwards, it was
missing three things the eventual DAG and HPC handoff both need, and each was a
gap the TODO item's own wording did not reveal:

- **No sinks.** Step 6 selects a stage to output. Without them the artifact
  describes a computation and declares no observable, and `sieve run` — two
  items away — would have had nothing to write.
- **No checkpoints.** Step 4 saves the representative clip to the child layer;
  step 6 has the HPC wizard "toggle off stuff like a compaction state". You can
  only toggle off what is written down, so which nodes are materialized is
  project state.
- **No clip range.** Already ruled project state by the TODO, but omitted as
  belonging to the transport-bar item. The executor needs it, so omitting it
  only deferred reopening the file.

The same pass turned up three defects in the filter contract shipped in
`da40c1c`, which are a finding and a TODO item rather than a fix here:
[the filter contract cannot type what VISION asks filters to
do](../findings/2026.07.25-the-filter-contract-cannot-type-vision.md). The
expensive one is that nothing declares a change of frame rate, which makes
ARCHITECTURE's warmup arithmetic wrong by the decimation factor across any
decimating node — silently, since the under-warmed frame still renders.

## The identity line

The one invariant this module is organized around: everything on `Node` feeds
the cache key, and nothing else in the file does, apart from the source and the
replicate geometry at a root. It decided where two fields went. `checkpoints`
and `outputs` both looked like node attributes and are not — materializing an
intermediate or writing it to a different folder changes nothing about what the
node computes, and two projects writing one computation to different folders
must share cache entries. Putting them on `Project` keyed by node id makes
hashing them by accident unavailable rather than merely discouraged.

`test_node_carries_identity_and_nothing_else` asserts `Node`'s field set
literally, so the next person to add a convenient flag to it gets a failure that
names the reason instead of a cache that misses whenever an output path changes.

## A bug the tests caught

`relocated` was originally `rebased_to(project_dir)`, taking one directory. It
could not work: rebasing needs the directory the stored path was written
against, and a relative path does not carry it. The guard read
`if current == Path(project_dir, self.source.path)` where `current` was
`self.source.resolve(project_dir)` — the same expression — so it returned `self`
unconditionally and rebased nothing. Replaced by `relocated(from_dir, to_dir)`,
which takes both because both are genuinely needed, and `save()` no longer
rebases at all.

The round-trip test then failed for a second, separate reason: `resolve` joined
without normalizing, so two references to one file compared unequal on their
`..` segments. That is a defect in the accessor rather than the test — every
caller comparing two resolved paths would have hit it. `Path.resolve` was chosen
over a lexical `normpath` because collapsing `a/link/..` to `a` is wrong through
a symlink, and footage on a symlinked scratch mount is ordinary on the machines
this runs on.

## Outside the item's scope

`FILTER_ID_PATTERN` and `SEMVER_PATTERN` lost their leading underscore in
`filter_base.py`. The artifact validates the same two strings on the way in from
YAML — which is not registry awareness, since it never asks whether the filter
exists — and the alternative was a second copy of both regexes.
