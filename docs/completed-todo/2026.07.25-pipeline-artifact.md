decisions:
  - what: 'the artifact carries sinks (`outputs`), not just a graph'
    why: 'VISION step 6 selects a stage to output; a graph with no sinks computes nothing observable and `sieve run` over it would have nothing to write'
  - what: '`checkpoints` and `outputs` are lists on `Project` keyed by node id, never fields on `Node`'
    why: 'everything on `Node` feeds the cache key; a `materialize` flag sitting beside `params` is one refactor away from being hashed with it, and materializing changes where a result lives rather than what it is'
  - what: '`ClipRange` shipped now rather than with the transport-bar UI'
    why: 'the executor needs it to request `[start - warmup, end)`, and leaving the slot out would have meant the later item reopening this file anyway'
  - what: 'replicates are a source-level fan-out, one pipeline run per replicate'
    why: 'chosen over one root node per replicate; the ordinary case (one chain, twelve arenas) would otherwise be twelve subgraphs the GUI generates and keeps in step'
  - what: 'project file is `<video stem>.sieve.yaml` beside the video, paths stored relative to it'
    why: "VISION step 1's layout — source in a folder, derivatives in children — and it makes copying the folder how footage reaches a cluster"
  - what: '`save()` does not rebase `source`; `relocated(from_dir, to_dir)` takes both directories'
    why: 'a relative path does not carry the directory it was relative to, so a save that silently reinterpreted one would corrupt exactly the projects it meant to help'
  - what: '`SourceRef.resolve` returns a normalized path via `Path.resolve`, not a raw join'
    why: 'two references to one file must compare equal; a lexical `normpath` was rejected because collapsing `a/link/..` is wrong through a symlinked scratch mount'
  - what: 'sink `format` is a validated string, not a `StrEnum`'
    why: 'the writer set is open, and an enum in `core/` is the manual-wiring problem non-negotiable #3 forbids for filters, reintroduced one layer down'
  - what: 'no measurements, no machine config, no HPC section in the artifact'
    why: 'a timing is a fact about one machine and this is the document two machines must agree about; VISION step 6 routes capability through command-line options, and the handoff is this document with `checkpoints` emptied and `clip` dropped'
  - what: '`FILTER_ID_PATTERN`/`SEMVER_PATTERN` made public on `filter_base`'
    why: 'the artifact validates the same two strings on the way in from YAML; a second copy of the regex is a second thing to keep in step'

rejected:
  - what: 'cycle detection here'
    why: 'it needs a traversal, it is the first thing `pipeline/dag.py` does, and two implementations means two answers to maintain'
  - what: 'resolving `filter_id` against the registry at load'
    why: 'a project naming an absent filter must open, so the user is told which filter to install and the GUI can draw a graph it cannot execute — registry awareness turns that into a parse error naming nothing'
  - what: 'parsing `params` into the filter''s `ParamsBase` subclass'
    why: 'the model lives in `sieve.filters`, above this layer; validating here would invert the layer stack or keep a second copy of the field list'
  - what: 'per-replicate parameter overrides'
    why: 'considered and declined — no workflow has asked for a dim arena with its own threshold, and the override map is addable later without a schema break'
