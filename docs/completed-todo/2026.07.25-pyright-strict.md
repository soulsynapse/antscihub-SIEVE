# Pyright strict

All eight errors were real. One was a bug; the rest were the code claiming
something it did not deliver.

## The bug

`ChannelSpec.count` shadowed `str.count` on a `StrEnum`. `ChannelSpec.BGR` *is*
the string `"bgr"`, so `ChannelSpec.BGR.count("b")` returned 3 — the channel
count — instead of 1. Any caller treating the spec as the string it is would
have been silently wrong, and nothing in the suite would have noticed.

Renamed to `channel_count`, with a test pinning `str.count` intact so the
shadowing cannot come back under another name.

This is the argument for strict mode in one example: the error pyright raised
was about a signature mismatch on an override, and the defect underneath it was
a wrong number returned to a caller that had no reason to doubt it.

## The honesty fixes

- `_downscale` was annotated `NDArray[uint8]` while doing nothing to guarantee
  it. Now `NDArray[Any]`, matching its input.
- `read()` tested `data is None` alongside `not ok` — a state OpenCV never
  produces separately. Dead branch, removed rather than typed around.
- `setShortcuts` was handed a bare `StandardKey`; now wrapped in
  `QKeySequence`.
- Three `selectionModel() is None` guards in `ReplicateTab` were unreachable:
  `setModel` runs in the constructor, before any of them. Deleted.

The last two are the pattern worth noting — a defensive `is None` check against
something that cannot be `None` reads as caution and is actually noise, and
strict mode is what makes the difference visible.
