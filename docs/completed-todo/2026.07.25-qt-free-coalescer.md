# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: one rank rule, applied at both the pending slot and the cache-hit path
    why: the two paths answered the precedence question differently, and the module docstring documented only one of the answers
  - what: only an EXACT may displace a pending EXACT — guesses yield to commitments
    why: a playback tick or a fresh drag could silently evict a released slider's target, stranding the user where they never asked to be
  - what: arrived() and drain() are two calls, not one
    why: the round trip is measured after the display emit so the synchronous view update counts, and draining first would start the next request's clock before that repaint
  - what: the coalescer returns the request to issue rather than issuing it
    why: issuing is a Qt signal emit, and taking it inside would put PySide6 back under an object whose point is running without it
  - what: sequence counters are not reset by new_generation()
    why: a reused sequence number makes an old source's frame look current, which is the display-ordering half of the bug the generation stamp fixed
  - what: Arrival carries the request even when stale
    why: stale and display are separate answers, and a caller that wants to log what it dropped should not have to reach back into the object
  - what: left in gui/ rather than moved to core/
    why: nothing below gui/ consumes it yet; pipeline/preview.py is what will justify the move, and moving it before that would be guessing

rejected:
  - what: a single arrived() that also drains and reports elapsed_ms
    why: it starts the next decode's clock before the caller has painted, systematically inflating scrub latencies and biasing the degradation decision
  - what: keeping latest-wins in the pending slot and fixing the docstring instead
    why: the cache-hit path already implemented the rank rule and has a test pinning it; two rules for one question was the defect
