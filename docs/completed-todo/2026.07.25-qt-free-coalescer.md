# Qt-free coalescer

The item asked for an extraction. What it got was an extraction plus the
resolution of a contradiction the extraction made unavoidable.

## The rule was already answered twice

`player.py` documented, in its module docstring, that "a pending exact request
is never discarded in favour of a later drag position". `_request` overwrote
`_pending` unconditionally, so a later `SCRUB` did discard it. The claim was
true only on the other path — `_display_cached` cleared the pending slot solely
when both the incoming and the pending request were `SCRUB`.

Two paths, one question, two answers, forty lines apart, and a docstring
agreeing with the less-travelled one. This is what a rule with no object to
live in looks like, and it is the concrete form of the divergence the item
predicted would happen between `player.py` and `pipeline/preview.py`. It was
already happening inside `player.py`.

`_outranks` is now the single answer: an intent may take the pending slot from
another intent unless the pending one is a commitment and the newcomer is not.
`request` and `served_without_decode` both consult it. Between equals, later
wins, as before.

The behaviour change is real but narrow. A drag position arriving after a
released slider is now dropped rather than replacing it, and a playback tick no
longer clobbers a pending seek — which also means the seek's frame reaches the
cache, since `PLAYBACK` frames deliberately do not.

## Why the arrival is two calls

`arrived()` gives the verdict; `drain()` frees the slot and hands back the next
request. Folding them into one call is the obvious API and is wrong: the player
measures the round trip *after* emitting `frame_changed`, so the synchronous
view update is inside the sample. A combined call would issue the next request —
and start its clock — before that repaint had happened, charging every request
the cost of painting its predecessor. On a scrub that feeds the degradation
decision, which is exactly the quantity that must not react to the player being
busy.

The pairing is a real hazard: forgetting `drain()` wedges the player. It is
documented on both methods, and `test_the_stale_frame_still_frees_the_slot_for_the_new_source`
is the test that would catch the omission on the one path where it is easiest
to forget.

## What was checked by mutation

Five deliberate breakages, each caught by exactly one test:

| Mutation | Caught by |
| --- | --- |
| drop the rank check — latest wins in the pending slot | `test_a_guess_does_not_displace_a_pending_commitment` |
| reset the sequence counters in `new_generation` | `test_sequence_numbers_do_not_restart_with_the_source` |
| remove the `EXACT` exemption from the display verdict | `test_a_commitment_is_painted_even_when_overtaken` |
| let a local display skip the sequence | `test_a_decode_overtaken_by_a_local_display_is_not_painted` |
| stamp the issue time at creation rather than at issue | `test_the_round_trip_is_timed_from_issue_not_from_creation` |

The first is the one worth keeping. It restores the exact behaviour `main`
shipped with, every GUI test passes with it in place, and the drag it breaks is
one the user performs a dozen times an hour.
