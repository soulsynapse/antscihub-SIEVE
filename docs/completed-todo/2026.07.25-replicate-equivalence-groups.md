# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: the fingerprint is a canonical JSON string used as a dict key, not a digest
    why: the string *is* the comparison, so there is no collision to reason about and no `hash()` salt to be surprised by
  - what: node order is the graph's declaration order, not topological
    why: every replicate is fingerprinted under the same order, so ordering changes each fingerprint and no grouping — see below
  - what: geometry, name, and `replicate_id` stay out of the fingerprint
    why: every arena has its own ROI, so including it would put twelve arenas in twelve groups and the column would report nothing
  - what: "`ReplicateDocument` gained a `Pipeline` and clears it in `bind_source`"
    why: a deviation is keyed by node id, so a graph outliving the replicates configured against it is a set of defaults tuned on footage nobody is looking at
  - what: "`grouping_changed` carries no row index"
    why: numbers are positional, so any change can move any replicate — there is no smaller claim than "all of them"
  - what: the group column recomputes the whole set on every cell read
    why: a cached number would need invalidating on every parameter edit anywhere in the graph, which is what recomputing already does

rejected:
  - what: storing a group number on `Replicate`
    why: it goes stale on every edit and would be a durable-looking handle on something that is a positional label
