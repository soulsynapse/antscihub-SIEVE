decisions:
  - what: the clip lives on ReplicateDocument, edited only through a SetClip QUndoCommand
    why: it is invalidated by the same source binding the replicates are, and undo has to cover the window rather than one table in it
  - what: bind_source gained frame_count, and a mark is clamped against it
    why: the clip is geometry in frame-index space exactly as an ROI is in pixel space, and the same clamp-do-not-reject rule applies
  - what: a mark that would invert the range releases the far mark instead of being refused
    why: ClipRange refuses end <= start, so the alternatives were a crash, a silent no-op, or a span the user did not ask for
  - what: marking out includes the frame the user is parked on (end = frame + 1)
    why: half-open is the storage contract, "the last frame I want" is the user's, and the translation belongs in one place
  - what: the strip is a sibling widget under the slider, not paint inside its groove
    why: QSlider has already drawn the handle by the time a subclass can paint, so a band in the groove either crosses the handle or guesses its geometry
  - what: ClipSlider.x_of_frame goes through QStyle.sliderPositionFromValue over the groove less the handle width
    why: it is where Qt actually parks the handle; the naive groove fraction is off by half a handle at both ends of the timeline

rejected:
  - what: in/out drag grips on the strip
    why: the marks are set at the playhead, which is where the user already is; grips are a second way to say the same thing and belong with the tuning UI that has a reason to nudge a boundary
  - what: treating a cleared clip as "the whole video"
    why: pipeline/plan.py already distinguishes them, and a project saved before the user marked anything must not reload claiming they marked everything
