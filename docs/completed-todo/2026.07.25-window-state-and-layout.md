# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: setWindowState(WindowMaximized) in the constructor, not showMaximized()
    why: a constructor that puts a window on screen takes that decision away from its caller — app.main still owns show()
  - what: resize(1280, 900) kept alongside it
    why: it is now the restore-down size; without it, un-maximizing lands on whatever the layout's size hint produces
  - what: restore_last_video() is a method app.main calls, not something __init__ does
    why: constructing a window must not touch the filesystem or start a decode, and every GUI test constructs one
  - what: MainWindow takes an injectable Preferences
    why: opening a video now writes to the store, so a test with the default store would write the developer's real settings
  - what: existence is checked by the caller, not by the accessor
    why: a Preferences that returned None for a missing file would leave the window unable to tell "nothing remembered" from "file moved"
  - what: last_video is recorded in _on_opened, not in open_video
    why: a path that failed to decode is not one to hand back at the next launch
  - what: writing last_video does not emit changed
    why: the changed signal means "reapply the settings you run on", and emitting it would make every video that opens look like a preference edit
  - what: restore_defaults() leaves last_video alone
    why: restoring defaults is a statement about behaviour, and forgetting which file the user was working on is not part of it
  - what: the transport bar stays in the left pane rather than spanning the top half
    why: it drives the player, and a scrubber running under a tool pane would claim to drive that too

rejected:
  - what: persisting the full geometry via saveGeometry()/restoreGeometry()
    why: a different feature with its own failure mode — a window restored onto a monitor that is no longer attached — and the item asked only for "big on launch"
  - what: reopening the video from __init__
    why: it would fire in every test that constructs a MainWindow, and would decode a file before the caller had decided to show the window
  - what: a placeholder label or frame in the empty right pane
    why: an empty pane says less than a label promising something that does not exist
