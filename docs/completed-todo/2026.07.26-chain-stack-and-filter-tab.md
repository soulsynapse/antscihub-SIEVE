decisions:
  - what: the tab adds no debounce of its own — knob bursts ride the runner's latest-wins slots
    why: the coalescing discipline already lives in preview_runner; a tab-side timer would be a second copy of the rule the coalescer extraction existed to avoid
  - what: the consumer's revision is runner.revision + 1, read on the GUI thread immediately before the submit
    why: the worker never calls a superseded request's consumer, so the only requirement is that the closure knows which revision it belongs to; nothing else can run between the read and the submit
  - what: card bodies are tab-owned persistent widgets, detached by the stack before every teardown
    why: the mockup's parent-death lesson (learning 6) applied inside one host — the graphs are expensive and the knobs hold focus, so they outlive their cards
  - what: a frequency-band drag moves only handles and the snapped readout; the transform waits for release
    why: the Morlet re-sum is the one band edit that is not cheap per mouse-move; value/count/D/centered drags re-derive from the retained band power inside the 50 ms tier
  - what: MainWindow no longer renders document.pipeline — the filter tab owns render submission
    why: two callers racing request_render on the same signals would supersede each other by connection order; the live chain is the graph the preview is for, and the status line still reports every finish
  - what: the § 8 budget-row question answered yes — band_drag_repaint (50 ms) and knob_to_graphs (3 s)
    why: the two-tier discipline is only enforceable if each tier has a ceiling; knob settle shares the full-render ceiling because the store, not speed, is what meets it
  - what: removing morlet_band leaves the chain grading OK (block series flows through) but the derivation refuses
    why: kinds type the chain, not the maths — the tab requires a reachable temporal and detection step before deriving, and the count plot names whichever is missing

rejected:

  - what: rebuilding the stack on every knob wiggle
    why: update_captions repaints in place; a rebuild per wiggle would churn focus and repaint the embedded graphs for no structural change
