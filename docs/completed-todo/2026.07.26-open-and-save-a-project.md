decisions:
  - what: the window holds `_project` and `_project_path`, not the document
    why: both are answers about this session; a document carrying them is GUI state back in the artifact
  - what: "`apply_to(project)` copies the project it was handed"
    why: "`source`, `checkpoints`, and `outputs` are invisible in this GUI, so assembling a fresh one drops them where nothing would ever show it"
  - what: "`_pending_project` carries a project across the asynchronous open"
    why: "`bind_source` clears the document when the video lands, so a load written before it is erased by it"
  - what: "`load_project` refits ROIs and the clip to the source actually bound"
    why: a project names its video by path, and a path promises nothing about dimensions or length
  - what: a clip entirely past the end of a shorter source is dropped, not clamped
    why: clamping invents a one-frame clip nobody marked; the absence is a state the document already models
  - what: "`confirm_discard` returns whatever `save_project` returned"
    why: choosing Save and then cancelling the file dialog has saved nothing, and treating it as consent loses the session
  - what: dirty is `QUndoStack.isClean()`, surfaced through `setWindowModified`
    why: every user edit is a command by construction, so there is no second source of change to keep in step

rejected:
  - what: reopening the video when the neighbour offer is accepted
    why: it is already open; `open_project` adopts in place when the source resolves to the file on screen
  - what: comparing directories before calling `relocated` on Save As
    why: rebasing onto the directory a project already sits in is a no-op, and the comparison that would skip it is a path-equality test — wrong across a symlink
