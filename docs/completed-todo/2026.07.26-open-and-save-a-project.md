# Open and save a project

## The ordering, which is the only hard part

`bind_source` clears replicates, clip, graph, and history on every open, and it
must: geometry in one video's pixel space cannot carry to another. Opening a
project opens its video *first*, and `VideoPlayer.open` is asynchronous — so the
clear always lands after the file has been read and before anything can be
populated from it. Any load written as a sequence of ordinary edits is erased by
the very bind that made the source known.

`MainWindow._pending_project` is the whole answer: the parsed project waits
there until `_on_opened` fires, and is applied on the far side of the clear.
`ReplicateDocument.load_project` is the matching primitive — one write of all
three fields, no undo commands, ending in `undo_stack.clear()`.

The mutation that proves this is tested: replacing `self._pending_project =
(project, path)` with an immediate `_adopt_project(...)` before `open_video`
fails both round-trip tests and passes the other twelve.

## What was checked by mutation

- **`apply_to` assembling a fresh `Project`** instead of copying the one it was
  handed → only `test_saving_keeps_the_fields_the_gui_cannot_edit` fails. That
  test exists because it is the *only* one that can: a sink and a checkpoint are
  invisible in this GUI, so every other assertion in the file passes while a save
  quietly deletes them.
- **Applying the project before the source binds** (above) → both round-trip
  tests fail.

## What changed outside the item's scope

**A crash, found by the tests and fixed in them.** `closeEvent` now refuses a
close when the user cancels the unsaved prompt — correct behaviour, and it means
`_player.shutdown()` never runs. Two tests deliberately refuse a close; the
decode thread then outlived the `QApplication` and took the interpreter down
mid-suite with no traceback naming the test. The `window` fixture declares the
document clean before closing, because teardown is not a user decision. Nothing
in the product changed: a running application that keeps a window open is
supposed to keep its decoder.

**An autouse guard against modal dialogs**, in `tests/gui/conftest.py`. A
`QMessageBox` in a headless suite is not a failure, it is a run that never
returns, and there are now four of them reachable from ordinary paths. Every
message box is answered by default — discard unsaved work, decline the
neighbour offer — and a test about a particular prompt overrides it and asserts
on the arguments.

**`_on_failed` routes through a new `_warn`**, so a failure says the same thing
in the status bar and in the dialog. It also clears `_pending_project`: a video
that did not open leaves nothing for a project to be a project *of*, and holding
it would apply it to whatever the user opened next.

## The item this created

Reading the screenshot of V1's Isolate tab against `ClipRange` showed the
representative clip is the wrong object — a window with a held length, not two
independent marks. It is written up as its own TODO item rather than folded in
here: the artifact needs no schema change for it, so persistence landed
correctly and the interaction is separable work.
