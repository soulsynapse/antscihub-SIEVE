# Per-frame delivery and the single-frame path

Item 4 of `docs/filter-tab-parity-plan.md`. `pipeline/preview.py` needed no
change at all — its `Consumer` hook already existed on both render paths;
what landed is the runner passing a caller's consumer through `RenderRequest`
and surfacing `render_frame` as `request_frame`.

**What was checked by mutation.** The collector's staleness test interleaves
a stale straggler after `start(2)` — removing the revision check fills the
new series with the old render's row. The gap test fails if the contiguity
check is dropped. The thread test asserts the consumer runs off the GUI
thread, which fails if delivery is ever moved onto a queued signal.

**Outside the item's scope.** `request_render`'s submission tail was
factored into `_next_revision`/`_submit` so `request_frame` shares it
verbatim rather than restating the revision discipline.
