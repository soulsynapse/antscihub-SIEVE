# Plot widgets (filter-tab parity item 5)

The four views are `TimelineStrip`-shaped: setters in, drags out, geometry
exposed as methods (`handle_y`, `gate_rects`, `grid_rect`, `block_at`)
because the claims worth testing are about geometry and a painted pixel is
not something a test can ask about.

**What was checked by mutation.** Changing the grab boundary from `<=` to
`<` failed exactly `test_at_eight_px_the_same_drag_grabs_the_handle`;
removing the `max(x1 - x0, 1.0)` floor in `gate_rects` failed exactly the
two narrow-width cases of
`test_a_one_frame_detection_paints_at_least_one_px`. Both were restored and
the suite is green.

**Widgets item 6 still wires.** Nothing here is drawn by the application
yet: the stack cards, the tab layout, and the document/player/runner wiring
are item 6, which these widgets were sized for (cards embed them; the count
plot's `set_notice` is where "no reachable detection step" arrives from the
chain model's grade).
