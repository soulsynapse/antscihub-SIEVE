decisions:
  - what: one base class (`BandPlot`) owns the whole gesture contract
    why: the 8 px grab-vs-scrub rule, the two event tiers, and the 1 px gate floor are the same claim on every plot; three re-implementations would drift
  - what: scrub speaks pressed/scrubbed/committed, exactly like TimelineStrip
    why: the plots' playhead goes to the same player; a two-event scrub here would either decode every pixel or land off by a frame
  - what: unbounded band = ±inf, unset band = clear_band(), two different things
    why: matches DetectorState's own encoding (±inf bands, None count_frac); the count threshold arms by first drag on dimmed edge handles
  - what: mid-drag, set_band is ignored for the held handle only
    why: the tab echoes state back per cheap tier; letting the echo move the handle under the mouse fights the gesture on any slow recompute
  - what: the count plot speaks counts, the state stores a fraction
    why: parity plan § 2 — the axis and drags stay in display units, the tab divides by B once; re-denomination on block-size change is state's problem
  - what: colormap stops are the mockup's (warm scalogram, cyan density, green status-only)
    why: § 8's open decision; the *structure* (one sequential ramp per surface, green never data) was already settled in § 2 and the mockup stops satisfy it
  - what: scalogram reduces columns by max, cached per width, normalized once in log space
    why: per-column max is the plan's rule (a single-frame event must survive any width); normalizing per rebuild would let a resize change contrast
  - what: block-heat fill scale set from outside (set_scale_max), not per-frame max
    why: per-frame normalization makes every cell pulse with the loudest one; a fixed scale keeps brightness meaning the same thing at every playhead
  - what: pyqtgraph AND napari dropped from the gui extra
    why: plan § 2 settled QPainter for plots and item 5 is the named removal point; the three-way overlay re-adds napari deliberately if it earns it

rejected:
  - what: per-plot solo/detector state
    why: the mockups' rule "plots own no detector state" is what makes the wizard's own plot instances over shared state possible (plan learning 6)
  - what: letting the block-heat click apply its own solo before set_state
    why: the panel and the density plot would disagree for a frame on every click; the click emits, the state model decides
