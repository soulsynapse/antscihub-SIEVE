decisions:
  - what: new rescale filter rather than a params-v2 of downsample
    why: disjoint parameter spaces (float scale vs integer factor) and output geometries (round vs truncate); migrating would break every existing cache key to make one filter answer two questions
  - what: normalize computes statistics from the frame's gray projection, applies the affine to all channels
    why: v1 normalized after gray conversion, v2's chain converts after this node; an affine commutes with the fixed convex gray projection, so this makes the downstream gray series exactly v1's normalized gray — pooled-channel stats would shift every band-power value and break item 9's numeric comparison
  - what: zscore always emits float32
    why: the affine lands on a continuous scale; narrowing back to the input integer dtype would quantize the contrast the step standardizes
  - what: rescale at 1.0 and normalize off return the input frame object
    why: v1 verified INTER_AREA at scale 1 bit-identical, so skipping is numerically free and a per-frame copy is not

rejected:
  - what: clahe mode
    why: v1's known crop-edge artifact (861 px/s phantom motion vs 48 real); named in the guidance so the wizard says so
