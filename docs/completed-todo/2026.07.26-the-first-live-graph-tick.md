decisions:
  - what: the item was split — this pass is the producer, the HUD is the next item
    why: slider_to_graph has no slider to drag, so half the original item was ungated only on paper
  - what: per-frame cost is a Qt signal, not a budget key on the bus
    why: a budget key is a named ceiling; 600 frames are 600 samples of an interval with none
  - what: x is the source frame index, so the playhead is the graph's cursor
    why: VISION's vertical bar is meaningless over sample arrival order
  - what: filter_to_first_tick is timed on the GUI thread, ending at the queued arrival
    why: a tick the user has not been handed is not a tick — it must contain the thread hop
  - what: the two threads share a newest-revision integer, not a cancel flag
    why: a flag has no safe moment to be lowered; see the body
  - what: cancellation is an exception raised out of the frame consumer
    why: the only hook there is — execute is a generator and pipeline/ takes no cancel argument
  - what: PreviewRunner takes registry and kernels
    why: without them the abandon path can only be pinned by a race against a fast real filter
  - what: an empty graph is refused rather than rendered
    why: it decodes the whole window to produce results with no outputs, and it is what makes "first filter" an event

rejected:
  - what: reusing gui/coalescer.py's RequestCoalescer for renders
    why: its rank rule is commitment-over-guess, and a render has no such pair — one desired graph, always the newest
  - what: publishing slider_to_graph from the window-moved re-render
    why: that gesture decodes and the budget's does not; it would make a 200 ms ceiling look generous by measuring the wrong thing
  - what: a HUD over MetricBus samples in arrival order
    why: cannot carry the clip cursor, and two numbers per render cannot say where in the clip the cost is
