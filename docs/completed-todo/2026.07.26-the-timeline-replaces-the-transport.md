# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: the window is an origin and a held length, not two independent marks
    why: the gesture is "keep my ten seconds, move them"; two marks must invent an out point
  - what: the default 10 s window is derived on read, never written into the document
    why: resolving it on open would make Project.clip = None unreachable from the GUI
  - what: document.window falls back, document.clip does not
    why: one stored value and one derived view; two stored windows would drift
  - what: seek clamps into the window, so every caller inherits "the playhead is inside it"
    why: one chokepoint instead of a rule each of step, play, scrub, and the strip must repeat
  - what: playback loops and shows stop-1 explicitly before wrapping
    why: playback drops undecodable frames, so an overshooting clock skips the window's last frame every lap
  - what: the window rule fires on press and on release, not on every drag move
    why: one gesture is at most two undo entries; a per-move rule needs mergeWith, which is a separate item
  - what: Geometry inverts over `width`, not `width - 1`
    why: the V1 denominator reaches the last frame a pixel early and never reaches it when the band is wider than the asset is long

rejected:
  - what: changing ClipRange to store (start, length)
    why: (start, end) carries identical information; which one survives an edit is an interaction rule, not a storage one
  - what: centring the window on a click outside it
    why: travels twice as far as asked and discards the stretch the user was looking at
  - what: a separate session-level window object beside document.clip
    why: two stored answers to one question, and the copy is the one that goes stale
