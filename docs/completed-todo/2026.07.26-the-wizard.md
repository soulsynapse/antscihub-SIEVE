# The wizard

Item 7 of `docs/filter-tab-parity-plan.md`. The seam affordances item 6
shipped as narrated no-ops now open the real helper.

**Shape.** `gui/wizard_model.py` is the Qt-free half: the catalog (five
node-backed entries plus the two tab-side suffix steps, so a chain that lost
`morlet_band` has a repair path), `candidates_for_insert/swap` with the
disable rules, `insert_step`/`swap_step` building provisional `LiveChain`
values, and the guidance section parser. `gui/wizard.py` is the inset widget;
`gui/param_form.py` generates settings rows from any registered params model
(bounds from the field constraints, enums as combos). The tab owns the
lifecycle: snapshot on open, adopt on every proposal, restore on cancel,
solidify on add — `_ensure_body` gives a committed non-parity step its card
body so the stack's contract survives the commit.

**What was checked by mutation.** The cancel test fails if `_on_wizard_
cancelled` forgets to restore the snapshot (the chain keeps the provisional
step) and if the wizard derives proposals from the previous proposal instead
of the snapshot (the settings edit survives into the restored chain as an
equality failure). The disabled-candidate test fails if `select_entry` drops
its enabled check or if disabled rows keep `ItemIsEnabled`. The store-reuse
test fails if provisional node ids are minted in a way that changes upstream
keys — `from_cache` collapses below two outputs per frame.

**Swap seeds the outgoing step's params.** Replacing a step with its own
entry keeps the node params (the wizard doubles as a settings surface); an
explicit wizard edit still wins. Pinned in the unit tests.

**A pre-existing staleness fixed in passing:** `docs/completed-todo/.index.md`
had not been regenerated after item 6's entry landed; `nox -s docs` rewrote
it here.

**Mockups deleted.** `mockups/insertion` and `mockups/tab` were the wizard's
runnable contracts; everything load-bearing is restated in the plan and this
entry, per the mockup README's own "what survives". `mockups/graphs` and
`mockups/seeker` stay until item 8 consumes the seeker decisions.
