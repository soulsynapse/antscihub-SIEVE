# Three small GUI fixes

Three unrelated defects found in one audit, all in `gui/`, none large enough
to carry an entry alone.

## The preferences dedupe was invisible to its own test suite

`_store` compared `self._settings.value(key)` — whatever the backing store
parsed — against the typed value about to be written. The audit called this
"works on the Windows registry, always misses on INI". That is right about the
consequence and wrong about when: `QSettings` caches a settings file
*per process*, so a second `QSettings` constructed over the same path is
answered from the same in-memory copy and hands back the `int` it was given.
Inside one session the guard therefore holds on INI too, which is why
`test_writing_the_same_value_is_silent` had always passed.

The miss is on the launch *after* the one that stored the value. A fresh
process parses the file off disk and every value is a string:

```
proxy_width=1920            -> '1920'   == 1920  is False
adaptive=true               -> 'true'   == True  is False
coarse_interval_seconds=2.5 -> '2.5'    == 2.5   is False
```

So every preference, on every second launch, wrote and emitted `changed` on an
edit that changed nothing — and `changed` means "reapply the settings you run
on", which reaches the decode worker's proxy width. The test that pins this
writes the INI as plain text rather than reopening a `QSettings`, because that
is the only way to get a file this process did not already have cached.

The comparison now takes the setter's own typed property as `current`.
`_store` is generic over keys and cannot know which coercion applies; the
setter always does.

## Naming

`gui/frame_cache.py` and `pipeline/cache.py` are both caches of frames and
share nothing else. The first is keyed by position in the video, holds what
the viewport is showing, and is emptied when the source closes. The second is
keyed by what computation produced the frame and is the thing that makes a
rerun cheap. `ProxyFrameCache` in `gui/proxy_cache.py` says which one it is at
the import line.

Entries under `docs/findings/` and `docs/completed-todo/` still name
`gui/frame_cache.py`. They are records of what was true when written and were
left alone; this entry is the forward pointer.

## What was checked by mutation

Both fixes were reverted in place and the new tests re-run:

- `setData` returning `True` unconditionally: all three parametrisations of
  `test_a_rename_the_document_refuses_is_reported_as_no_change` fail.
- `_store` comparing `self._settings.value(key)` again: all three
  parametrisations of
  `test_writing_the_same_value_is_silent_over_a_file_qt_did_not_write` fail.

The first version of the preferences test — a `Preferences` reopened over the
same path — passed against the bug, and is the reason the per-process cache is
documented above rather than only worked around.

## What changed outside the item's scope

`ReplicateDocument.rename` grew a return type. It is the only one of the
document's user intents that reports anything; `set_roi` still returns `None`
because `setData` learns of a rejected geometry from the `ValueError` that
`ROI` raises before the document is reached. An unchanged-but-valid geometry
edit therefore still returns `True`, which is a repaint of an identical cell
and not a lie about what the user typed.
