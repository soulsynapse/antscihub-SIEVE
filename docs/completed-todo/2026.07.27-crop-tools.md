# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: two rectangles — content_rect is the fit, view_rect is the mapping
    why: every coordinate method assumed fit-scale, and threading a scale and a
      pan through each one separately is how they drift apart; one rect that
      *is* the mapping means to_source, to_widget and the paint path cannot
      disagree, and content_rect survives as the thing view_rect is clamped
      against — which is the entire zoom-floor rule, not a separate guard
  - what: view_rect returns content_rect itself at zoom 1.0, not an equal copy
    why: a floor implemented by clamping a running product lands a float epsilon
      under the fit and paints a hairline of letterbox inside the frame
  - what: adjustment handles exist only on the selected replicate
    why: a dozen arenas wearing ninety-six grab targets is an unreadable
      overlay, and the tab's existing rule already makes the selected box the
      only adjustable one — a click on any other box accepts it and navigates
  - what: handles are hit-tested before containment
    why: a handle straddles its corner, so its outer half lies inside whatever
      box is behind; containment-first makes the corner of an overlapping box
      unreachable and turns the press into a new drawn region
  - what: drawing needs travel in both axes, adjusting needs it in either
    why: a one-pixel-tall new replicate is never intended, but a box slid
      horizontally along a rack has travelled exactly as far as the user meant —
      under the both-axes rule that drag releases as a click, and the tab reads
      a click on a replicate as accepting it and navigating away
  - what: placement slides against the frame edge, never trims
    why: '"placement must preserve width and height exactly" — a stamp that lost
      four pixels to the edge lands in a different equivalence group while
      looking identical on screen; ROI.clamped_to is the opposite rule and
      belongs to typed numbers'
  - what: undo merging keyed on a per-press token, defaulting to no merge
    why: one gesture is one entry, two gestures are two, and a typed number is
      its own — the token distinguishes all three, where a merge id keyed on the
      command class collapses an afternoon of nudging into one entry
  - what: mergeWith keeps the first command's displaced geometry
    why: Qt runs redo before merge, so the later command has already applied;
      absorbing its _previous too would undo to the second-to-last waypoint
  - what: every drawn region sets the stamp size, in both modes
    why: the vision says a stamp is "drawn first"; making that a stamp-mode-only
      side effect requires switching modes before the draw that defines the
      size, which is an ordering nobody would guess
  - what: the tools pane writes through ReplicateDocument.set_roi, as the table does
    why: one undoable command over one document; a parallel edit route is a hole
      Ctrl+Z reaches unevenly

rejected:
  - what: ROI.moved_inside as a core primitive paired with clamped_to
    why: written, then removed — it takes a valid ROI, and a stamp centred near
      the origin computes a negative x that ROI.__post_init__ rejects before any
      clamping could run, so the core version was strictly weaker than the view
      helper that takes loose integers
  - what: painting handles on every replicate
    why: see the decision above; discoverability was not worth the overlay
  - what: widening MIN_DRAG_PX's rule to cover adjustment
    why: the two gestures want different predicates, and sharing one is what
      produced the horizontal-move bug found by the first failing test
