# An infinite band edge saves as null and poisons the project

Reported against `videos-testing/stab_GX010050c2_02_18_26.sieve.yaml` (kept
beside the video as `….sieve.yaml-BUGGED`): a project reopened with its
replicates clickable and its tuning frozen — no knob edit reached the file, and
deleting the file was the only way out. The file said why in two lines:

```yaml
detector:
  value_band: [51206.805552141734, .inf]      # baseline: correct
replicates:
- detector_overrides:
    value_band: [51206.805552141734, null]    # pin: destroyed
```

`DetectorSettings.value_band` is `tuple[float, float]`, and pydantic leaves a
non-finite float alone in a typed field under `model_dump(mode="json")`.
`Replicate.detector_overrides` is `dict[str, Any]` — it must be, since the
detector's fields are validated one layer up and a filter owns its own
parameter model — and the `Any` serializer obeys `ser_json_inf_nan`, which
defaults to `'null'`. So one drag of a value band with an open top edge, on an
arena that pins it, wrote a pin that was not a number.

The reader then let it in: `_references_resolve` checked the *spelling* of a
detector pin and deliberately left its value to `resolved_detector`. The
document therefore loaded clean and the `ValidationError` fired later, inside
whichever Qt slot first asked what the selected arena runs with. A slot that
raises aborts, so the table went on selecting rows while the knobs never
resynced, `edit_detector` never landed, and every save wrote the same
unchanged pins back.

**What was checked by mutation.** Each of the three changes was reverted in
turn against the new tests: dropping `ser_json_inf_nan` fails the pinned-`.inf`
round trip (through the new reader guard, which is the two halves being
independently real); replacing the `resolved_detector` call in
`_references_resolve` with `pass` lets the poisoned document load; returning
`value` rather than `SCHEMA_VERSION` from `_readable` leaves the stale stamp.

**Where the old test was.**
`test_project_round_trips_detector_and_pins_including_infinite_edges` is named
for exactly this case and never reached it — its infinity is on the baseline,
a typed field, and its only pin is an `int`. The seam was between what the
test's name claimed and what its data covered.
