# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: the serializer is configured on `_Artifact`, not worked around at the pin sites
    why: the two halves of one band disagreed only because one lives in a typed field and the other in `Any` storage; a fix at the pin site would have to be repeated for `Replicate.overrides` and for every future opaque mapping, and the next one would be found the same way this one was
  - what: the reader validates pinned detector *values*, not only their spelling
    why: the split that left value validity to `resolved_detector` meant an unloadable pin became a deferred raise inside whichever Qt slot asked first — the table went on selecting rows over a document whose every tuning path was dead, which is rule 6's mirror direction
  - what: schema_version is normalized to SCHEMA_VERSION on read
    why: the GUI saves by copying the `Project` it opened, so any stamp that survives `model_copy` survives forever; a document this build accepted is by definition in this build's schema, since every field it lacked took the default written to make the older document mean the same thing

rejected:
  - what: repairing a `null` band edge on load by reading it as the infinity of its side
    why: recoverable is not unambiguous — which infinity depends on the edge, and freq_band's lower edge is 0.0 rather than -inf, so rule 6 applies as written (refuse rather than approximate), and the refusal arrives where main_window._read_project already has a file name to put in the message
  - what: catching the resolve failure in the GUI so the tab degrades instead of dying
    why: it treats the symptom at the second-furthest point from the cause; with the reader refusing at load, the only pins that reach a running session are the ones `edited_detector` already validated
