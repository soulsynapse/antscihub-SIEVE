# ---- the load-bearing part ------------------------------------------------
decisions:
  - what: follow-until-touched (sparse pins over a moving baseline), not snapshot-per-replicate
    why: chosen explicitly by Kendrick after comparing both; one rack tunes as one thing, deviation is sparse and visible as equivalence groups, and "the tuning" stays a single exportable object
  - what: the two-write edit was extracted to module level (edited_params / edited_detector)
    why: the GUI document holds pipeline pieces, not a Project; delegating with_param_edit to the same helpers keeps CLI and GUI on one definition of an edit
  - what: detector tuning entered the artifact as Project.detector + Replicate.detector_overrides (schema v3)
    why: bands and the count threshold decide what is claimed as an event; two machines agreeing about the graph but not the thresholds are not agreeing about the run
  - what: solo_block stays out of the artifact; None detector means never tuned
    why: soloing is looking, not tuning; and the untuned D is fps-derived, so resolving a default into the field would fabricate a choice nobody made
  - what: the tab's LiveChain became the resolved view for the selected replicate; the document owns tuning
    why: edits go down as undoable two-write commands and return via tuning_changed/detector_changed; drag tiers and provisional wizard state stay tab-local so live repaints and Cancel cost nothing
  - what: equivalence groups fingerprint the resolved detector alongside the graph
    why: a pinned threshold makes identical series claim different events — "runs the same thing" has to mean detection too
  - what: GUI edits submit only the fields touched, never the whole resolved view
    why: submitting a deviated replicate's full view would drag its pins into the baseline and change every follower for fields nobody edited (edited_params' docstring records the trap)

rejected:
  - what: snapshot-per-replicate settings files with explicit import
    why: no canonical tuning to export, no live propagation across a rack, and the existing override machinery would have gone dead
  - what: session-only memory in the tab (dict keyed by replicate_id)
    why: saves would stay tuning-blind and equivalence groups constant; Kendrick chose artifact persistence
  - what: reserved pseudo-node id to carry detector settings through Replicate.overrides
    why: validation rightly refuses overrides naming no node; a parallel field-level mechanism is honest about the detector not being a node
