decisions:
  - what: rule form is directive + objective + falsifier
    why: a crisp proxy alone Goodharts (fires on cases its objective does not
      care about, leaving only guilty violation or dumb compliance); a squishy
      objective alone binds nothing; splitting the jobs keeps enforcement
      crisp while pre-authorizing revision
  - what: O2 outranks O1 unconditionally; O1 is optimized, the rest satisfice
    why: multiple objectives are managed by constraining all but one (the
      standard multi-objective resolution); without a stated precedence every
      rule collision is re-litigated from scratch
  - what: budgets are scoped to the reference workload
    why: an SLO is a promise about a workload, never about all workloads; the
      five-stacked-filters miss is the scope clause working, and the overload
      regime owes honesty (O2), not speed
  - what: debt relaxes only the gate, never the display, and dies with its item
    why: xfail keeps the miss in the report with the repaying item attached
      (rule 4's visibility); test_budget_debt.py fails when the item file is
      gone, so tolerance cannot outlive its justification
  - what: budget anchors are perceptual bands, written as comments in budgets.py
    why: a number anchored to Card/Moran/Newell's response bands outlives the
      hardware that first met it; one anchored to what v1 achieved is history
      wearing a rule's costume

rejected:
  - what: binding the squishy objectives directly
    why: unenforceable rules are decoration that teaches readers all rules are
      decoration
  - what: anchor/scope as new columns in the machine-checked budget block
    why: the block's parser is character-exact and the anchors are per-budget
      prose, not table cells; comments beside the limits keep one home per fact
  - what: an adaptive concurrency split (rule 5's falsifier case)
    why: named as the revision path in the falsifier, not built — no evidence
      yet of cores idling while a user waits
