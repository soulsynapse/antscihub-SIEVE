decisions:
  - what: the size comes from the stamp fields, not from the selected box
    why: the two numbers the button applies are then on screen beside it before it is pressed
  - what: centre-preserving, not origin-preserving
    why: the boxes were drawn around the arenas, so the middle is what each one asserts
  - what: slides at the frame edge (ROI.placed_in), never trims
    why: a trimmed box leaves the rack non-uniform in exactly the case the button was pressed to fix
  - what: SetReplicateROIs is one command holding many rows, not a loop over SetReplicateROI
    why: mergeWith only joins commands naming the same row, so a loop is one undo entry per replicate
  - what: the slide rule moved from VideoView._placed into core/types.py
    why: the stamp and the batch resize are the two callers, and two copies of a clamp disagree at the only place either is interesting
  - what: no undo entry when the rack is already uniform at that size
    why: a button that stacks a no-op onto the history every press teaches users not to press it

rejected:
  - what: scoping "set all" to the selected equivalence group
    why: groups are derived from parameter overrides, which is a different axis from geometry entirely
  - what: applying the selected box's full ROI, position included
    why: that stacks every replicate on one arena; only the extent is shareable
