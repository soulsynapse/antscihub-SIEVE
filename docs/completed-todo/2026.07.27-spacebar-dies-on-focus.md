# Spacebar dies on focus

Two things worth knowing that the diff does not say.

**The two halves could not be split.** The item offered to defer the
commit-boundary work as its own item, and that reads as the smaller change until
you write it: removing focus-based suppression *without* commit-based
suppression regresses Delete. The shortcut fires before the focused widget sees
the key, so a spin box with `15` half typed and no claim on the keyboard would
have Delete remove the replicate being edited. Focus suppression was covering
for the absence of a commit boundary, and the two had to be replaced in one
step. The drop menus genuinely are separable, and they were separated.

**The delegate stores its editors' keys rather than deriving them twice.** The
first attempt keyed on `id(editor)` computed at both ends, which is wrong in a
way no test would have caught: PySide is free to collect a wrapper it is not
holding and hand out a fresh one for the same C++ widget, so the close could
arrive under a name the open never used and the keyboard would stay claimed
forever — the exact defect this item is about, reintroduced one layer down.
Holding the editor in a dict fixes the identity and keeps the wrapper alive for
as long as the entry that names it. The ordering in `destroyEditor` — pop and
announce, then `super()` — follows from that and is not visible at the call
site.

Mutation-checked, four single-line reversions, each failing a distinct test and
nothing else: dropping `setKeyboardTracking(False)` (a partly typed number
reaches the document); dropping the `hideEvent` override (a field hidden
mid-edit strands the keys); `EditingSources.mark` clearing instead of discarding
on close, which is the old latch's behaviour (one source's close cancels
another's); and putting focus back as a claim (a click into a field disables
play).
