decisions:
  - what: a third thread for the derivation, not the GUI thread or the render thread
    why: the GUI thread blocks the repaint the work exists to cause; the render thread's consumer runs inside the timed spans, so an FFT there inflates full_preview_render and steals decode throughput
  - what: pacing is "submit when idle", with no timer or interval anywhere
    why: the partial rate then settles at render_time / recompute_time on its own — a cheap chain nearly streams, an expensive one steps, and a fixed cadence would have to be wrong in one of those directions
  - what: the curves draw to the decode frontier faded, but the gate stops at the settled one
    why: a provisional value reads as provisional; a provisional detection does not — ticks drive the seeker's jumps, so an interval that appears and vanishes is navigation lying
  - what: the x axis is the working window, set at submission, not the frames collected
    why: an axis that grew with its data would slide every curve leftward on each pass, so a filling graph would read as a moving one
  - what: the final derivation goes through the same worker as every partial one
    why: two paths producing the graphs are two places for the frontier arithmetic to disagree; `final` is just a partial pass allowed to claim the whole record
  - what: knob_to_first_partial added rather than knob_to_graphs redefined
    why: both intervals are real and answer different questions, and redefining would silently rewrite what existing findings measured
  - what: non-negotiable #5 reworded over consumers rather than over the two regimes
    why: it was a two-body rule and there are now three contenders for cores; the case that bites is a third consumer starving both others
  - what: the worker cap is an optional parameter defaulting to every core, not a constant in core/
    why: a CLI run, a whole-clip pass and a headless parity check on a cluster node have nobody to leave room for and should saturate the node
  - what: PAD_EFOLDINGS 1 -> 3 and a new COI_SETTLE_EFOLDINGS of 2
    why: measured; see the finding — the pad was letting the record wrap onto itself at 2.4% of full scale

rejected:
  - what: settled-frontier-only painting, with the trailing ~2.7 s left blank
    why: that gap is the complaint, not the fix — it would make the empty region permanent instead of transient
  - what: recomputing in the render thread's consumer with the contract amended
    why: buys graph liveness with decode throughput, which non-negotiable #5 calls a defect rather than a tuning choice
  - what: a Regime.DERIVED third value in bench/budgets.py
    why: the regime axis is about where the user feels latency, not which thread does the work; a headless run has no regimes and the value would mean nothing off the GUI
  - what: a cancel flag on the detector worker
    why: a single FFT has no boundary to check at, so the flag would be read once, before the work — which the submission already did
  - what: keeping filled/settled in DetectorState
    why: DetectorState serializes into the pipeline artifact, and render progress is GUI-only state — non-negotiable #2

measurements:
  source: synthetic (T, B) block series, 20 fps, bank 0.50-9.00 Hz; 40-frame GUI fixture
  results:
    - "partial passes over a 40-frame window: 13-14 across three runs, strides of ~3 frames"
    - "same probe with prefetch read-ahead disabled: 17 passes at ~2 — the loop
       self-paces to the render, so a slower render buys more and smaller passes"
    - Morlet pad wraparound at 1 e-folding: 2.4e-2 of full band-power scale
    - same at 3 e-foldings: 3.0e-7 (float32 floor from 4 onward)
    - settled-frontier error at 1 e-folding: 1.5e-3, worst index at the cut
    - same at 2 e-foldings: 4e-5, worst index interior
