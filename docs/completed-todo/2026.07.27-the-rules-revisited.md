# The rules revisited

## What the audit found, beyond the rules themselves

Four claims in `ARCHITECTURE.md` were false about the code:

**"Cache keys include upstream content hashes."** They do not, and
`cache_key.py` argues at length for why not — source identity is
`path | st_size | st_mtime_ns`, because hashing the file costs a full read of a
multi-gigabyte video on every project open. Upstream *keys* are folded in, so
ancestry is transitive, but it bottoms out in three cheap facts. This was the
most dangerous sentence in the document, because it is the kind of claim
somebody builds a correctness argument on top of.

**The warmup walk.** The document said `core.source_warmup_frames` "is the only
thing that should" compute lead-in and that the executor requests from it. It
has no runtime caller. `pipeline/plan.py`'s `_lead_in` is what runs: a backward
pass over `Dag.order` taking the **maximum over a node's downstreams**, because
a DAG has many root-to-node paths and a diamond has exponentially many. The two
agree only because `input_warmup_frames` is monotone non-decreasing — the path
walk is the definition and the property test's oracle, the max walk is the
implementation. The document described the oracle as the implementation.

**Ports were absent entirely.** Multi-upstream landed with `Edge.port`,
`MergingKernel`, and schema v2, and the architecture document still described a
Pipeline Model of four bullets with no mention of any of it — including the
consequence that ports are bound into the digest, so `a - b` and `b - a` are two
computations.

**`bench/` is drawn above `pipeline/` and depends on nothing.** It imports only
stdlib; nothing observes from up there, things push into it. Its tier is a
prohibition, and the price is that `pipeline/preview.py` spells two budget keys
as string literals — reintroducing one layer down the unchecked-key typo that
`metrics.py`'s key registry exists to prevent. Documented rather than removed,
and closed from the other end by the new test's AST check.

## The bug the rules review turned up

`gui/filter_tab.py` called `chain_model.recompute` without a `workers` argument.
The default was `ALL_CORES`. On a frequency-band commit that path discards the
retained band power and runs a full Morlet transform — so the fourth consumer
that `gui/concurrency.py` exists to forbid was running over every core, on the
GUI thread, beside the player's decode thread and the preview's pool, doing
exactly what `detector_worker.py`'s module docstring says that worker exists to
prevent.

`tests/unit/test_concurrency.py` passed throughout. It sums three declared
constants and asserts the sum leaves a core free; a consumer that never declared
itself is outside what that test can see. This is the generalizable part, and it
is now written into `AUTO-GUARDRAILS.md` §7: **a shared-resource cap should be a
required argument before it is a constant with a test**, because the required
argument is checked where the violation would be written.

Capping at `DETECTOR_WORKERS` restores the arithmetic but does not make the
stall go away — it lengthens it, since the transform now has two cores instead
of all of them. The honest fix is routing that derivation through
`detector_worker.py`, which is a follow-up rather than part of this item because
it changes ordering and partial-pass behaviour.

## What was checked by mutation

The producer test was verified not to pass vacuously, which mattered because a
guardrail that cannot fail is precisely what this file's §4 was already warning
about:

- The reference scan was run over all 74 modules outside `bench/` and partitions
  the table 7/4 — matching, independently, what a separate read of the call
  sites had found. A scan that matched everything or nothing would have produced
  the same green test.
- The `*_BUDGET` AST check finds 6 real constants across three modules,
  including the two in `pipeline/preview.py` that the layer boundary forces. A
  check finding zero constants would also have passed.

## What changed outside the item's scope

`ALL_CORES` is no longer imported by `gui/chain_model.py` — with the default
gone it appeared only in prose, and ruff caught it. `tests/unit/test_chain_model.py`
now imports it from `sieve.core.wavelet` and passes it explicitly, which is the
right thing for a headless unit test to say anyway.

`bench/metrics.py`'s docstring claimed the table held eight budgets and that four
could not be checked. The table holds eleven, and the sentence had been true when
written.
