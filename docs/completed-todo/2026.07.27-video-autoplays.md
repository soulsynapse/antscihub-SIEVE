# Video autoplays

There was no autoplay path to repair — `VideoPlayer.play` had exactly one
caller, the space-bar toggle — so the whole item was placement, and the tests
are about placement rather than about playing.

Mutation-checked: moving the `play()` call up to just after
`self._preview.open(...)` — the earliest point where it would still "work" —
fails `test_playback_starts_after_the_document_is_bound` and
`test_playback_waits_for_the_neighbour_offer` while leaving
`test_opening_a_video_leaves_it_playing` green. That is the split the three
tests exist for: the first says the behaviour happens at all, the other two
each pin one ordering constraint, and neither can be satisfied by asserting on
the end state.

The neighbour-offer constraint is still live. The item recorded it as
*dissolved* by `docs/todo/no-save-prompts-keep-history.md`, which decided the
neighbour project is opened and announced rather than asked about — but that
item has not landed, and `main_window.py:_offer_neighbour_project` still raises
a `QMessageBox.question`. When it does land, the modal goes away and
`test_playback_waits_for_the_neighbour_offer` goes with it; nothing about the
placement has to change, because "last" stays correct once the thing it was
sequenced after stops existing.
