  - what: the target test is unfocused *and* enclosed by a scroll area with
      room to move — not focus alone
    why: focus alone taxes every knob in the application to fix the one column
      where a wheel is ambiguous; the D slider under the video has no second
      possible meaning for a wheel and made that concrete, so the rule asks
      the question that actually distinguishes them — is there something else
      here this gesture could move
  - what: "room to move is part of the test, not a refinement of it"
    why: a card column short enough to fit has nothing to scroll to, so
      yielding there would leave the knob dead to the wheel with nothing
      gained; the cost is that unfocused behaviour depends on panel height,
      which is the lesser surprise
  - what: pass-through forwards a copy up the parent chain rather than
      returning False
    why: '`QAbstractSpinBox.wheelEvent` and `QAbstractSlider.wheelEvent` step
      on any wheel that reaches them, focused or not — declining hands the
      event to exactly the behaviour this filter replaces'
  - what: the walk is written out instead of delegated to QApplication.notify
    why: notify performs its wheel-propagation loop only for *spontaneous*
      events; a re-sent one is delivered to its receiver and stops, so
      sending to the parent and trusting Qt to climb silently does nothing
  - what: Polish takes the wheel bit out of a knob's focus policy
    why: "`QApplicationPrivate::giveFocusAccordingToFocusPolicy` acts on a
      spontaneous wheel before any event filter runs, and both widget kinds
      default to `Qt.WheelFocus` — so the first real notch over an unfocused
      knob would focus it on the way in and arrive here already focused; the
      focus half of the rule would be true and useless"
  - what: scroll areas' own QScrollBars are exempt from the filter entirely
    why: they are navigation rather than values, and they are where a
      forwarded wheel lands — QAbstractScrollArea.wheelEvent sends to them,
      so normalizing them would swallow the scroll just forwarded

rejected:
  - what: per-widget setFocusPolicy / installEventFilter on each card
    why: '`param_form` generates knobs for every filter, present and future,
      so the fix would have to be repeated on every card ever added — the
      compounding the item was opened to avoid'
  - what: requiring focus on every knob in the application
    why: it was the first rule tried and it locked the D slider, which is
      useful to wheel freely; the bug is a property of the scrolling column,
      not of knobs

# Wheel over the panel

The item asked for a precondition on an existing filter and that is what this
is, but two things about Qt had to be established first, and neither is
visible from the filter's own code.

**Qt gives focus on a wheel, before any filter sees it.**
`QApplication::notify` calls `giveFocusAccordingToFocusPolicy` for spontaneous
wheel events, and `QAbstractSpinBox` and `QAbstractSlider` both default to
`Qt::WheelFocus`. A focus test alone would therefore have been satisfied by
the very gesture it was meant to reject — and no test would have caught it,
because a hand-built `QWheelEvent` is not spontaneous. The `Polish` hook is
what makes the focus half mean anything; it is pinned directly by
`test_polish_takes_the_wheel_out_of_a_knob_s_focus_policy`, which asserts on
the policy rather than on behaviour for exactly that reason.

**Qt does not propagate a re-sent wheel.** The propagation loop that climbs
the parent chain lives inside `QApplication::notify` and runs only for
spontaneous events; `sendEvent(parent, wheel)` delivers to the parent and
stops there. The first version of the pass-through did that and the scroll
area never moved. `_pass_through` now mirrors Qt's loop — offer, stop at the
first acceptor, respect `isWindow` and `WA_NoMousePropagation`.

**What was checked by mutation.** Reverting `_pass_through` to a plain
`sendEvent` to the parent fails
`test_the_passed_through_wheel_reaches_the_scroll_area` while every other
test still passes — which is the shape of the near-miss worth guarding, a
pass-through that looks correct and moves nothing.

**The rule changed once under use.** The first implementation used focus
alone, as the item suggested. Driving it showed the D slider locked until
clicked, which is a real loss: the left column has no scroll area, so a wheel
there was never ambiguous. The scrollable-ancestor test replaced it. The item
was right that the fix belongs in one place; it was the *rule* that needed
the column it was written for.
