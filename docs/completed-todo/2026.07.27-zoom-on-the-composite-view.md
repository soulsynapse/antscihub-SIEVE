# Zoom on the composite view

The item's reading of the inverted tab names was right: the replicate tab has
zoom, the filter tab is the one that did not.

**What was checked by mutation.** Four defects, each failing exactly one of
the four new tests and no others:

- the grid painted against the un-zoomed content rect (the pre-item
  behaviour) → the registration test;
- `block_at` without its second containment test → the letterbox test;
- the wheel zooming without panning → the anchor test;
- `view_rect` without its clamp → the floor test.

Two of those tests did not catch their defect when first written, and both
misses are the same shape — a fixture centred where the bug is invisible:

- The anchor test used a mid-cell point. A magnifier that zooms and never pans
  still holds a point at fraction `u` at `0.5 + (u - 0.5) / zoom`, which drifts
  by at most a quarter of the grid — so mid-cell anchors survive the missing
  pan. The anchor now sits a hair inside a cell boundary in both axes, where
  that drift crosses.
- The floor test scrolled out about the pane's centre. Panned to the centre,
  the clamped rect and the unclamped one are the *same numbers*, so the storm
  exercised the arithmetic and never the clamp. Both wheels are off-centre now,
  and the per-step assertion is that the rect still contains the fit.

The registration test also had to be made two-sided. Read for bare red alone,
it catches a grid that drifted one way and is blind to the other — and which
way is a matter of the sign of the pan, which the test controls by accident.
It now checks both edges against the seam of the image itself, read off the
rect the image was drawn into.

**One thing found on the way.** `pane = make_view().pane` drops the last
Python reference to the parent, and Qt then deletes the child mid-test — which
surfaced only under the full suite's collection timing, not when the module ran
alone.
