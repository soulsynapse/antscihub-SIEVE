decisions:
  - what: >
      The refusal is a *hole* in the spin box's range — `{0} | [floor, 256]` —
      not a raised minimum.
    why: >
      `0 = auto` sits under the floor and is the resting default. A `setMinimum`
      bound would have taken it with it, and auto is the one value whose block
      count is a property of the source rather than of the knob (64 source px,
      3,901 blocks on the reference frame). The hole is enforced on the three
      paths a value enters through — `stepBy` for wheel and arrows,
      `valueFromText` for typing.
  - what: >
      A value *already* below a newly-derived floor is left exactly where it is,
      and the stall it would cause is refused at the surface instead.
    why: >
      The floor governs what may be entered; it is not a claim about what the
      pipeline holds. A project saved before the bound, or one whose crop grew
      under a fixed block size, is a real parameter value, and a widget that
      silently raised it would display a number the chain does not hold — rule
      6's mirror clause. `density_plot.set_series` is where every path into the
      value passes, so that is where the bound is absolute.
  - what: >
      A new `density_rebuild` budget at 100 ms, published by `filter_tab`, with
      `MAX_BLOCKS` defined as the B it is pinned at.
    why: >
      The item required the threshold to be a ceiling with a producer rather
      than a number in a widget (rule 4). 100 ms is the instantaneous band: the
      rebuild runs on the GUI thread and lands repeatedly while a window
      renders, so each one must fit in one perceived beat rather than merely
      inside the 500 ms `knob_to_first_partial` it sits within. Measured at
      84.1 ms at B = 16,384, confirming the provisional bound.
  - what: >
      `min_block_for` lives in `filters/block_signal.py` beside `grid_shape`,
      not in the GUI.
    why: >
      It is the same ceiling division read backwards. A GUI-side copy would be
      free to disagree with the grid the kernel actually forms, and a control
      refusing the wrong values is worse than one refusing none.
  - what: >
      `MemoryError` joins the two value errors the worker catches, and all three
      are reported as a `DetectorFailure` rather than swallowed.
    why: >
      The original argument was sound about modals and wrong about silence. A
      raise there is still a module defect a user cannot act on — so no dialog —
      but a graph that stops advancing and says nothing reads as "still coming",
      which is rule 6 exactly. `MemoryError` is the failure this path actually
      reaches at a large block count, and it was escaping uncaught.

rejected:
  - what: computing every legal value and letting the benchmark guard the cost
    why: >
      The item's own rejected side, and it holds: the benchmark runs in CI
      against the reference count, never against the value a wheel notch just
      set, so it cannot protect the session that matters.
  - what: raising the `density_rebuild` ceiling to buy a second octave below auto
    why: >
      It is anchored to the ~100 ms perceptual threshold, not to what this code
      achieves. B grows as the square of the reciprocal block edge, so a second
      halving costs 340 ms — the ceiling would have to more than triple. The
      honest route to a lower floor is a cheaper binning, which is an open
      question in the finding.
