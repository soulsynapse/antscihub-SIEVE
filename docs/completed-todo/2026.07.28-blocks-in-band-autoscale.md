decisions:
  - what: >
      The regime disclosure is a derived title-row line (`CountPlot.scale_label`
      through a new `BandPlot.readout_text` hook), naming both the ceiling in
      force and the region's block count, always, plus `· full` when they meet.
    why: >
      The ceiling is computed inside `_range` from four pieces of paint-time
      state (peak, band edges, region size, the drag freeze). Anything pushed in
      from outside — a `set_readout` call from `filter_tab` — is a second
      derivation that can fall out of step with the frame it labels, which is
      exactly the rule-6 failure the line exists to prevent. Overriding the hook
      makes the label and the geometry read the same `_range` call.
  - what: >
      Both numbers appear in both regimes rather than a mode word or a badge
      that appears only when autoscaled.
    why: >
      "0-7 of 512 blocks" and "0-512 of 512 blocks · full" are the same sentence
      with different numbers; neither can be misread as the other, and there is
      no state in which the absence of a marker has to be noticed. A marker that
      appears only in one regime is a thing a reader can fail to see.

rejected:
  - what: Tick labels on the value axis.
    why: >
      No plot in the family carries them — the shared frame is title row, grid,
      handles with right-margin readouts. Adding them to one plot would make the
      count plot read as a different kind of object than the density and
      scalogram plots beside it, to say one number that fits in the title row.
  - what: Recomputing the label whenever the inputs to `_range` change.
    why: >
      Five call sites (`set_series`, `set_band`, `clear_band`, press, release)
      each responsible for keeping a cached string true. The lazy hook has one.

# Blocks in band autoscale

The autoscale itself — series peak unioned with the band edges, ×1.06
headroom, capped at B, zero floored, frozen for the duration of a handle drag —
had been written and committed in `599af61` by an earlier session that never
completed the item. This session verified that work against the item's stated
claims and found one of the three unbuilt: the axis said nothing about which
ceiling it was on, so two tunings whose counts differ by two orders of
magnitude drew identically. That gap is what this entry adds, along with the
tests for all three claims in one place.

The load-bearing test is the third one — the label follows the *frozen* axis
through a drag. It is the one that would fail if the label were ever re-derived
independently of `_range`, and freezing is precisely the window in which an
independent derivation would disagree.
