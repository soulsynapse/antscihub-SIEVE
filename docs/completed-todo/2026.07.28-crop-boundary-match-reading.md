summary: >
  The four states of a replicate's source boundary — absent, writing, at rest,
  stale-with-the-clause-that-missed — are now derivable in one Qt-free call
  (`gui/crop_binding.py`), alongside the span a backed clip may not leave, so
  the card and the freeze that both need them read one implementation instead
  of two; `Project` gained the wholesale `with_crops` and the identity-keyed
  `without_crop` a discard gesture needs.

decisions:
  - what: >
      Split out of docs/todo/crop-boundary-gesture.md and landed on its own,
      leaving the card, the worker, and the freeze surfaces open there.
    why: >
      Step 3 of that item named "one implementation, imported" as the thing
      that keeps the card and the freeze from disagreeing — which describes a
      module, and one that needs no Qt to be written or tested. Landing it
      behind the widget would have meant the shared rule arriving only as an
      implementation detail of the first thing that happened to need it.
  - what: >
      An orphaned record is attributed to a replicate by overlap, and to
      nobody when two replicates overlap it.
    why: >
      Records carry no replicate id on purpose (`CropArtifact`) — association
      is by parentage and geometry, so a renamed arena keeps its artifact and
      a moved one correctly stops matching. That leaves a record whose box
      moved with no owner in the model, and overlap is the only answer the
      model admits. Declining on a tie is rule 6: a card that guesses which
      arena a file belonged to is worse than one that stays quiet about a file
      the user can still see in the folder.
  - what: >
      A set of records with no common span freezes nothing, rather than
      freezing to an empty or reversed range.
    why: >
      The frozen span is the intersection of every backing cut, and only
      hand-editing a project can produce records that do not overlap. Freezing
      to an impossible span would refuse every clip edit including the ones
      that resolve it, trapping the user in the state they most need to edit
      their way out of.
  - what: >
      Window coverage is evaluated here rather than folded into
      `CropArtifact.backs`.
    why: >
      A record whose window widened past the cut still matches on parentage,
      geometry, and format — the file is on disk and re-cutting it wider is
      the remedy. `resolve_source` needs only "can this serve", and answers by
      falling back to the parent; the card needs "why not", and a clause
      hidden inside the predicate could not be named on screen.
  - what: >
      `Project.without_crop` is keyed on `CropArtifact.identity`, and
      `with_crops` validates rather than assigns.
    why: >
      Identity, because what is discarded is a *cut* and the path it happens
      to be recorded under is convenience — a discard must not depend on the
      caller holding the same spelling the document stored. Validated, because
      `with_crop` cannot produce "two records for one cut" but a caller
      assembling a whole tuple can, and an assigning setter would let the GUI
      write a document `Project` itself would decline to load back.

rejected:
  - what: Rendering a stale record as not-at-rest, with one boolean for both.
    why: >
      Rule 6's central case. An artifact that was cut and then orphaned is a
      different claim from one that was never cut; collapsing them makes a
      file sitting on disk look like a decision nobody has taken yet, and the
      user takes it again — a minute of encoding for a file they already have.
  - what: Freezing the box while a *stale* record names it.
    why: >
      `frozen` is AT_REST only. A stale record is already orphaned, so the
      freeze would be protecting a file that has stopped serving, at the cost
      of the edits that would fix it.
