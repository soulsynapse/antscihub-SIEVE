  - what: >
      One geometry, `_CompositePane.grid_edges`, returns the integer pixel
      columns and rows the grid lines fall on, and both the paint and
      `block_at` read it.
    why: >
      The seam was float associativity, not device-pixel rounding: cell `i`'s
      top came from `top + i*ch` and cell `i-1`'s bottom from
      `top + (i-1)*ch + ch`, the same real number and not always the same
      float, and one ULP either side of a half pixel is a bare row. Rounding
      the line rather than each cell's own origin and extent makes the shared
      edge one number, so neighbours cannot round apart. Routing the hit test
      through the same list is the free half: the cell under the pointer is
      the cell drawn there, rather than agreeing to within a rounding.
  - what: >
      A detected cell owns its top and left wall pixels always, and its
      bottom and right ones only where no detected neighbour is there to own
      them instead. Fills take whatever the walls leave.
    why: >
      That asymmetry is what makes a wall one pixel wide *everywhere* — two
      adjacent detected cells split one line rather than each insetting and
      each stroking — while keeping every wall pixel painted exactly once, by
      exactly one cell, so the border alpha means one thing on screen rather
      than compositing over itself at shared edges and at corners.

      The item's first suggestion: stroke boundary edges only, so an edge is
      drawn iff exactly one of the two cells it separates is detected.

# Grid overlay seam and border width

Both defects were in `_CompositePane._paint_grid`, and both came from the same
habit: each cell computing its own rectangle from a float cell size.

**Mutation-checked.** Restoring the old per-cell `QRectF` heat fill fails
`test_the_heatmap_tiles_with_no_uncovered_row_at_any_pane_height` at pane
height 229 of the 200–260 sweep — so the sweep is load-bearing and not
decoration. The sweep's shape was chosen from a probe of the old geometry over
`ny` 2–60 x heights 150–400: about 3.6% of geometries seam, always a single
row near the pane's middle, and they cluster at a fixed height period for a
given row count. That is why a single geometry proves nothing here and the
item asked for a sweep; a 60-height window at 12 rows contains several.

The border test measures with the fill opaque and the border at zero, so the
wall reads as bare panel and its *width* is a count of background pixels —
exactly one where it used to be two. The lone-cell test is the other side of
the ownership rule: giving the bottom and right lines away is only sound if a
cell with no detected neighbour keeps them.

## What was checked and left alone

The item's second seam candidate — partial edge blocks, where `grid_shape`'s
ceiling division makes the grid's data extent up to `block - 1` px past the
frame — is real and is *not* fixed here. It could not be the seam (a uniform
stretch distorts registration everywhere rather than opening one clean gap,
and the screenshot's line sat mid-pane), and the pane cannot correct it as
built: `set_grid` tells it the grid *shape* and nothing else, so it has no
block size and no frame size to compute the overhang from. Correcting it means
a new fact crossing the tab boundary, which is a wider change than this item.
The residual error is a uniform scale of `ny*block / frame_h`, bounded by
`(block - 1) / frame_h` — under half a percent at the block counts the
overlay is readable at, and zero whenever the frame divides evenly.
