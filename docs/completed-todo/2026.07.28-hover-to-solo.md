summary: >
  The block grid solos whatever the pointer is over, a click pins one so it
  survives leaving the grid, and the gesture costs a repaint instead of a
  re-derive because `recompute` never read `solo_block` in the first place.

decisions:
  - what: >
      Solo takes a repaint tier of its own — `_set_detector` then `_apply`,
      no `recompute` — rather than the cheap derive tier every other tab-side
      detector edit uses.
    why: >
      `recompute` does not read `solo_block`: the soloed block picks which
      column of the retained band power the density plot overlays, and that
      choice is made in `_apply`. The cheap tier was therefore paying a full
      in-band count and windowed mean over the whole series to produce a
      bit-identical update. That was invisible at one click per block and is
      the whole cost question at one crossing per pointer move, so the answer
      to the item's "measure the burst of re-derives" was to delete the
      re-derive. `tests/unit/test_chain_model.py` pins the property the skip
      rests on, so a future `recompute` that starts reading `solo_block`
      fails there rather than silently painting a stale update.
  - what: >
      Hover wins over the pin while the pointer is on the grid; the pin is
      only what leaving reverts to.
    why: >
      The item's own rule ("leaveEvent reverts to the latched block"). A pin
      that outranked hover would end the preview tier at the first click —
      there would be no way to compare a second block against the one you
      kept without unpinning first.
  - what: >
      The gesture still publishes `band_drag_repaint`, and it is the pane —
      not the tab — that suppresses a request the state model already holds.
    why: >
      Rule 4: a path that repaints every graph at pointer speed with no
      producer is a ceiling nothing can miss. Deduplication sits in the pane
      because that is where the crossing is known, and it compares against
      `self.solo` — the value the model last applied — rather than a private
      record of what was emitted, so a request the model dropped is asked
      again on the next crossing instead of being deduplicated into silence.
  - what: >
      A grid going away clears the pin and asks for none.
    why: >
      Rule 6's mirror direction. A pin outliving the grid keeps one block's
      trace overlaid on the density plot with nothing on screen saying which
      block it is.

rejected:
  - what: Coalescing hover onto a zero-timer, as the item proposed if the rate bit.
    why: >
      It is the fix for a cost that no longer exists, and it buys latency in
      a gesture the item says should stay immediate. `hover_changed` already
      fires per block crossing rather than per mouse sample, so the residual
      rate is bounded by how fast a pointer crosses cells, against a handler
      that now runs no arithmetic over the series at all.
  - what: Drawing the pinned block's marker differently from the hovered one.
    why: >
      Real ambiguity — while the pointer is on the grid every block draws the
      same marker as it passes, so the pin is not visible as such — but the
      pin does announce itself the moment it matters: it is the one that is
      still soloed after the pointer leaves. A second marker style is a
      change to what the grid means, and it can be added later against a
      complaint rather than guessed at now.
