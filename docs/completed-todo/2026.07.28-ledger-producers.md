decisions:
  - what: psutil became a declared runtime dependency rather than
      ctypes/GetProcessMemoryInfo per platform
    why: the sensor must exist in every install, not only where the dev
      group's transitives happen to resolve it; and the child-process walk it
      gives for free is what the process-isolation item will need, where the
      ctypes route would be rewritten
  - what: counters plus a sampler, not spans on the metrics bus
    why: the bus publishes one duration judged against one budget key, and a
      pool's busy time is a monotonic total only a difference turns into a
      number — also `decode/` sits below `bench/` and may not import it, so
      the meter class lives in `core/pool_meter.py`
  - what: a raise inside `PoolMeter.working()` still counts as busy — the
      deliberate opposite of `MetricBus.measure` publishing nothing on a raise
    why: the bus measures achievement against a ceiling and here the quantity
      is occupancy; a pool that looked idle while its workers raised would
      read as headroom that does not exist
  - what: meters are owned above the churn — the runner owns the prefetch
      meter, the player its decode meter — never by the pool object itself
    why: prefetch sources are rebuilt per footage and per format, and a
      sampler differencing busy time must never see the total jump backwards
  - what: the expensive RSS read runs on the probe's own thread; the GUI-side
      tick reads only meters and mode, and skips when the sampler is out
    why: the child walk (`Process.children()`) snapshots the process table on
      Windows —
      milliseconds on the thread every latency budget is about; a sampler
      that falls behind must thin, not backlog
  - what: an unreadable memory reading publishes `rss_bytes = None` and the
      HUD prints "unreadable" in the band color
    why: rule 6 — a partial sum would be believed, and a probe that went
      quiet would read as a session with nothing to report
  - what: every sample carries the mode that produced it (render-fed
      playback / playback / render / idle)
    why: the recorded session of 2026-07-28 scored zero ring hits in a mode
      where the ring is not in play by design; a consumer summing across
      modes would average regimes that do not compare
  - what: utilisation is busy over wall x resolved workers, not an
      in-flight-time fraction
    why: it answers whether the declared width fits — a two-worker pool with
      one worker saturated reads 0.5, which is the evidence
      `DETECTOR_WORKERS`' docstring asks for by name

rejected:
  - what: a runtime governor that re-tunes the pools live
    why: there was no sensor to close a loop around; this item builds the
      sensor, and `docs/todo/adaptive-worker-allocation.md` holds the
      governor question until multi-machine evidence exists
  - what: per-share memory occupancy sensors in the same item
    why: the session RSS bounds the shares' sum; per-row occupancy is a
      different instrument per consumer, so the four share rows went into
      `WITHOUT_SENSOR` where the reconciliation test keeps the gap visible
