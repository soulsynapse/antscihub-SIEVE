summary: >
  A replicate that has been opened in the filter tab now refuses to be dragged
  until the user accepts what the move costs — the refusal arrives on release
  rather than under the pointer, a declined move leaves no undo entry at all,
  and an accepted one keeps the pins, drops the lock, and lets the ROI hash do
  the invalidating.

decisions:
  - what: >
      The end of a gesture is a signal — `VideoView.roi_adjust_finished(row,
      token)` — and the lock hangs off it, not off `set_roi`.
    why: >
      "Hang the refusal off the merged command" is right about *when* and could
      not be implemented as written: a `QUndoCommand` is never told its gesture
      ended, and `roi_adjusted` looks identical on the last step and on every
      step before it. Only the widget that saw the button come up knows. The
      signal carries the token, so the document can refuse a release that does
      not match the drag it recorded rather than trusting the row.
  - what: >
      A declined move is put back under the gesture's own token, and
      `SetReplicateROI.mergeWith` marks the command obsolete when the merged
      geometry equals the geometry the gesture started from.
    why: >
      This is the only way to reach "no command reaches the stack" without
      rewriting how a drag is recorded. Qt deletes a command that reports itself
      obsolete after a merge, so the entry the drag built removes itself and the
      stack returns to clean — an undo of an undo-able edit could not do that,
      because it leaves an entry to press Ctrl+Z through. Escape's
      `_cancel_gesture` already restored the box the same way and now collapses
      to nothing too, which is what its docstring had been claiming.
  - what: >
      Visitation is recorded by the filter tab on `showEvent` and on every
      selection change while it is the page — not on a render completing.
    why: >
      A frame that never arrived is still an arena the user chose and looked at,
      and a lock that engaged only on success would leave the slowest footage —
      the footage most worth not re-rendering — the only footage unprotected.
  - what: >
      `Project.with_visited` filters to ids that name a live replicate instead
      of validating.
    why: >
      `apply_to` writes the graph last, so every intermediate document it passes
      through has replicates whose overrides name nodes the empty pipeline does
      not have yet; a validating setter fires there. Filtering also gives the
      deleted-arena case for free — the document does not prune on removal, so
      an undo of a delete brings the lock back with the arena, and the file is
      where the stale id is dropped.

rejected:
  - what: >
      Putting the visitation set in `DocumentState`, so rollback and undo move
      it with everything else.
    why: >
      It is edited by the GUI but not by the *user*. Rolling back to Friday's
      geometry does not unsee the arena, and a restore that reinstated a dropped
      lock would re-arm it behind a user who had already been asked and had
      already answered. The cost is the other direction — undoing an accepted
      move restores the tuned geometry with the lock down — and it is
      self-healing: the next look re-arms it.
  - what: >
      Deferring the push during a locked drag, so the geometry only reaches the
      undo stack once the user has accepted.
    why: >
      The box on the video is drawn from the document's replicates, so a drag
      that pushed nothing would freeze the box under the pointer. Step 1 of the
      specified sequence — the drag runs normally, nothing is interrupted — is
      exactly what makes the question answerable: the user is looking at the
      move they are being asked about.
