title: No save prompts, keep history
date: 2026-07-28

tags: [gui, undo, project-io, safety-net]

summary: >
  A tuning session now keeps its own history: every undo-stack step writes the
  whole document to a `<project>.sieve.yaml.history/` directory beside the
  project, and File > History rolls back to any of them as an undoable action —
  so nothing a user does has to be predicted in advance to be recoverable.

decisions:
  - what: >
      A snapshot is a whole `Project` file, and its `source` is relative to the
      history directory rather than to the project directory.
    why: >
      It makes every snapshot openable on its own — `Project.load` reads one,
      the CLI reads one — instead of a fragment that only means something in a
      parent it does not name. Anchoring to the project directory would have
      made each file name a video one level up from where it sits.
  - what: >
      History is kept even when no project file has ever been chosen, at the
      conventional path beside the video (`project_path_for`).
    why: >
      That session is the one with the most to lose. A net that only engages
      after a Save would be absent for exactly the users this item exists for.
  - what: >
      Rollback is `DocumentState` — replicates, pipeline, detector, clip — and
      not a `Project`.
    why: >
      `source`, `checkpoints`, and `outputs` are the window's, not the
      document's (rule 7). A restore that carried them could reassign the video
      underneath the user while claiming to undo an edit.
  - what: >
      A write failure turns history off for the session and says so in the
      status bar, once.
    why: >
      Rule 6. A safety net that has silently stopped being kept is worse than
      no net, and retrying every keystroke into a read-only directory buries
      the one message that matters.
  - what: >
      Retention keeps the newest 50 ordinary snapshots plus *every*
      session-start mark, uncapped.
    why: >
      A pure newest-N rule ages out the "before today" restore point mid-session
      — the case a rollback is most often reached for. The marks are a few
      kilobytes each, which is the price of not having to choose a second
      number. Revisit when outputs make documents heavy.

rejected:
  - what: A snapshot keyed to wall-clock time, or to an interval.
    why: >
      The undo stack already knows what a user-meaningful action is —
      `SetReplicateROI.mergeWith` folds a whole drag into one entry — and an
      interval would cut across gestures, producing checkpoints in the middle
      of one.
  - what: History inside the project file, or in an app-data directory.
    why: >
      Inside the file, every snapshot becomes a rewrite of the artifact the CLI
      reads. In app-data keyed by project path, history detaches the moment a
      project is moved or copied.
  - what: Restore as a file-open that clears the undo stack.
    why: >
      It would make the safety mechanism the one destructive gesture in the
      app. `RestoreSnapshot` is a command, so a mistaken restore is one Ctrl+Z.
  - what: Taking the save prompts out in the same item.
    why: >
      Deleting `confirm_discard` before autosave existed would have opened a
      window in which neither net was in place. Split to
      docs/todo/remove-save-prompts.md, takeable now.
