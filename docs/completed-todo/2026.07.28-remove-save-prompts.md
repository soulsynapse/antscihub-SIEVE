# Take the save prompts out, now that rollback exists

`confirm_discard` and `UNSAVED_PROMPT` are gone, and the four call sites are
unconditional. The load-bearing claim is a *pair* — the close proceeds **and**
the work survives — because either half alone passes on a broken build: a close
that asks nothing and keeps nothing is the silent loss the prompt existed for,
and a history written by a close the user can still refuse is the state before
this item.

Both halves were checked by mutation rather than by reading. Deleting the
`closeEvent` flush leaves `test_closing_with_unsaved_edits_asks_nothing_and_keeps_the_edit`
asserting `[] == ["Add Replicate 1"]`; deleting the new `close_video` flush does
the same to `test_closing_the_video_keeps_the_edit_it_dropped`. The
"asks nothing" half is asserted by recording `QMessageBox.warning` calls, not by
answering them: `no_modal_dialogs` answers everything autouse, so a leftover
prompt would not hang the suite — it would pass unnoticed.

## Outside the item's scope

The `close_video` flush above, and the fixture teardown line in `rejected`.

## What the item asked to be checked, and what was found

- The `closeEvent` flush survived, as required.
- `tests/gui/conftest.py`'s `no_modal_dialogs` still earns its place for the
  failure dialogs `_warn` raises; its `warning` answer changed from Discard to
  Ok, because `warning` is now only ever a statement and the button it returns
  no longer decides anything.
- The neighbour-project modal was already gone (`_open_neighbour_project`), so
  nothing was owed there.

The parent item's ~70–90 line estimate was in the right region for the source
side and understated the tests: the two prompt tests became three, plus two
helpers.
