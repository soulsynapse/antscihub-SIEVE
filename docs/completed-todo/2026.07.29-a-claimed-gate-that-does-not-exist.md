summary: >
  A guardrail can no longer claim a check that was renamed away, and a fired
  trigger can no longer sit without the item it became: AUTO-GUARDRAILS and
  ARCHITECTURE name every check as `path.py::name` and it is resolved by AST,
  cited `.importlinter` contracts are resolved by parse, every **Trigger:**
  line parses with a date and — when FIRED — a `docs/todo/` item that exists,
  and every **Gate:** line in REWORK.md names a live check or says OPEN. The
  armed/fired counts and the oldest re-check date are a derived line in
  `.state.md`.

# Rows a later item must not re-decide, or the word `none`. Generated into
# docs/SETTLED.md; this is the only thing that writes it. Answering `none` is
# the common case and is a real answer — leaving the marker is not.
settled:
  - what: How a trigger and a gate are written, so a machine can read them
    where: "`tools/guardrail_refs.py`"
    do_not_redecide: >
      The state lives inside the bold — `**Trigger: FIRED**`, never
      `**Trigger:** FIRED` — which is what lets the same file name the
      construct in prose without declaring one, and a declaration miswritten
      in the prose shape is an error rather than a skip. FIRED carries
      `→ docs/todo/<slug>.md`; NOT FIRED carries a `(YYYY.MM.DD)` date and
      nothing else is required. A gate declaration is paragraph-initial in
      REWORK.md. Every one of these lines wraps across two source lines, so
      the text is flattened before matching — a line-oriented parser sees
      none of them.
