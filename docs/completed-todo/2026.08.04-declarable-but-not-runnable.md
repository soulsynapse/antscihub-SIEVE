settled:
  - what: Where the "what can this executor not call" enumeration lives
    where: '`src/sieve/backend/dispatch.py`'
    do_not_redecide: >
      Beside the kernel protocols, not beside the executor that raises. Every
      refusal exists because no protocol in that module takes the shape, so the
      protocol and its refusal shrink together in one file on the day a filter
      needs one — `a-kernel-that-sees-a-span` deletes a branch there and nowhere
      else. The function is pure over the spec and returns a *clause*; the node
      id and the filter's id and version are prefixed by `_bind`, which is what
      keeps the answer machine-independent and the message actionable. It stays
      a separate question from `KernelRegistry.select`: whether any protocol
      could call this spec is the same on every machine, and whether a kernel
      for the plan's backend exists here is not.
  - what: How exhaustiveness over a declaration enum is enforced
    where: '`src/sieve/backend/dispatch.py`, `tests/unit/test_declarable_shapes.py`'
    do_not_redecide: >
      `if`/`elif`/`else` with `assert_never` in the `else`, not `match`. An
      exhaustive `match` needs a catch-all pattern and pyright strict reports
      that pattern as unreachable (`reportUnnecessaryComparison`), so the
      construct that reads better is the one that cannot carry the check — this
      was tried and reverted. What the idiom buys is that a third `Mode` or
      `StreamKind` member narrows to itself rather than to `Never` and fails
      pyright on the day it is written, which is a stronger and earlier
      instrument than the walk. The walk is the second one, and it is built from
      the enums by `itertools.product` rather than from a list of shapes, for
      the same reason.
