title: The commit hash writes itself
date: 2026-08-05T18:31:42-07:00
commit: "e4dc68b"
tags: [docs, tooling]

summary: >
  A completed entry's `commit:` is no longer typed: the `post-commit` hook
  reads the entries the commit just carried, writes `git rev-parse --short
  HEAD` into each one, regenerates the index that quotes the hash in a column,
  and commits that as `docs(<slug>): stamp the entry with its commit` — the
  one field that cannot be known when the rest of the entry is written is now
  the one field nobody writes.

settled:
  - what: How a completed entry gets its commit hash
    where: "`tools/stamp_commit.py`, `tools/githooks/post-commit`"
    do_not_redecide: >
      Additively, in a second commit, never by `--amend` — amending changes the
      hash being stamped, and rewrites history a push may already have shipped.
      Scoped to the entries in `git diff-tree HEAD`, so an older `pending` entry
      is left alone rather than stamped with a commit it does not describe. The
      recursion terminates on the pending check itself: the stamp commit touches
      `docs/completed-todo/` again and finds nothing pending.

rejected:
  - what: The whole hook in `sh`, with `sed` doing the substitution
    why: >
      The value is derived and the target is YAML whose quoting is load-bearing
      — an unquoted all-digit hash parses as an integer, one with a leading zero
      as octal. That is the case this repo's bulk-edit rule names, and `sed`
      cannot be tested. The shim is two lines; everything that can be wrong is
      in a typed module with a test.
