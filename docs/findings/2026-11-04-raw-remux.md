# Remuxing a raw H.264 stream: what -c copy loses

2026-11-04, on v5-blob-detection, with the ffmpeg and cv2 of the SIEVE venv on this machine; the
script is docs/findings/experiments/2026-11-04-raw-remux.py. The question, raised when the decoder
began refusing raw streams and naming the remux instead: is the remux the Pi upload worker's `mux`
mode runs actually lossless. The clip is synthetic, 60 frames of 64×48 encoded by
libx264 with a keyframe every 4, once with B-frames (libx264's default of 3) and once without, as the
Pi 4's hardware encoder writes. Each raw stream is remuxed to MP4 three ways with `-framerate 30`
before `-i`. Frames are counted by ffprobe reading every frame and by cv2 reading until the stream
ends; the header column is the container's claim.

| raw stream | remux | ffprobe claimed / read | cv2 claimed / decoded |
|---|---|---|---|
| B-frames (bf=3) | as raw | n/a / 60 | none / 60 |
| | `-c copy` | 60 / 58 | 60 / 58 |
| | `-fflags +genpts`, `-c copy` | 60 / 58 | 60 / 58 |
| | re-encode, libx264 crf 18 | 60 / 60 | 60 / 60 |
| no B-frames (bf=0) | as raw | n/a / 60 | none / 60 |
| | `-c copy` | 60 / 60 | 60 / 60 |
| | `-fflags +genpts`, `-c copy` | 60 / 60 | 60 / 60 |
| | re-encode, libx264 crf 18 | 60 / 60 | 60 / 60 |

A stream carrying B-frames loses its last two frames to a `-c copy` remux, and the container still
claims all sixty, so the file's header lies by two and the decoder corrects itself at the end as it
does for any lying header. The loss is at the tail and does not grow with length: an earlier run of
ten frames lost the same two. Generating timestamps does not recover them. A stream without
B-frames remuxes whole. Re-encoding keeps every frame of either, at the cost of a decode and encode
of the whole file and a second generation of quantisation.

So the mux mode is lossless for the Pi 4 cameras if their encoder writes no B-frames, which the
V4L2 encoder is understood to do and which `ffprobe -show_streams` reports as `has_b_frames` on any
segment to hand; a Pi 5 encoding in software through libav may write them unless told not to, and
there the mux costs two frames a segment, 2 s of a ten-minute segment at 1 fps, or the worker
re-encodes. Not measured here: a real camera segment, which this finding wants before the Pi
worker's default is flipped.
