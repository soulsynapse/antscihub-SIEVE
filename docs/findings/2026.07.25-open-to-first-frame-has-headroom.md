# Open to first frame has headroom

Recorded because a budget that is met is worth a number too — the next time
this path grows a step (a project file to load, a thumbnail track to build, an
index to scan) the question will be how much of the 287 ms of slack it can
spend, and that is unanswerable without knowing the slack was 287 ms.

The split matters more than the total. 25 ms of the 213 is the container
reporting its metadata; the remaining 188 ms is one decode of one 5.3K frame,
which is an order of magnitude above the 28.7 ms a steady-state sequential read
costs. First-decode cost is not per-frame cost, and anything reasoning about
open latency from the per-frame numbers in
`2026.07.25-decode-cost-is-colour-conversion.md` will be wrong by roughly 7x.

Measured through `MainWindow.open_video` rather than against `VideoReader`
directly, because the budget is written about what the user waits for, and that
includes the trip through the decode thread and the first repaint.
