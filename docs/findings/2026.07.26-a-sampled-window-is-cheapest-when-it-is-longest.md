# A sampled window is cheapest when it is longest

The shape is worth stating as a prediction, because a negative result with no
stated prediction is indistinguishable from not having looked. Two costs
compose. A median over `s` samples costs `O(s)` per cell, so **holding more
samples is linearly more expensive**. The estimate is recomputed only when a
sample is admitted, which happens every `stride` frames, so **admitting less
often is linearly cheaper**. Both are driven by the same parameter through
`s = ceil(n / stride)` and `stride = ceil(n / MAX_SAMPLES)`.

Below `MAX_SAMPLES` frames the stride is pinned at 1 and only the first effect
is live: cost climbs linearly with the window. Above it the sample count is
pinned at roughly `MAX_SAMPLES` and only the second is live: cost falls as
`1/stride`. The maximum is exactly where they change places, and it is a
discontinuity rather than a smooth peak because the stride is an integer — 255
frames and 258 frames are one slider nudge apart and 4x apart in cost.

The consequence for the declaration is the part that generalizes. `CostEstimate`
is static and has to be a worst case over the legal parameter range, and the
instinct is to evaluate the range's endpoint. That instinct is wrong for any
filter whose cost is non-monotone in a parameter, and a sampled window is the
ordinary way to make it non-monotone. The endpoint here — 30 s, the largest
window the model permits — would have declared 0.557 s/MP, understating the
actual worst case by exactly 7x.
