# Dilation creates activity and diffusion conserves it

The prediction worth stating before the numbers is that this is a *conservation*
question and not a tuning one. Diffusion is the divergence of a flux: whatever
leaves a block arrives at its neighbours, so the field's integral is fixed by
the source alone and any width bought comes out of the peak. A grayscale
dilation is a maximum, and a maximum has no conservation law at all — a block
adjacent to a driven one is set to `kappa` times the driven value without the
driven block giving anything up. Both operators "spread activity"; only one of
them is moving it.

The measurement's job was to say how much that costs at the parameter values a
user would actually reach for, and the answer is that it costs everything. At
`reach_blocks = 4` — four blocks, which at the default 64-source-pixel block is
a fifth of a 1080p frame and an entirely ordinary thing to want — `diffuse`
leaves the peak at 6.6% of the input. A threshold set at four deviations with
coupling off does not fire at all with `diffuse` on, and the user's mental model
says they widened something.

The generalizable part is about which knob a parameter turns. `reach_blocks` is
declared as a width, and in `dilate` that is all it is: the peak is invariant at
every value tested, so the threshold set before touching it is still the
threshold after. In `diffuse` it is a width *and* a gain, and a parameter that
silently moves the quantity being thresholded is the same failure
`temporal_baseline` exists to remove one level up — a number that means
something different in a second setting. That is a stronger argument for
defaulting to `dilate` than the one REFINED-VISION made from the shape of the
operator, and it is the one to cite if the default is ever revisited.
