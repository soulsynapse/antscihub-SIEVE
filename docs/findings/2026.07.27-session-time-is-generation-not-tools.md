# Session time is generation, not tools

The prior this was built to test: repeated full-gate runs dominate session
wall-clock, so an incremental gate is the highest-value tool. The measurement
inverts it. All 301 nox invocations plus 397 direct pytest/pyright/ruff calls
together executed for 1.6 h across three days, and no single `nox -s checks`
run exceeded 36 s. The suite is small, unit-heavy, and benchmark-disabled at
check time; it is already the fast loop the scoped gate was meant to create.

What a faster gate could never have bought back is the 19.4 h of residual —
time between a tool result landing and the next tool call, which is model
thinking and generation plus sub-10-minute user reading. That is where writing
code, writing tests, writing docs prose, and conversing actually live. The
tools that help are therefore the ones that remove *generated* ceremony: a
scaffolder that emits the completed-todo frontmatter and file lists nobody
should type, and a primer that replaces the three-file orientation read at
session start.

A number that would flip this: if the suite grows past the point where
`checks` takes minutes (GUI and integration tests are the growth risk), the
scoped gate becomes live again. The distribution above is the baseline to
compare against; `tools/transcript_stats.py` re-measures it in one command.
