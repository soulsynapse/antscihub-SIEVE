# Of the free block measures, only two are not already on screen

## Why the redundancy test is the one that binds

The parent item pre-stated a two-prong gate: a measure earns a `Signal` entry
only if it separates events *and* is not explained by the existing three.
Only the second prong is fully computable without a person at the keyboard,
and it is also the prong that does the killing — a measure the existing three
predict is worthless no matter how well it separates, because whatever it
separates is already on screen. So the screening was built around it and the
separation numbers are read only where redundancy leaves room for them.

That asymmetry matters for reading the table. `trace` has a frame contrast of
+2.36, which in isolation looks like a strong detector. It is change_energy's
+2.44 with rounding. The contrast column is only informative for a row whose
redundancy column is low.

## What would have had to be true for a candidate to survive

A measure that carried something new would show a low R² on the three *and* a
low per-block temporal correlation — the second is the stricter test, because
two measures can share a spatial layout (both light up where the ants are)
while their time courses within a block diverge. `texture` is exactly that
shape: 0.66 correlated with change_energy overall, but only 0.27 block by
block over time. It is not redundant in the way the aggregate number claims;
it is redundant in the sense that matters here, which is that it never moves
when an event happens (d = +0.48).

`flow_agreement` is the opposite shape and is the reason the item was worth
running. Its aggregate R² is 0.08 — the lowest of any candidate that also
separates — its per-block temporal correlation with change_energy is 0.23,
and its frame contrast is +1.61, which is flow_speed's +1.56. It responds to
the same events the existing signals do while being nearly uncorrelated with
how they respond.

## The prediction that was wrong

The item pre-stated agreement as "the likely redundancy casualty" against
coherence, on the argument that both ask whether one translation explains the
block. Its rank correlation with coherence is 0.09 at block=2 and 0.09 at
block=16, and its per-block temporal correlation with coherence is 0.16. The
two questions are only the same question in the abstract: coherence weighs
*all* change in the block against a single translation, agreement weighs only
the change that resolved into a flow vector at all. A block that is half
featureless floor is, to the eigensolve, a block whose change is poorly
explained; to agreement it is a block in which everything measurable moved
together. Those disagree constantly on real footage.

Recording this because a pre-stated prediction that fails is the only kind
worth writing down. The item also predicted texture-vs-change_energy as a
casualty, and that one held.

## A negative result about coherence, noticed in passing

Coherence's frame contrast is *negative* — −0.44 at block=16, −0.73 at
block=2. Frames with the most change energy are frames whose blocks are
*less* coherent, not more. This is consistent with the filter's own markdown
("a nearly static block with a whisper of sensor noise can legitimately read
high") and it sharpens the working rule stated there: coherence is not merely
useless alone, it is anti-correlated with activity alone, and gating it
against change_energy is not a refinement but a precondition.

## The two variants of agreement, and why the choice was made on principle

The resultant can be normalised by the block's pixel count or by the count of
pixels that actually resolved a flow. On this clip the two are
indistinguishable on every number measured. The shipped kernel takes the
second, because the first conflates two questions — *did the pixels agree*
and *how many pixels could be measured* — into one scalar, and a block that
is half unmeasurable would report "half of these pixels disagreed" about a
scene in which nothing disagreed with anything. That is rule 6, and it is
worth taking even when the data does not care.
