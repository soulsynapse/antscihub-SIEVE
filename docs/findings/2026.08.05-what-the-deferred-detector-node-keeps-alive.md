# What the deferred detector node keeps alive

## The subtree

`the-detector-node-is-centered` (deferred, high) is the `after:` of
`detector-state-dies` (open, normal), which is in turn the `after:` of
`rule-sixs-frontier-moves-into-the-contract` and
`the-band-handlers-are-one-shape-said-five-times`, and the judgement that makes
`the-wizard-lifecycle-leaves-filter-tab` a cheap slice. Four ranked items, none
of them about detection as such, all of them waiting on one protocol widening —
`a-kernel-that-sees-past-its-target`, which this finding's first draft
described as unproposed and which is now the top of the chain.

Three more edges are machine-checked rather than written down as items. The
`gui-computes-nothing` contract carries exactly three `ignore_imports` entries —
`chain_model`, `filter_tab`, and `scalogram_plot` reaching
`core.ops.wavelet` — and the contract's own comment says the list is the
rework's work list and only shrinks. All three are detection. So the shrink-only
list stops shrinking, at full length, for the duration.

## What the gate actually is

The Morlet transform is non-causal and sees both sides — of whatever series it
is handed. It is not a filter: `filters/` holds ten modules and none of them is
a wavelet, `morlet_power` lives in `core/ops/wavelet.py`, and `detect.py` calls
it. What hands it a series is the executor, which sizes a windowed span as
refined warmup plus the current frame, and `FrameSpan.target` is `frames[-1]`
by construction. So every frame the transform sees is behind the frame it is
answering for, and the two-sidedness that makes the wavelet the right
instrument is spent entirely on history.

Everything else the widening needs already exists and is measured. That is why
this is a ranked item rather than a research question, and why the honest cost
is a latency number rather than an unknown.

## The exception that stops being transitional

After the flip the graph decides the crop and the span, and `Project.detector`
is the last field that decides a *result* from outside it. That is rule 1 and
rule 2's exception, and its whole justification has been that it is on its way
out. A gate that is an unwritten item is not a way out; it is the exception
becoming the design. `detect_series`, `settled_for`, `gate_to` and
`to_settings`/`from_settings` — the compatibility surface `filters/detect.py`
keeps precisely so that the GUI and `sieve detect --csv` agree with each other
rather than with the executor — are load-bearing for as long as that lasts, and
so is `sieve detect` as a command distinct from `sieve run`.

There is a cache consequence nobody has had to state yet: results the executor
computes are keyed and reused, and detection is not computed by the executor, so
the tuning loop for the one parameter set a user cares most about is served by a
bespoke worker rather than by the thing the whole cache exists for.

## The instrument problem, which is the part that does not resolve itself

The crop and span migrations were proven by rendering a checked-in v5 fixture
both ways and diffing pixels — `tests/integration/test_upgrade_run.py`. That
technique is not available for the detector, and not for want of effort: the
migration *changes the numbers on purpose*. A trailing kernel and a centered
whole-record derivation disagree, which is the entire reason
`detection-is-a-filter` refuses to substitute one for the other. An equivalence
test would fail by construction, and a test written to pass anyway would be a
test written around the failure it exists to find.

So whenever the detect node lands, it lands on an argument rather than on a
diff, and the argument has to be about *how much* the claimed intervals move and
*where* — first half-window, last half-window, or throughout. That is a
characterization: same footage, same params, `detect_series` against a
span-walked `detect_cpu`, intervals diffed as intervals. It needs no protocol
change, no schema change, and no item to be unblocked, and until it exists the
deferral is being justified by a disagreement whose size nobody has measured.

The scientific stake is why the gate is right rather than cautious. A saved
project is the reproducible unit, and the output is a published event table. If
the upgrade to a detect node changes which intervals a document claims, then an
upgrade silently restates a result — which is rule 6 at the level of the whole
artifact rather than of a widget. Either the centered semantics survive the move
(the look-ahead kernel), or the move is a declared change to what the project
claims and has to be presented as one. What is not available is upgrading
quietly.
