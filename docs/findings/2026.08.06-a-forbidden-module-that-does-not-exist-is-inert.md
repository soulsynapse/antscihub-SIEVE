# A forbidden module that does not exist yet is silently inert

This narrows [2026.08.06-every-contract-goes-red-on-one-line.md](2026.08.06-every-contract-goes-red-on-one-line.md),
whose verdict — contracts over empty packages are not vacuously true — was
established one edge per contract. It holds for the edges tested. It does not
hold for `sieve.core.ops`, the one forbidden entry in the file that names a
module rather than a package that exists, and that entry was not among the five
probed.

The distinction that matters is between an *empty* package and an *absent* one.
Empty packages are fine: `sieve.tools` has nothing in it and
`gui -> sieve.tools` is caught, because grimp builds the graph from directory
structure, not from contents. Absent packages are the hole — there is no node
to match, so the contract reports success.

What a passing result would have looked like: import-linter emitting a warning,
or a non-zero exit, for a forbidden module absent from the graph. It emits
neither, at either alerting setting available.
