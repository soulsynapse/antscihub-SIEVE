# Block-size retention does not pay for its share

The tempting fix is the v1-shaped one: keep the pixel-resolution planes that
`block_signal` already blurred, then a block-size edit reduces those planes onto
the new grid instead of re-running the extraction. The v1 warning matters here,
but the first question is whether v2 has the same failure.

It does not on the measured path. The first render decodes one lead-in frame
plus the 300-frame window and writes the cacheable `rescale` and `normalize`
outputs. A later block edit changes `block_signal.block`, whose node is
stateful and therefore has no cache key. The executor still serves the two
upstream nodes from the store, so no source frame is read. The remaining cost is
the stateful block-signal pass over already-held upstream frames plus detector
derivation over the new block grid.

The hypothetical retained-plane path is much faster on the narrow operation:
the block-16 edit drops from 0.743 s to 0.155 s when the blurred
`change_energy` plane is already held. But this saves about 0.59 s on a path
that is already comfortably under the 3 s complete-render budget. The memory
price is the harder result: at 630x846, one 300-frame float32 plane is
639,576,000 bytes. The render-ring-style 1% share on this machine is
641,288,355 bytes, so one additional frame would exceed it. That comparison
also excludes the preview store already holding two upstream frame series.

The measured case is the default `change_energy` signal. It is the friendliest
case for retention because it needs one blurred plane. The flow/coherence tier
would need five or six blurred product planes if the store is literally a
blurred-product store, and those fit only 50-60 frames at the measured
geometry. A different design that retained final speed or coherence planes
would be a different cache and needs a separate measurement; it is not the
blurred-plane proposal evaluated here.

So the item closes negative. A retained plane store would need a new declared
machine-relative share and a visible fallback path, because a control promising
re-reduction and quietly recomputing extraction is the v1 failure in another
shape. The current measurement says not to add that surface.
