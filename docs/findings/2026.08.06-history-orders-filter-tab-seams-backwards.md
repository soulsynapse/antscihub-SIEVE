# History orders filter_tab seams backwards

The retired item was useful, but it was not a todo. It named six secrets in
`filter_tab.py`, measured some of their history, and then explicitly said it
was staying open as a record. That made `docs/todo/` carry an item nobody could
take. The record belongs here because the claim is durable even after the file
that triggered it changes shape.

The claim is narrower than "split the tab". Reading the outline says the step
composite is the obvious seam and the source/crop boundary is a detail. Reading
the commit history says the reverse. That reversal has now been right twice:
the source boundary left as `gui/source_boundary.py`, while the composite was
struck from the extraction order.

## Current co-change

The live tree at 91d4456 changes the raw counts from the 2026-08-04 todo item.
Using `git log --no-merges --format=%H`, `filter_tab.py` has 44 commits.

| candidate | candidate commits | co-change with `filter_tab.py` | `filter_tab.py` without candidate | candidate without `filter_tab.py` |
|---|---:|---:|---:|---:|
| `composite_view.py` | 11 | 9 | 35 | 2 |
| `wizard.py`/`wizard_model.py` | 9 | 9 | 35 | 0 |
| `materialize_worker.py`/`crop_binding.py` | 5 | 5 | 39 | 0 |

The table does not prove the source boundary by itself; pairwise file history
can only measure seams that already have files. It does keep the composite from
coming back as an obvious split: the composite file still mostly changes with
the tab, not beside it.

## Blame containment

Current `filter_tab.py` blame has to be read with care because the source
boundary has already shipped out of the file. At HEAD, `filter_tab.py` is 2,202
lines with 15 section buckets and 39 commits carrying surviving lines. The
founding composite commit, `c5b0300` ("Draw the step composite..."), is still
only 66% inside `the step composite`.

For the source boundary, the comparable measurement is the replay at
`5f4905b^`, just before the extraction commit. In that tree,
`7ffed9f` ("The source boundary gets a card...") is 82% inside
`the source boundary`, and `4ff1c15` ("The crop stops holding things still...")
is 92%. `c94dd95` moved Qt-free logic and is only 69%, so it should not be
counted as source-boundary containment evidence on the current replay. The
exact percentage drifted with surviving lines and section boundaries; the
ordering did not.

After `5f4905b`, `source_boundary.py` is a 306-line controller introduced by
one commit. Its own blame is 100% in one bucket only because the new file has
no section markers, so the meaningful evidence is the pre-extraction replay
plus the shipped seam: a controller over the document and source card, with no
back-reference to the tab and three crossing signals.

## What still has no owner

Knob-edit routing through the document still has no item of its own:
`_submit_params` and `_submit_detector` decide per edit whether the node is in
the document pipeline, using a document command when it is and a local chain
rewrite when the edit is provisional or no pipeline is open.

Chain structure edits as document-routed macros still have no item of their
own: remove and reset collapse multiple document writes into one undo entry,
and reset deliberately means "parameters, not structure."

The other four secrets are already owned elsewhere: the source boundary by
`docs/completed-todo/2026.08.05-the-source-boundary-is-its-own-object.md`, the
band handlers by
`docs/todo/the-band-handlers-are-one-shape-said-five-times.md`, and the wizard
plus composite ordering by `docs/todo/filter-tab-is-eleven-jobs.md`.
