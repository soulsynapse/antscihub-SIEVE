# Ragged block mean costs like divisible geometry

The v1 note matters more after the v2 crop moved into the filter graph. A
non-divisible working plane is now an ordinary output of a crop, not an unusual
tile shape, and `block_signal` calls `_block_mean` repeatedly: once for
`change_energy`, once for `flow_speed`, six times for `coherence`, and three
times for `flow_agreement`.

The previous v2 implementation got the edge semantics right by padding to the
ceil-divided grid with NaN and using `nanmean`. That preserved
`include_partial=True`: an edge block was averaged over the pixels it actually
covered. It also allocated the padded plane and then a `(ny, nx, block*block)`
cell copy before reduction.

The slab route uses the geometry v1 recorded. The fully covered core reduces
as a reshape view. If height is ragged, the bottom strip is one array whose
cells all share the same short height. If width is ragged, the right strip is
one array whose cells all share the same short width. If both are ragged, the
corner is the single remaining cell. There is no per-cell loop and no padded
plane on the finite hot path.

The output is not bit-identical for finite fields because the fast route and
the padded route sum in a different order. The measured maximum on the timed
730x1300 field is `3.0517578125e-05`. That is the cost of removing the
temporaries; NaN-bearing input still routes through the old `nanmean` path
because skip-NaN behavior is a semantic, not an optimization detail.
