# The rest of the overnight batch, and the gate that compares a run to itself

The first audit named the class as *machinery that is written and tested but
that nothing in the running system reaches*, and found it in a parameter
(`lowering.protected_nodes`), a sampler (rescale cost dropping `reuse`), and a
duplicated derivation (lowering's geometry). The nine remaining items extend it
in one direction worth stating on its own: **the unreachable thing can be the
check.**

`tests/property/test_filter_settling.py` is the gate the `warmup-is-derived-not-declared`
item built to make R3's settling claim answer to data rather than to a
docstring sentence. It runs every discovered filter from two origins and
asserts the outputs agree after the declared warmup. For the nine streaming
filters it does exactly that — lowering `background_ema`'s warmup to two frames
makes it fail at the `allclose` line, which is what a gate is for.

For `detect` it did nothing, twice over, and the two failures are independent.

The first is arithmetic. The windowed branch clamped its span to the declared
window: `first = max(start, target - window + 1)`, with `window = warmup + 1`
and `target = later_start + warmup + extra`. Substituting, `target - window + 1`
is `later_start + extra`, which is at least `later_start` for every value
Hypothesis generates — so both origins resolved to the same first frame and the
"two-origin" comparison had one origin in it. The assertion compared a run to
itself and could not have failed.

The second is the array. `detect`'s kernel publishes `FrameSpan.target`, which
is the span's *last* frame, and a trailing detector cannot settle its last
frame — so it returns NaN. Not sometimes: at 248, 494, 741, 1000, and 2000
frames of history, the published value is NaN. And the assertion passes
`equal_nan=True`, under which two all-NaN arrays are close to each other. Had
the clamp been fixed and nothing else, the gate would still have passed.

Both fixes are in. The clamp is gone, so the frame-zero run now carries real
extra history; the gate asserts there is a non-NaN value before asserting
agreement; and `detect` moves into `WITHOUT_SETTLING_PRODUCER` with its reason
and the item that empties it
(`docs/todo/the-detect-kernel-publishes-an-unsettled-sample.md`) named beside
it. That list is the construction the tree already uses for `WITHOUT_PRODUCER`
and `WITHOUT_SENSOR`, and the item's own `settled` row had already prescribed
it — "discovered filters either pass the two-origin probe or enter the
shrink-only unverified set." What was missing was any way for a filter to
*fail* to be probeable for a reason a structural predicate cannot see.

## The declaration that was true when it was written

Two of the mutual-tier findings are the same shape a commit apart. `.importlinter`
still listed `(sieve.mutual)` in parentheses, which the file's own header
defines as a layer "declared before they exist"; the commit that created
`src/sieve/mutual/` did not drop them, though `sieve.storage` had set the
precedent eleven days earlier. Injecting a violation shows the layer is
enforced anyway, so this was a false declaration rather than an absent check —
which is the milder half, and still exactly the thing `SCAFFOLD.md` has a
paragraph about.

`core/ops/wavelet.py` is the sharper one. Before the move its docstring said
`core.machine.available_cpus` "is importable from here now that the machine
reading lives in `core/`" — true, and the point was that the module declines to
take it anyway. The move rewrote the sentence to say the reading "lives below
this module", which inverts the fact: `mutual` sits *above* `core`, and the
layers contract refuses the import outright. A sed-shaped retarget of every
mention of a moved module is how a comment ends up asserting the opposite of
what the same commit made true.

## The anchor that was a number without a denominator

`work-units-have-one-anchor` replaced eight per-filter `seconds_per_megapixel`
constants with `WorkUnits` denominated against `WORK_UNIT_ANCHOR`, which is the
right move and is what stops a reference CPU living in a filter spec. The
anchor it named was "copy one full frame at the reference resolution", and the
field it denominates is `work_per_megapixel`.

Those are different dimensions. `crop` declares `WorkUnits(1.0)` and its own
comment says why — "a non-identity crop is one contiguous copy of the retained
pixels" — which is one *megapixel* of copying per megapixel of input. Read
against the anchor as written, the same number says a crop costs one whole
5312x2988 frame-copy for every megapixel it passes, sixteen times the truth on
the reference source. Nothing consumes it yet, which is why nothing broke; the
consumer is `docs/todo/a-number-says-how-it-was-founded.md`, whose whole job is
to divide by this anchor on a target profile. It is now "copy one megapixel of
a frame", every declared number is unchanged and correct against it, and the
undefined "reference resolution" — a phrase that appears nowhere else in the
tree — is gone.

## What is left, and why it is not an edit

Six questions are recorded above rather than fixed, and they divide into two
kinds. Three are placement decisions somebody has to make: whether a
verification tolerance belongs on `FilterSpec` at all, whether `read()` takes
positions or integers, whether the NaN fallback in `block_signal` is a
preserved semantic or a dead branch. Three are gaps that are honest but wide:
`CostEstimate` maintained by nine filters for one CLI subcommand, a preference
boundary asserted over a filter that does not ship, and a plan that raises
where it should refuse by name.

The seventh is the architecture item this audit was pointed at, and it is
written: `docs/todo/a-filter-declares-the-extents-it-emits.md`. The short
version is that `lowering.py` enumerates filters because the outside has no
typed way to ask a filter what extents it emits, and the three `cast(Any, ...)`
in that file are the same absence seen by the type checker. The nearest
existing declaration, `frame_bytes_ratio`, structurally cannot answer — a ratio
takes no input, and `crop.py:94` already says so in the course of explaining
why crop declines to override it.
