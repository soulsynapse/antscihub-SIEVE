# The scaffold's 72-column annotation does not fit a ported module

`ANNOTATION_LIMIT = 72` and the rule that the docstring's first line *is* the
scaffold annotation were both written when v3 had no modules — so they were
written against annotations authored for the column. Every module the plan
ports had its summary authored against something else: ruff's 100-column line,
with the freedom to wrap. Those are two different specifications for the same
line of text, and the first ported module is where they meet.

The distribution is what makes this a decision rather than an adjustment. If
the overshoot were a tail — two files at 90 — raising the limit would be
bookkeeping. Instead 42 of the 46 sit between 73 and 78, which is what a
population written to a *different* limit looks like: there is no number that
both clears v2's summaries and bounds the column, because 66 is what the
100-column budget actually allows and the summaries cluster ten characters
above it.

The wrapped-fragment cases are the independent half, and they would survive
raising the limit to any value. `decode/reader.py`'s docstring opens *"OpenCV
`VideoCapture` wrapper trading grab-vs-seek and BGR-vs-luma for"* — 70
characters, under the limit, and not a sentence. Ported verbatim in Phase 2, it
puts that fragment in SCAFFOLD.md as the statement of what the module owns. The
generator has no way to notice, because the check it runs is a length check.

The blast radius is worth naming separately from the rule, because it is what
turned a red test into a stopped item. `collect_modules` raises during
collection, before `doc_index.py` writes any of the four derived files, so a
single over-limit docstring takes `todo/.index.md`, `findings/.index.md` and
ARCHITECTURE.md down with SCAFFOLD.md. The indexes are the loop's own read of
what is open, so an item cannot record its own blocker in the same tree as the
module that blocked it. Whether the generator should degrade — write what it
can, fail the one file — is a separate question from which annotation rule is
right, and answering only the second leaves this coupling in place for the next
module that trips any other check.

What would have made this a non-finding: v2 summaries clustering under 66 with
a handful of outliers, and no module whose summary wraps. Neither holds.
