# 05.1's case count is v2's file count, and two of those cases are the command

The count and the scope sentence in 05.1 disagree, and the disagreement is
readable from v2 alone: 8 is what `wc` says about a file whose last two cases
invoke a CLI, while "what is left here is the cutting and the verification pass"
excludes them. Nothing was weakened to resolve it — the file still holds 8 rows.
What changed is which 8, and the substitution is the honest one rather than the
convenient one: both replacements are claims v3's model makes and v2's did not,
so neither is padding to reach a number.

The reason this is worth a file rather than a sentence in a commit message is
the second measurement. It is easy to read "cli/ port-with-rename" in PLAN.md
and assume the materialize command is a transcription waiting for a session to
type it. It is not. v2's command reads a `ClipRange` off the project and an
`roi` off the replicate; schema v1 has neither, by decisions Phase 2 and
`adr/detector-is-a-node.md` already made. Whoever takes that item is deriving a
region from a crop node's per-replicate override and a span from the `span`
tool's parameters, and finding out mid-session that the port has no source to
port from is exactly the shape of surprise the plan exists to prevent.
