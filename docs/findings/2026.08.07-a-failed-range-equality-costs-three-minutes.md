# A failed `range == range` at ALL_FRAMES' size costs three minutes

The cost is not in comparing the ranges — `range.__eq__` is O(1), and the
comparison that *succeeds* is free. It is in what pytest does afterwards: an
unequal comparison of two objects it recognises as sequences gets an explainer
that iterates both to report the first differing element and the extra items.
`ALL_FRAMES` is `range(4294967296)`.

The failure mode this creates is worse than slowness. The run produces no output
while it iterates, so a wrong default — which is precisely what the assertion
exists to catch — presents as a test suite that has hung, and the natural
response to a hang is to interrupt it, which discards the diagnosis. A gate is
only as good as the report it produces on the day it fires.

What would have to be true for the fix to be wrong: if `range` equality ever
meant something the three-tuple does not capture. It does not — two `range`s are
equal when they are the same sequence, and for step 1 that is exactly the pair of
bounds. The second assertion is kept anyway, because it is the claim being made
and the first is only there to reach it cheaply.
