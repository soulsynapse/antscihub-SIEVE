# An inert forbidden entry can be proven red against a copy of the tree

The copy is sound because `lint_imports` puts the working directory on
`sys.path` and reads its config from the working directory, and grimp builds
the graph by parsing files rather than importing them. Nothing in the run
consults the installed `sieve` distribution, so a top-level `sieve/` beside a
`.importlinter` in a temp directory is the same subject the real invocation
has. The control probe is what makes that claim checkable rather than
argued: the copy is linted clean before the violation is planted, so a
non-zero exit afterwards cannot be a config the copy broke.

What would have refuted this: the clean copy reporting a different contract
count or a different verdict from the real tree, or the planted violation
naming a contract other than the one under test. Neither happened; the copy's
`6 kept, 0 broken` is character-for-character the real run's.

The encoding probe is the one trap worth carrying forward. A test that runs
the linter in a child and asserts only on the exit code will pass on Windows
while its reader thread has died and its captured output is empty — the
failure surfaces as a `PytestUnhandledThreadExceptionWarning` next to a green
test, which is exactly the shape nobody reads. Decoding as UTF-8 explicitly is
the fix, and asserting on the report's text rather than on the exit code alone
is what makes the omission visible.
