# detect's two window bounds are the same number

The commit that landed 04.8 also landed
`findings/2026.08.07-v2s-settling-frontier-ships-at-half-its-own-measurement.md`,
which convicts v2 of exactly this shape one level down: a bound whose test
computes its expectation from the constant it is checking, so the assertion
holds at any value. `test_the_bounds_are_reached_only_at_the_corner_and_every_run_refines_them`
asserts `corner.warmup_frames() == SPEC.warmup_frames == FrameCount(MAX_WARMUP_FRAMES)`.
Both sides of that chain reduce to `max(599, 1972)`. Move the 599 and every
term of it and the case is still green — which is why the sweep's six survivors
sit there.

The rest of the 89 split three ways and only the middle group is worth work.
About forty are equivalent mutants that cannot change an answer: the
`workers == 1 or len(starts) < 2` fast path exists precisely because both
branches produce the same array (`test_the_thread_count_cannot_move_a_bit` is
the case that says so), `overwrite_x` and the inner FFT `workers=1` are
wall-clock choices, and `out[:, 0]` and `out[:, -1]` are the same column when
the squeeze path guarantees one. About twenty-five are default values and range
bounds — `MAX_WINDOW_FRAMES`, `MAX_FPS`, `default_freqs`' `fmax`, `block_chunk`,
the two `Field` defaults — which are policy numbers nothing but a table can
pin, and the table is `docs/todo/a-tools-declaration-is-asserted-by-nothing.md`.

What is left is the middle group: the empty-band snap that exists twice and is
tested once, a validator with no case at all, band-edge inclusivity pinned on
one side of one comparison, and an edge clamp whose fixture is flat exactly
where the clamp acts. Three of those four are v2's gaps carried across intact —
the same shape 04.5's review found and named — but `_ordered` is v3's own code,
written in this commit, and it arrived with nothing that reads it.
