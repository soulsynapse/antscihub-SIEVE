# Every tool landed in one src file, and none of them took a row

The strict reading of ADR-7 has been false since the first tool: `downsample`
landed with two goldens and a test file beside its module. The reading that is
true of all nine landings is narrower and stronger — no tool has ever had to
open a file another tool opens.

That is the property `filter_tab.py` violated, and reading its 2,321 lines as
"a second file" undersells it. It was bad because every v2 filter had to enter
it to be usable, so it accreted eleven jobs, became the merge point, and made
each new filter pay for every filter before it. A golden array only its own
test loads imposes none of that: nothing serializes on it, and no one else can
be broken by it.

The distinction the record actually draws is between a file that grows *more
capable once* and one that grows *per tool*. `SCAFFOLD.md` is the first kind by
construction — it lists every module in the repo and is edited by nobody,
because `doc_index.py` derives each line from the module's own docstring. The
tool states its own fact, in its own file, and the shared artifact follows.
Where a shared file must exist, that is the shape available, and it is why a
row-per-tool table is a choice rather than a necessity.

What would flip this: a tool that cannot be written without editing a file
another tool edits, where the edit is not extending a closed vocabulary. None
of the ten is that, and the two-input tool schema v1 cannot express is the
nearest candidate — it is a vocabulary extension, which is the licensed case
rather than the counterexample.
