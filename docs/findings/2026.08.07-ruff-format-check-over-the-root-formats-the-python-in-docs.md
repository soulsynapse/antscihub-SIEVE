# The gate's `ruff format --check .` reaches the Python inside every document

The number was on screen in the run that shipped this and was read as a Python
file count. That is the whole mechanism: `ruff format` prints one summary line,
the summary is a file count with no breakdown, and a repo whose documentation
outweighs its code by two to one produces a number that looks like a large
Python tree rather than a small one plus a library of Markdown. Nothing in the
command's output names a directory, so the only way to see the scope is to ask
for it.

What would refute the framing here is a ruff configuration that already
excludes Markdown — there is none: `[tool.ruff]` in `pyproject.toml` sets
`line-length` and `target-version` and nothing about `include`, `extend-include`
or `exclude`, so the default file discovery is what runs.

The reason this is worth a finding rather than a line in the item is that the
green is load-bearing in the wrong direction. A gate that is green because the
condition it would fail on has never yet occurred is indistinguishable from a
gate that is green because the tree is correct, and this one will first go red
in a commit that touches no code at all — the shape hardest to attribute to the
change that caused it, twenty commits back.
