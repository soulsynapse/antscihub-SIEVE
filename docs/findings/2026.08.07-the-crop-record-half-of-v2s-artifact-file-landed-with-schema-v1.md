# The crop record half of v2's artifact file landed with schema v1

The collision looked like two items wanting one filename, and 04.1 minted it
that way. It was not. Once the nine cases are read against v3's tree rather
than against v2's, seven of them are green today and were green before 04.1
started — the record model came over with 02.1 and brought its own tests. Only
the filename was ever contested; the work behind the count had already been
done under a different name.

What would have made this a real conflict: a v2 case whose subject v3's
`CropRecord` carries but whose claim nothing asserts. There is exactly one —
that a record survives its file being renamed — and it is one case in the file
that already owns `backs`, not nine in a file that does not exist.
