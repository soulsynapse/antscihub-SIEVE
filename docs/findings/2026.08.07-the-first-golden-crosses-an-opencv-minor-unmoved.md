# The first golden crosses an OpenCV minor unmoved

The prediction that would have refuted this: v2's 4.13.0 and v3's 4.14.0
disagreeing anywhere in the 325 values of the area golden, by any amount. A
single count would have been enough, because it would have meant the parity gate
was measuring the OpenCV pin rather than the port, and every Phase-4 item after
this one would have had to open with a tolerance argument.

The input was chosen so that a disagreement had somewhere to come from. A factor
that divides both extents reduces INTER_AREA to a block mean, which is exact
integer arithmetic and would have agreed for reasons that say nothing about the
interpolator; 101 columns into 25 puts partial source pixels on both sides of
every output column, which is where an implementation change would show. The
stride path is in the goldens as the control: it is pure indexing and could not
have disagreed, so its agreement is what confirms the area case's agreement is
about the resample and not about the harness.

What this does *not* license is treating goldens as version-independent. The
`opencv-python-headless>=4.10,<5` pin exists because `decoder_identity()` puts
the OpenCV version into the cache key, so a major bump already changes what every
cached result means; this finding is scoped under that pin and expires with it.
