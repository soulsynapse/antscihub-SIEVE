# The gate-line walk catches one of the two drifts the item cites

The walk is not vacuous. It is red on a real drifted copy, it names both lines
when it fires, and the companion case beside it pins the shape rather than
asserting an empty set. What it is, is narrower than the evidence it was built
from — and the narrowing is not visible from the test, because the worker note
states the evidence as uniform when it is not.

Both drifts were commands *added to the line* and not to the copy. That much is
true and it is what the item says. Where they differ is where the added command
landed. `actionlint` went on the end, so the stale copy is the line's prefix.
`ruff format --check` went second, so the stale copy has a hole in the middle
and shares only its first command with the line as a prefix. A rule keyed on
prefixes sees the first shape and not the second, and which shape a future
drift takes is decided by where the next command is appended — which is a fact
about the gate line's growth, not about the copy.

The reason this does not have an obvious fix is the neighbour. Widening the
rule to "the copy's commands appear in the line, in order" catches episode 1
and simultaneously flags `the-gate-has-no-opinion-about-the-workflow.md`, whose
`done_when` is the same three commands for an unrelated reason: it is checked
by them, it does not restate anything, and it was written before
`ruff format --check` joined the gate at all. The two strings are equal. ADR 19
draws its line on a semantic — *something requires this to stay identical* —
and that requirement lives in an item's prose, where no walk reads it. The
prefix rule is what is left when a walk has to guess the semantic from the
string, and the honest statement of its coverage is that it catches a copy that
falls behind an appended command and not one that falls behind an inserted one.

What would flip this: a marker in an item's front matter saying its `done_when`
is meant to be the gate line, at which point the walk reads the requirement
instead of inferring it and can demand exact equality. That is a second
enumeration in the sense ADR 19 refuses — but only one that has to be
*maintained*; a boolean does not drift the way a command list does. Whether
that distinction is real enough to build on is the open question, and it is
Kendrick's, not a worker's.
