# The goal with no gate is the one going backwards

VISION's five features each got a checkable form except this one. A tool is one
file (`adr/a-tool-is-one-file.md`), the GUI knows kinds and never tools
(`adr/gui-knows-kinds-not-tools.md`), crop is a contract, detect is a node —
each names a mechanism. Feature 3 named a quantity and no mechanism, and it is
the one that moved the wrong way.

The obvious defence is that v3's ported subset is contract-heavy: `tool_base`,
`pipeline_model`, `dag` and `cache_key` are exactly the modules where the
docstring *is* the interface spec, and the tools and decode modules that would
dilute them are a smaller share of 51 files than of 124. That defence survives
the aggregate and dies on the matched pairs. Two re-derivations came out
proportionally wordier than the v2 files they replaced while being shorter in
absolute lines — which is the signature of prose surviving a rewrite that the
code did not.

`core/types.py` is the control worth keeping in view: a verbatim port, 625
lines and 47% on both sides. Ports do not move this number in either direction,
by construction, which is why the porting discipline exempts them and why the
number is a fact about what v3 *wrote*, not about what it copied.

What would flip the conclusion: the fraction falling below v2's on a like-for-
like set of re-derived modules, or a demonstration that the matched-pair
direction is an artifact of which four files were compared. The five pairs
above were chosen as every module with a direct v2 counterpart at the time of
measurement, not selected on their fractions.
