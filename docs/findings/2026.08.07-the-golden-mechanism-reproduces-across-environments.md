# The golden mechanism reproduces across environments, and its reach is the fixture's

The reason to write this down is that the two halves point opposite ways and
both are true of the same three files. The mechanism half is a strong result:
`REGENERATE` is a string in a docstring, with no gate running it, and it still
reproduced three arrays byte-for-byte in another session's hands a day later.
That is the whole claim of the convention 03.7 minted, and it had never been
tested by anyone but the session that wrote it. The `git diff --quiet` prefix
is what makes it a statement about v2's `main` rather than about whatever is
sitting in the sibling worktree, and it earned its place — the worktree does
carry uncommitted work at times, and the check passed here only because it did
not on these three files.

The coverage half is the caution. Byte-identity is a very strong assertion
about one array and says nothing about the parameter space around it. The
rescale golden is a 101x53 frame at scale 0.25; every mutant that changes what
happens *at that frame* dies, and truncation instead of rounding does not
change what happens at that frame, so it lives. There is a temptation, once a
golden exists, to read it as covering the tool — the file is opaque, the
comparison is exact equality, and both of those feel total. They are total
about one point.

What would have refuted the mechanism half: any of the three arrays differing
in a single byte, which would have meant either v2 moved under the golden or
the golden was never v2's. What would refute the caution: a fixture whose
scaled extents landed above the half on either axis, which would have made the
same golden carry the rounding too. That is one number in one call, and it is
what 04.3 was reopened to add.
