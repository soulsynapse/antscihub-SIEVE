# The Morlet golden crosses a scipy minor and a numpy minor unmoved

This is the first golden in v3 whose value passes through a library other than
numpy and OpenCV, and the question was live: an FFT is the sort of routine that
picks kernels by transform length and by CPU feature, and a minor release that
changed a threshold would move the last bits of a float32 result without
changing anything anyone would call behaviour. It did not, over a gap of one
minor in each of the two libraries involved — which is what lets the parity case
say `array_equal` rather than `allclose(rtol=...)`, and the difference matters
because a tolerance wide enough to absorb an unknown is also wide enough to
absorb a wrong scale normalization.

What this does not establish is portability across machines. The transform
length here is `next_fast_len(256 + 247)` = 504, the same on both sides, and both runs
were on one host — so what was crossed is a library version, not a
microarchitecture. If CI ever runs this case on other hardware, that is the
measurement to make before assuming the equality survives.
