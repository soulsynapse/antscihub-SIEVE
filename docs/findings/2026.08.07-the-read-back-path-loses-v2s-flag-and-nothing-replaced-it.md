# The read-back path loses v2's pre-cropped flag, and nothing replaced it

The dividend of the child-source model is real and 05.2 collects it: `plan.py`,
`executor.py` and `cache_key.py` are untouched by the read-back path, where v2
threaded a flag and a frame floor through all three. What the model does not do
is dissolve the question the flag answered. It relocates it — out of the plan,
where a field could carry it, and into the graph, where only a caller holding the
crop node's id can act on it.

That relocation is easy to read as a removal, and the tell that it is not is
`tools/crop.py`'s `WHOLE_FRAME`: the identity crop exists as a *value* precisely
so that "no crop" is expressible as a parameter rather than as an absence. A
served run wants that value at exactly one node, and 05.2's contract stops one
step short of naming it.

The reason this is a finding rather than a line in the item is the second
measurement. `test_crop_serving.py` passes frame for frame against a
parent-served run, which is the strongest claim in the file, and it passes
*because the test performs the substitution itself*. A later session reading a
green integration suite would reasonably conclude the read-back path is closed.
It is not: it is closed to the point where a caller takes over, and no caller
exists.
