# The rename gate does not survive borrowed vocabulary

The gate was built on a claim that reads as obviously true — v3 imports no v2
file, so nothing in `src/sieve/` has a licensed reason to spell v2's
vocabulary — and the claim is still true. What it missed is that the words v2
renamed are not v2's words. `filter` is FFmpeg's name for a stage in `-vf` and
the ordinary English verb for dropping lines from a stream; `roi` is what every
imaging library calls a rectangle; `clip` is what a video is. The rename took
three common words out of circulation inside SIEVE and the gate then went
looking for them in files whose whole job is to speak to something outside
SIEVE.

The prediction this refutes is specific: the 02.2 pool item expected the first
collision to be `np.clip` in `rescale`/`normalize`, at 04.3, and expected the
question to be about array math. Had that been the shape, a word-boundary match
would have answered it, because `np.clip` and `clipped` differ from `clip` only
in what surrounds them. It is not the shape. `-filter_threads` and
`ffmpeg_roi` fail a word-boundary match too — they *contain* the dead word as a
morpheme — so the fix cannot be a matching rule alone. Something has to say
which vocabularies a file is allowed to speak, and `decode/` speaks two.

The single genuine hit is worth keeping in view rather than sweeping up with
the rest. `reader.py:135` calls a downscale "never a pipeline filter", which is
exactly what the gate exists to catch, in a file the plan says arrives
byte-identical.

## Amended by the review of 2026-08-07

This record shipped claiming that last line was a standoff between the gate and
the porting discipline, for Kendrick to break. It is not. PLAN.md's porting
discipline defines verbatim as identical modulo import paths *and* ADR-1's
renames, so the rename was licensed on that comment before the file was copied.
`core/types.py` is the case already decided that way: it sits in the same
verbatim list and its blob is *not* equal to v2's, because 01.5's gate renamed
six lines of its prose — including the two that spelt `Replicate.roi` and
`CropParams.roi`, which are the same `roi` row firing on the same kind of line.
Byte-identical was a stronger property than the discipline asks for, and on one
line it was the wrong one.

Nothing in the measurement changes: 27 of 28 are still borrowed vocabulary, the
matching rule still cannot reach them, and that is still what 03.2.1 has to
decide. Only the count of open questions drops from two to one.

## Amended again by 03.2.1: the count was wrong, and it was wrong in one direction

Reading the 27 line by line rather than by module, 16 of them are v2's word.
The error has a single shape: a dead spelling carried inside a compound whose
*other* half is foreign reads as foreign. `ffmpeg_roi` is not FFmpeg's name for
a rectangle, it is SIEVE's `roi` field with the consumer of the rectangle
prefixed onto it, and the same goes for `source_roi`, `roi_parts`, and the four
locals bound off them. `LoweredScale.filter_id` had no foreign half at all and
was still counted with the flags, on the strength of sitting in `decode/`.
Seventeen lines renamed, `reader.py:135` included — the sixteen plus the one
the amendment above had already licensed.

That leaves eleven, and they are the ones the shape had to be built for. Five
are tokens FFmpeg owns whole (`-filter_threads`, `-filter_complex_threads`, and
the `filtergraph` property named after what `-vf` takes), and a token goes in
the row, where it excuses one spelling and nothing else in the file. Six are
prose in a module whose subject is the foreign sense, and prose has no token to
strip: `quiet.py` says "filters it by line" about a byte stream and
`crop_writer.py` says "a whole clip" about a video, and nothing lexical
distinguishes either from `reader.py:135`'s "never a pipeline filter". Only a
declaration per `(module, word)` reaches those.

Both granularities are load-bearing and this file is the evidence for why.
`lowered.py` held FFmpeg's `filtergraph` and v2's `filter_id` on lines forty
apart; a module-wide waiver for `filter` there — the cheap single-table
answer — would have excused the flag and buried the field, which is the one
outcome the gate exists to prevent. The token table keeps `lowered.py` out of
the module table entirely.

The residue is bounded rather than trusted:
`test_every_declared_vocabulary_is_still_spoken` fails on a declaration that no
longer matches a line, so a module that stops speaking FFmpeg loses its waiver
in the same run rather than carrying it forward as a permanent exemption.
