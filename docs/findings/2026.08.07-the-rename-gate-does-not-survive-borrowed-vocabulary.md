# The rename gate does not survive borrowed vocabulary

The gate was built on a claim that reads as obviously true — v3 imports no v2
file, so nothing in `src/sieve/` has a licensed reason to spell v2's
vocabulary — and the claim is still true. What it missed is that the words v2
renamed are not v2's words. `filter` is FFmpeg's name for a stage in `-vf` and
the ordinary English verb for dropping lines from a stream; `roi` is what every
imaging library calls a rectangle; `clip` is what a video is. The rename took
three common words out of circulation inside SIEVE and the gate then went
looking for them in files whose whole job is to speak to something outside
SIEVE.

The prediction this refutes is specific: the 02.2 pool item expected the first
collision to be `np.clip` in `rescale`/`normalize`, at 04.3, and expected the
question to be about array math. Had that been the shape, a word-boundary match
would have answered it, because `np.clip` and `clipped` differ from `clip` only
in what surrounds them. It is not the shape. `-filter_threads` and
`ffmpeg_roi` fail a word-boundary match too — they *contain* the dead word as a
morpheme — so the fix cannot be a matching rule alone. Something has to say
which vocabularies a file is allowed to speak, and `decode/` speaks two.

The single genuine hit is worth keeping in view rather than sweeping up with
the rest. `reader.py:135` calls a downscale "never a pipeline filter", which is
exactly what the gate exists to catch, in a file the plan says arrives
byte-identical. Both rulings are Kendrick's and they disagree over one comment.
