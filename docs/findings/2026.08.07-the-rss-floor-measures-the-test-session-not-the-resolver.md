# The RSS floor measures the test session, not the resolver

The assertion is `before > 64 * MIB`, commented "a Python process with numpy
loaded holds more". Numpy is loaded in v3 — `tests/conftest.py` imports it at
module scope, as v2's does — and the process still holds 47 MiB, because what
the number actually tracks is the total import footprint of whatever pytest
was told to collect. v2's bare session measures 63.98 MiB against a 64 MiB
threshold — 20 KB short — so the assertion passed there only on what
`test_machine.py`'s own imports add on top, a margin nobody chose. v3 is 87
modules and 17 MiB lighter for reasons the plan made deliberately: no scipy
(`core/wavelet.py` has not ported and may not), no PySide6 until Phase 7.

The prediction that would have made this a port defect: if a module had been
dropped or an import path rewritten, the other assertions in the same file
would have moved too, and the full-suite run would fail the same way. Neither
happened — the identical selection passes under `pytest -q` and fails under
the three-file selection, which is a property of the collector, not of
`process_memory_bytes`.

What makes this worth recording past the item is that it is the first ported
v2 test to fail on an *ambient* premise rather than on behaviour, and it will
not be the last: v2's suite grew up in a process carrying scipy, Qt, and
fourteen `pipeline/` modules. Any ported assertion whose subject is "how big
is this process" or "how long did this take" inherits that environment as an
unstated argument, and v3's is smaller by construction.
