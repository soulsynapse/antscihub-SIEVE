# v2's most-argued line in background_ema is asserted by nothing

The docstring on v2's `_narrow` makes the case at length: a bare `astype`
truncates toward zero, "which biases every pixel of a background model downward
by half a level on every frame it is read, and darkens the model against footage
it should be tracking exactly." The argument is correct. Nothing in v2 checks it.
The neighbouring test — `test_the_output_dtype_is_the_inputs_however_wide_the_accumulator`
— asserts `produced.data.dtype`, which both spellings satisfy, and the
convergence case reads means of flat frames whose model values are integers
already, so the two spellings agree there by construction.

This is the same shape as
[temporal_baseline's documented degenerate paths](2026.08.07-temporal-baselines-documented-degenerate-paths-are-asserted-by-nothing.md),
and it is worth naming the pattern: in v2 the line a module argues hardest for is
disproportionately likely to be the one no test reaches, because the argument
felt like the verification. Porting the test file verbatim carries that blind
spot forward intact — the parity half is what closes it, and only if the golden
is cut on the side of the code the argument is about.

The prediction that would have refuted this: the truncating mutant failing any
v2 assertion. It fails none, in either the unit file or the three other v2 files
that exercise the tool through the executor.
