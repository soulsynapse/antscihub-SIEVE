# v2's preview edits a replicate and renders the one before it

The failure mode is worth naming precisely, because it is invisible in every
number the command prints. The edit is applied to the document. The graph the
render receives is the edited graph. The *replicate* is stale, so
`resolved_params` merges the old pin over the new default and every node key is
the key it was before — which means the second render is a total cache hit,
which is exactly what `--edit` is run to observe. A working preview and a broken
one print the same two lines with different reuse percentages, and the broken
one prints the better number.

What would have refuted this: `resolved_params` merging in the other order, or
`with_param_edit` clearing the pin rather than rewriting it. Neither holds — the
override is documented as the winner and `edited_params` computes `changed`
against the pre-edit resolution and pins it.

It is a defect of the *command* and not of the mechanism. `with_param_edit`'s
two writes are what make an un-configured replicate follow the last one edited,
and both v2 and v3 keep that; what the command owes it is to read the replicate
back out of the document it just wrote, rather than to keep the copy it was
holding when the user typed.
