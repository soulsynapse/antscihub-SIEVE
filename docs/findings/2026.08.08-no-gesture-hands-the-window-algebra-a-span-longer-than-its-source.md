# No gesture hands the window algebra a span longer than its source

`moved_to` clamps the length it carries over: `length = min(window.frame_count,
frame_count)`. The GUI-skeleton item calls this the guard-with-no-caller shape
and warns that a case calling `moved_to` directly kills the mutant whether or not
anything in the tree can reach it. So the fixture was written with the question
attached, and the question has an answer.

The static half is an enumeration. `TimelineBar._window` is written in five
places and every one of them is already bounded by `_frame_count`: `bind_source`
sets `whole_of(self._frame_count)`, `set_window_length` clamps `frames` into
`[1, _frame_count]`, `move_window_to` and `_bring_to` store what `moved_to` and
`containing` returned, and `_on_window_resized` stores what the strip's drag
produced — which is `started_at`, `ended_at` or `moved_to`, each clamped to the
same count. `bind_source` is the only writer of `_frame_count`, and it re-derives
the window in the same call, so the shrink that would otherwise strand a long
window over a short source cannot happen either.

The dynamic half is the probe: append an assertion to the clamp line and sweep.
If any driven gesture in the suite reached `moved_to` with a too-long window the
sweep would report the mutant killed, and it reports it survived. The positive
control matters more than usual for a negative result — the same mutant against
the new file alone is killed, so the assertion is live and what it is reporting
is the absence of the input.

What would flip this: a caller outside the widget. `TimelineBar.set_window` is
public and takes any `SourceSpan`; `app.py` does not use it and the two test
files that do pass windows inside their sources. The day something adopts a
window from the document rather than from the source — a saved span, a span node
read back — the clamp acquires a caller and this finding is the record of when
it did not have one.

## The review's ruling, and a symbol this file misnames (2026-08-08)

The rotation's review re-ran both halves and they hold: the criterion's mutant
dies, the same sweep with `--ignore=tests/gui/test_window.py` is 0 killed / 1
survived, and the appended-assertion probe reproduces at 0 killed / 1 survived
over the driven suite. The consequence this file left open is now taken and the
file is closed on it: **the clamp stays.** `moved_to`'s docstring states a total
contract over the arguments its types permit, and the clamp is what makes that
sentence true; removing it would trade the guard for a `SourceSpan` refusal
raised out of a function whose job is to return a drawable window, on the
strength of a caller set `TimelineBar.set_window` is public in order to let move.

The first open question above names `Strip._window_from_x`. No such symbol
exists: the span is `TimelineStrip._dragged_to`, `bar.py:435`. Its reasoning
survives the correction, and the mutant it implies was measured rather than
inferred — `end=max(self._frame_count, 1) ==> end=self._frame_count` survives
`uv run pytest -q tests/gui`. It survives because the branch is unreachable, by
this file's own argument one degree further on: `_dragged_to` reaches it only
when `self._window is None`, `whole_of` returns `None` only at zero frames, and
`_on_source_changed` disables the strip there. Reaching it from a case means
calling `_dragged_to` directly on a disabled widget, which asserts arithmetic
rather than a behaviour. Recorded, not scheduled.
