# The foreign pointer guard is load-bearing only at its own length

The item this answers framed the choice as reachable-or-delete. The measurement
splits it: reachable, and reachable in a way that makes the branch matter for a
narrower set of pointers than its docstring implies. `_dereference` degrades in
two different ways that a reader cannot tell apart — the prefix check, and the
`defs.get(key, {})` default under it — and for every pointer whose eight-
character-stripped tail is not a definition name, the second does all the work.

What would have refuted keeping it: a demonstration that no pointer of
`#/$defs/`'s length can arrive. `ref_template` takes any string, so the length
is the caller's to choose, and the case is written at the length where the guard
is the only thing standing between a foreign pointer and a resolved definition.
