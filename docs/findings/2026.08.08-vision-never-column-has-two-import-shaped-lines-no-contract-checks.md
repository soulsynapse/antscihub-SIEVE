# VISION's Never column has two import-shaped lines no contract checks

The structure that produces this gap is worth stating on its own, because it is
what makes both misses look like nothing at the time. A never-clause is refused
for free when the import it names points *upward* through the layers contract,
and needs a bespoke `forbidden` contract only when it points *downward* — a
package refusing to reach something it is architecturally allowed to reach.
Every row of the table has at least one of the free kind, so a walk that stops
at "this row is covered" is right about the row and wrong about the clause.
Both existing bespoke contracts, `gui-computes-nothing` and
`pipeline-computes-nothing`, exist for exactly this shape; the two found here
are the third and fourth instances of it and were sitting between them the
whole time.

The prediction that would have refuted this: `lint-imports` going red, or any
of the six contracts naming `sieve.session` or `sieve.decode` as a source with
a `sieve.core`/`sieve.tools` module forbidden. `headless` names `sieve.session`
as a source, but only against `PySide6`, and its comment says so.

What makes the Phase-0 claim wrong rather than merely dated is that its own
argument covers the case it missed. It minted a contract for
`pipeline -> sieve.core.ops` while conceding the entry was inert because the
module did not exist, on the reasoning that a boundary is widened by code
written against it and so must bind first. `sieve.session` was a declared,
empty package on the same day, and the same reasoning applied to it verbatim.
