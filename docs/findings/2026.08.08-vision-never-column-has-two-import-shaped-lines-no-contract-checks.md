# VISION's Never column has two import-shaped lines no contract checks

The structure that produces this gap is worth stating on its own, because it is
what makes both misses look like nothing at the time. A never-clause is refused
for free when the import it names points *upward* through the layers contract,
and needs a bespoke `forbidden` contract only when it points *downward* — a
package refusing to reach something it is architecturally allowed to reach.
Every row of the table has at least one of the free kind, so a walk that stops
at "this row is covered" is right about the row and wrong about the clause.
Both existing bespoke contracts, `gui-computes-nothing` and
`pipeline-computes-nothing`, exist for exactly this shape; the two found here
are the third and fourth instances of it and were sitting between them the
whole time.

The prediction that would have refuted this: `lint-imports` going red, or any
of the six contracts naming `sieve.session` or `sieve.decode` as a source with
a `sieve.core`/`sieve.tools` module forbidden. `headless` names `sieve.session`
as a source, but only against `PySide6`, and its comment says so.

What makes the Phase-0 claim wrong rather than merely dated is that its own
argument covers the case it missed. It minted a contract for
`pipeline -> sieve.core.ops` while conceding the entry was inert because the
module did not exist, on the reasoning that a boundary is widened by code
written against it and so must bind first. `sieve.session` was a declared,
empty package on the same day, and the same reasoning applied to it verbatim.

## The walk only ever ran table-to-config, and the other direction has three members (2026-08-08, review of 44608be)

Both walks — the Phase-0 one and the one above — read a `Never` cell and asked
which contract refuses it. Neither read a `source_modules` entry and asked which
cell requires it, and the header's claim is symmetric: the file *is* "the
forbidden edge set of VISION.md's component table, made checkable", not a
superset of it. Walked the second direction at 44608be, `opencv-containment`'s
five sources against the rows they name:

- `core`, `gui`, `cli` — cv2 named in the cell, backed.
- `bench` — the cell is "Qt; sitting in the execution path it measures". No
  cv2, and none since the file was written; the contract's own `name` has said
  "core, bench, and the front ends" the whole time.
- `session` — no cv2 in the cell either. 44608be added the source and said so
  in its final message rather than widening the table.

So the divergence is not something 44608be introduced; it made the second
instance of a shape that had been sitting in the file since Phase 0, and is the
first artifact to name it. What is new is that the config is now a strict
superset in two places while the table is still the stated source, and nothing
reads either document — `todo/ownership-lines-answer-to-the-component-table.md`
checked the `Owns` half against `__init__.py` first lines and left `Never`
alone, which is the half both errors live in.

The third member is the one that costs something today. `sieve.pipeline` is
refused cv2 by no contract in the file: `headless` names it against `PySide6`,
`pipeline-computes-nothing` against `sieve.core.ops`, and `opencv-containment`
does not name it at all. Probed by planting `import cv2` in a module under each
package and running `lint-imports` on the real tree — `sieve.session._probe_cv2`
exits 1 naming `opencv-containment`, `sieve.pipeline._probe_cv2` leaves all
eight contracts KEPT. That makes the count of unenforced import-shaped nevers
above an undercount in its own terms only if the pipeline row is read as
implying cv2, which it is not; the row says Qt and `ops/` and nothing about a
codec. Which is the point — the row that owns **cache keys and the one
executor** is the row where a second `VideoCapture` would do the most damage,
and it is silent, so no walk of the column could ever have flagged it.
`todo/the-cv2-refusal-skips-the-executor.md` carries both halves.

## The divergence closed towards the table, not away from it (2026-08-08, work of `the-cv2-refusal-skips-the-executor`)

`opencv-containment` gained `sieve.pipeline`, and the `bench`, `session` and
`pipeline` rows gained the cv2 clause the config had been enforcing (or, for
`pipeline`, was about to) without them. Both directions of the walk now agree,
so the header's claim to be the forbidden edge set of the table — the thing this
finding closed as false — is true again as written, and the `closed` entry above
holds for the tree it was measured against rather than for HEAD.

What did not change is that nothing checks the agreement: it was restored by
hand, in the direction the item argued for, and the next divergence will be
found the same way. The `open_questions` entry above is untouched by this.
