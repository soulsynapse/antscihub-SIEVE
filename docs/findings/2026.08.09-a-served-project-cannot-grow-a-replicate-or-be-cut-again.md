# A served project cannot grow a replicate or be cut again

The whole-document offer is the right call — one pipeline serves every
replicate, so a crop node cannot be a `footage` node for one arena and a crop
for another, and `adr/one-execution-path.md` refuses the per-replicate graph
that would be the alternative. What the ruling does not come with is the way
back.

Both halves of that are reachable from the state a user is in the moment the
last arena is cut, which is also the moment the edit lands. Re-cutting is the
benign half: the refusal is explicit, names why, and a user who reads it can at
least see that the project changed shape. Growing is not. The override a front
end writes for a crop node is `region`, the node it names still exists under
the same id, and `Project`'s validator is satisfied by that — so the document is
saved. The graph the document describes has no `region` anywhere, and the first
thing that resolves parameters says so in pydantic's words rather than the
document's.

The measurement is a probe, not a case in the suite: both behaviours are one
`serving_edit` away from being covered, and which shape covers them depends on
whether the reverse edit exists. That is the open question above rather than a
gap in `tests/integration/test_crop_serving.py`.

## 2026-08-09: the reverse edit exists, and the second question is untouched

Both probes are now cases in `tests/integration/test_crop_serving.py`
(`TestTheWayBackFromAServedProject`), and both were re-run red against the tree
before the fix — the re-cut still refused with "no crop node reading the source"
and the grown project still failed with `extra_forbidden` on `region`, verbatim
as recorded above. `crop_serving.unserving_edit` is the edit, and `sieve
materialize` takes it implicitly on the invocation that asks to cut a served
project: it un-wires, cuts, and re-wires when every replicate has a file again,
so the visible cost of a re-cut is a re-cut.

What that leaves the second consequence with is a *path* rather than a save-time
refusal, which is the split the work item's criterion ruled on deliberately. The
document a front end writes for a thirteenth arena is still accepted by
`Project`'s validator, and it is still an override naming a parameter the node's
tool does not have; what changed is that cutting it is now what makes it
runnable rather than a command that refuses. The second open question below is
therefore live exactly as written, and its scope is unchanged by this: it is
about every override of an absent parameter and not about this one.
