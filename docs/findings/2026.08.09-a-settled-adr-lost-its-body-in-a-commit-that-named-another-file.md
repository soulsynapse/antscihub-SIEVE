# A settled ADR lost its body in a commit whose subject named another file

The failure surfaced two steps from its cause. A review that had committed
nothing ran the suite and found it red on the index-currency test; `--check`
named `ARCHITECTURE.md`; the regeneration diff was a single row, and the row was
an ADR summary that had become a note about who wrote it. Only then does `git
show` on the one commit since the last green tree explain all three.

The regeneration is where this gets awkward, and the awkwardness is worth
recording rather than resolving quietly. Leaving `ARCHITECTURE.md` stale keeps
the suite red for everyone downstream. Regenerating it takes a line that is
wrong in one file and publishes it into the file every reader opens first. There
is no third option inside a reviewer's powers, because the index is derived and
the derivation is correct — the ADR really does begin with that sentence now.
This review took the regeneration and is saying so here, so that the index row
is read as a symptom with a dated cause rather than as an ADR that decided
something strange.

For the conclusion to flip — for this to be a deliberate retirement rather than
an accident — the ADR would have to have a successor holding what it dropped,
which is how `adr/the-epsilon-admission-is-closed.md` was minted beside ADR 17
by the same author three commits earlier. There is no such successor, and the
missing trailing newline says a writer truncated the file rather than edited it.
