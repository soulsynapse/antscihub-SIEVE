# The no-fan-out half of the serving pair cannot be reached or killed

`serving_edit` splits on `targets == (None,)` and writes the chosen record into
the node's own parameters; `unserving_edit`'s `_uncut` mirrors it and writes the
record's region back the same way. Both are the correct shape for a project
that runs one target with no fan-out, and neither is reachable: the branch is
taken only when `project.replicates` is empty, and `project.crops` is written
only by `materialize_replicate`, which cannot run without naming a replicate.

The two survivors are therefore not a gap the suite could close by adding a
case through the command — there is no invocation that reaches them. A case
would have to construct the `Project` by hand, which pins the branch against a
document no front end writes, or the branch goes when the pair's contract says
a served project is a fanned-out one. That choice is the item's, not this
file's.

What makes this worth recording rather than fixing: the reverse edit was
written to mirror the forward one, and mirroring is right — the asymmetry would
have been the finding if it had gone the other way. The dead half was inherited
from `b63f43f`, and the sweep above is the first thing in the tree that says
so out loud.
