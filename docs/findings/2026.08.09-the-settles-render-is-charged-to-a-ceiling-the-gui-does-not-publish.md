# The settle's render is charged to a ceiling the GUI does not publish

The ruling's second bullet is the sentence at issue: the settled request "paints
the exact render, charged to the ceiling that already means the settled, correct
picture — scrub release → exact frame". That phrase is `scrub_settle`'s label,
verbatim. The work carried the ruling out correctly, and the worker flagged the
mismatch itself rather than papering over it; what nothing records is that the
sentence names a row `src/` has never published.

The reason this is worth writing down rather than filing as a defect is that the
divergence is safe in the direction that matters. `slider_to_preview` is 100 ms
and `scrub_settle` is 250 ms, so the interval the ruling wanted covered is
covered by something stricter than the thing it named. A miss would still be
caught; it would simply be reported under a key whose label says "slider →
preview" for a gesture the user experienced as a release.

What would flip this into a defect: a settle path that stops moving the playhead.
`slider_to_preview` is published on the playhead move, and the settle is only
under it because a `seek` moves the playhead. If a future settle repainted the
viewport without moving the bar — a re-render on the same index, say — the
render would be charged to nothing at all, and `scrub_settle`'s absence from
`WITHOUT_PRODUCER`'s justified list would stop being bookkeeping.

`docs/todo/cut-to-ready-gets-a-headless-referent.md` is the nearest neighbour and
is a different question: that key is absent from `budgets.TIMED` because no
headless gesture corresponds to it. `scrub_settle` is timed — `test_loop_budget.py`
measures it through the decode boundary — and what it lacks is a *runtime*
producer, which is a gap `metrics.py` already declares as a class.
