# A removal's price is charged only to the old document

A version stamp buys one thing: a build that meets a document it cannot read
refuses it by number instead of guessing. ADR 38 keeps that property in the
direction it looked — a v1 document carrying `source:` meets the post-removal
build and is refused by name, which is the price the ADR names and which costs
nothing while no such document exists outside a test. The other direction is
where the stamp actually earns its keep, and there the ADR's bump clause makes
the number stay at 1, so the pre-removal build has nothing to refuse by.

What it does instead is measured above: it reads the document, finds no
`source`, and tells the user to add footage to a project that names footage in a
node param it can see. That is a guess in the sense ADR 38's own first paragraph
rejects — "the failure mode of guessing is a run that completes and is wrong"
is the strong version; this is the weak one, an instruction the user cannot act
on. The prediction that would refute the reading: if the pre-removal build
refused the post-removal document for any reason of its own — a required field,
a validator on the graph — the bump would be decoration and the clause would be
harmless. It does not; `source` has been optional since
`adr/superseded/a-document-may-name-no-footage.md` narrowed it, and that
narrowing is exactly what makes the absence indistinguishable from a project
under construction.

This is not a defect in what 0b21a81 built. `Project._readable` keeping the
version it read is right under either branch, and the removal clause the item
asked for exists. What is left is that the clause is one-directional, and the
fold into 11.2 written in the same commit presents its consequence as a choice
for that item's worker. A worker picking between two branches with this cost
unmeasured is the shape the loop exists to prevent, so the measurement lands
here and the item's criterion now pins the answer whichever branch is taken.
