# Anchoring puts the project directory into the node key

The ADR clause is one sentence and it names both halves of this failure:
"Resolution policy stays out of the key. What is hashed is the resolved file's
identity, never the rule that found it — neither 'this exact path' nor 'the
folder of this name beside the project'. A rule in the key makes two projects
naming one file disagree about it." The anchoring is the second of the two
forbidden rules, applied and then hashed.

What makes it worth a file rather than a line in the item is that the direction
of travel is towards universality, not away from it.
`adr/a-document-names-footage-only-through-a-tool.md` — the ADR d62948e is
implementing — requires the document to store the path *relative to the project
file*. So relative is not an edge spelling that a few hand-written projects
happen to use; it is what every project will hold once the migration lands. Today
most params on disk are absolute, because that is what a file picker and
`crop_serving` write, and for those the key was already location-bearing before
this commit. The relative spelling was the one that was location-independent, and
it is the one the migration makes the norm and this commit makes location-bearing.

The user-visible cost is a cache that empties when a project folder moves.
Relocating is not hypothetical: `Project.relocated` exists for it and
`tests/unit/test_pipeline_model.py::test_relocating_rebases_every_stored_path`
says why in its own comment — "Moving a project folder is how footage reaches a
cluster". After a move the document is correct, every file resolves, and every
node below the source recomputes, with no symptom that says why.

The probe, verbatim, because nothing in the tree holds it:

```python
from pathlib import Path
from sieve.core.pipeline_model import Node, Pipeline
from sieve.pipeline.dag import Dag
from sieve.pipeline.resolve_source import anchored
from sieve.tools import discover

discover()
p = Pipeline(nodes=(Node(node_id="s", tool_id="pick", version="1.0.0",
                        params={"pattern": "plate_bg.png"}),))

def keys(pl):
    return Dag.build(pl).node_keys(source="SRC", picked={"s": "IDENT-SAME-FILE"})

print(keys(p))
print(keys(anchored(p, Path("C:/one/proj"))))
print(keys(anchored(p, Path("C:/two/elsewhere"))))
```

A negative result would have been three equal keys, or two equal anchored ones —
either would have meant the path param does not reach the digest and the commit's
claim held. All three differ.

## What the criterion could not have caught

`done_when`'s four legs name a refusal, a rewrite, a CLI message, a library line
and a version. None of them derives a key, so a green criterion here would have
said nothing about this either. The clause that was discharged was checked by the
one case the run wrote, and that case asserts the resolved *file* — which is
right, and is a different assertion from the key the resolution moved.
