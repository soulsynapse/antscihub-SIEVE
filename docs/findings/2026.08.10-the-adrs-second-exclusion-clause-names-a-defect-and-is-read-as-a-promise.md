# The ADR's second exclusion clause names a defect and is read as a promise

The exclusion clause forbids two derivations by name and then prices each. Both
halves of the priced sentence are failures, and the second one — a project that
goes on agreeing with itself after the folder underneath it has been
reorganized — is a failure precisely because the reorganization may have put a
different file where the rule looks. That is the ADR's opening scenario, one
background swapped for another, served under the first's name with no symptom.

The reading that treats it as a promise cannot be held with the sentence before
it. Only a key derived from the rule rather than from identity survives a
reorganization of the folder; identity-derived keys cannot, because the identity
is of the file and not of the pattern. So a reader who wants that half delivered
is asking for the mechanism the same paragraph forbids two lines earlier.

What makes this worth a file rather than a correction in passing is where the
reading came from. `picked_key`'s docstring has restated the clause as a
conjunction of two properties since before a1ce8d0 — "so two projects naming one
file agree about it and one project agrees with itself after the folder is
reorganized underneath it" — and every subsequent reader met the ADR through
that sentence. The item that ordered a1ce8d0's work inherited it, the run
inherited it from the item, and the run's amendment now states it as a measured
bound on a settled design. Nothing in that chain was careless: the ADR was cited
by name at every step, and the paraphrase reads as a faithful one until the
original paragraph is opened.

Under the promise reading a1ce8d0 discharges half a clause and half is still
owed. Under the reading argued here it discharges the clause whole, and the
recomputation a user sees after moving a project folder is the ADR working as
written. The commit's code is the same under both, which is why this is a
correction to four prose sites and not to `node_key`.
