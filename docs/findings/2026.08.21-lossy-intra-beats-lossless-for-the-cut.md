A 300-frame 1024x1024 region cut from the 5.3K source, five ways, against
decoding the original with a crop (random access = frame-accurate seek to a
random frame in the region; p50s from the one run that measured all five,
`results/05-the-cut-20260821T192609Z.json`):

| route              | size    | sequential | random   |
|--------------------|---------|-----------:|---------:|
| original + crop    | —       | 6.3 ms     | 315.5 ms |
| FFV1 intra         | 124 MB  | 0.21 ms    | 25.5 ms  |
| x264 CRF18 inter   | 15 MB   | 0.24 ms    | 38.9 ms  |
| x264 CRF18 intra   | 22 MB   | 0.10 ms    | 10.3 ms  |
| x264 qp0 intra     | 147 MB  | 0.29 ms    | 37.5 ms  |
| Ut Video           | 186 MB  | 0.22 ms    | 6.4 ms   |

Each encode cost ~3 s. Intra-only makes random access ~30x cheaper than the
original — the tuning loop is trivially feasible on a cut — but the surprise
is FFV1: intra *and* lossless, yet 2.5x slower at random access and 5.6x
larger than lossy intra, because losslessly encoding inherited sensor noise
makes FFV1's own decode the new floor (the failure mode ideas.md predicted).
This is why NLE proxies are lossy intra (ProRes/DNxHR/CineForm), and it
sharpens the proxy question from lossless-vs-lossy to *which lossy intra
codec*, traded against reversibility.

"Lossless loses," though, is a fact about *which* lossless. x264 `-qp 0`
loses the way FFV1 does — H.264's entropy machinery makes it the dominated
point of the table, no faster than inter and 6.6x the lossy-intra bytes,
and routing it through NVDEC did not help (explorer-logs 20:08: ~35 ms
drags through the cuda approach too). Ut Video does not lose: Huffman over
a simple spatial predictor is the least decode a lossless codec can do, and
it posts the fastest random access of *any* file in the tree, felt as well
as timed (explorer-logs 20:08: ~3.4 ms drags, 2.5-5.3k fps sweeps). The
price is 8.3x the lossy cut's bytes — sparse-raw losing to inter-coded is
the same arithmetic in the other direction — no rate knob, and no hardware
route ever (NVDEC's codec list is fixed silicon). So: lossy intra wins the
size/speed trade and stays the tuning substrate; when a use needs exact
pixels with interactive random access, Ut Video is the cache codec, and
FFV1's remaining claim is archival, not use.

## How to recreate

```
uv run --group experiments python experiments/decode-experiments/05-the-cut.py
```

The script re-encodes the clips into `video-tests/derived/` only when they
are absent (delete them to re-pay and re-measure the encode), and notes
encode wall time and sizes in the result.
