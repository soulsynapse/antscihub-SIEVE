A 300-frame 1024x1024 region cut from the 5.3K source, three ways, against
decoding the original with a crop (random access = frame-accurate seek to a
random frame in the region):

| route              | size    | sequential | random   |
|--------------------|---------|-----------:|---------:|
| original + crop    | —       | 6.4 ms     | 296.6 ms |
| FFV1 intra         | 124 MB  | 0.22 ms    | 25.4 ms  |
| x264 CRF18 inter   | 15 MB   | 0.22 ms    | 40.0 ms  |
| x264 CRF18 intra   | 22 MB   | 0.10 ms    | 9.5 ms   |

Each encode cost ~3 s. Intra-only makes random access 31x cheaper than the
original — the tuning loop is trivially feasible on a cut — but the surprise
is FFV1: intra *and* lossless, yet 2.7x slower at random access and 5.6x
larger than lossy intra, because losslessly encoding inherited sensor noise
makes FFV1's own decode the new floor (the failure mode ideas.md predicted).
This is why NLE proxies are lossy intra (ProRes/DNxHR/CineForm), and it
sharpens the proxy question from lossless-vs-lossy to *which lossy intra
codec*, traded against reversibility.

## How to recreate

```
uv run --group experiments python experiments/decode-experiments/05-the-cut.py
```

The script re-encodes the clips into `video-tests/derived/` only when they
are absent (delete them to re-pay and re-measure the encode), and notes
encode wall time and sizes in the result.
