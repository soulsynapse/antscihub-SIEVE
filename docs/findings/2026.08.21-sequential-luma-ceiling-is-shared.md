Sequential full-resolution luma off the uncut 5.3K HEVC source costs ~5.3–6
ms/frame (~7.6x realtime) and three unrelated routes land on it: PyAV with 4+
codec threads (5.3), ffmpeg CLI to a null sink (8.4 including process
startup), and CUDA NVDEC via ffmpeg (5.5). Pure decode is at parity between
cv2 (`grab`) and PyAV — same libav underneath — so switching bindings buys
*joints* (free luma plane view, seek control, batch shape), never decode
speed. The luma plane view costs ~0.2 ms over decode; cv2's `retrieve`
conversion costs ~17 ms for a job PyAV's cached reformatter does in ~1.6 ms,
so "conversion costs more than decode" was a cv2 artifact, not a video fact.

Also bounded here: NVDEC decode-with-download runs 9.3 ms/frame (loses
sequentially, wins on seek latency — see the seek finding), and piping
full-res rawvideo from a subprocess is pipe-bound on Windows at ~18 ms/frame
(~880 MB/s), which disqualifies out-of-process decode at full resolution
while display-sized pushdown (scale+gray in libavfilter) makes it free.

Machine: 22 logical CPUs, RTX 4060; builds in the result files.
