Fresh decoders each taking a disjoint 300-frame GOP-aligned chunk of the
uncut 5.3K source, in one process, measured by the explorer's parallel
sweep (aggregate and per-worker fps, opens included):

| shape    | aggregate | per worker              |
|----------|----------:|-------------------------|
| 1sw+1hw  | 186 fps   | sw 99 · hw 109          |
| 2sw+1hw  | 157 fps   | sw 54, 57 · hw 103      |
| 4sw+1hw  | 143 fps   | sw 29–30 ×4 · hw 100    |

Software workers destroy each other — ~190 fps solo down to ~30 fps each at
four wide, aggregate *lower* than one worker alone — while NVDEC holds
~100–109 fps under every shape. This reproduces v2's open "1.88x faster
pipeline made playback worse" finding as a mechanism: the ceiling is shared
(memory bandwidth / allocator, the AVBufferPool suspicion in
docs/decode/ideas.md, unconfirmed as to which), not per-core. The fastest
whole-video pass on uncut footage is the lean asymmetric pair, and
decoder-per-consumer designs are dead on arrival here.

Caveat: measured through the explorer's Python-per-frame loop, which caps
solo software near 120–190 fps where the harness measures 190; the collapse
ratio is the finding, not the absolute fps.

## How to recreate

```
uv run --group experiments python experiments/decode-experiments/explorer.py
```

Open the uncut source, press "sweep ∥" once per shape in the shape picker;
per-worker and aggregate numbers land in the HUD and in a new
`explorer-logs/*.json` under the run's `sweeps[].parallel`. A
harness-proper version of this is README experiment #5, still unwritten.
