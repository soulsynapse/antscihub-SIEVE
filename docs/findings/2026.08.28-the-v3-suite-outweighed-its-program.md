The v3 test suite against the source it tested, in files and lines:

| | files | lines |
|---|---:|---:|
| `src/` | 101 | 31,171 |
| `tests/` | 117 | 33,521 |

1,145 test functions; the suite is larger than the program. By directory:
unit 50 files / 15,813 lines, gui 38 / 9,382, integration 11 / 3,751,
bench 7 / 1,841, docs 3 / 1,618, scripts 3 / 619, plus a 158 KB `goldens/`
of `.npy` arrays and cache-key strings.

Character, not just size: zero property-based tests (no hypothesis import
anywhere in the tree), example-based throughout — fixtures constructed by
hand, outputs asserted against values the implementation produced.

What the measurement can and cannot say. It cannot count the regressions
the suite caught while v3 was alive; that value was real and is invisible
here. What it can say is what outlived the tree: when v3 stopped, zero
test files crossed into v4, while the things that did cross were
decisions and measurements (the ADR shelf, the findings). A suite this
size that transfers nothing was encoding the implementation beside it,
not the contracts above it — which is exactly what example-based tests in
an oracle-free domain must do, having nothing else to assert against.
Two sub-cases sharpen it:

- `tests/bench/` is 1,841 lines of budget tests — fixed performance
  figures of the kind ADR-0008 now refuses outright. In hindsight this
  seventh of a suite defended numbers that were properties of one
  machine.
- `tests/goldens/` held cache-key strings and small arrays — the one
  golden-master role the relations lead would keep, and about 0.5% of
  the suite by weight.

The transferable claim: a test's survival value is the survival value of
what it asserts. Assertions against contracts (declarations honoured,
keys complete, relations between runs) outlive rewrites; assertions
against outputs the code produced die with the code, at a carrying cost —
here — of a second program's worth of lines.
