`docs/decode/ideas.md` holds that a protocol derived from one backend is that
backend wearing an interface's clothes, and `experiments/tool-experiments/README.md`
holds that a tool that does not exist may be a workload and may never be evidence.
So the contract was not argued with — two more sources were written against it
unchanged, run, and the breakages recorded.

## What it cost each source to answer

| source | open | listed | first picture | listed-not-deliverable |
|---|---:|---:|---:|---:|
| video file, 5.3K HEVC cut mid-GOP | 800.4 ms | 11 328 | **7141.6 ms** | 20 |
| image directory, 12 stills 640×360 | 176.6 ms | 12 | 9.9 ms | 0 |
| synthetic, random access | 0.9 ms | 300 | 0.3 ms | 0 |

Three orders of magnitude between the ends of that table, through one contract,
with the same `Store` and the same window. That is the thing worth having: every
number below is a difference the contract has to survive, not a video fact.

## The seven gaps

**1. An address is not a path, and everything downstream assumes it is.** The
contract types `handles`, `open` and `Opened.address` as `str` and never says
file. `library._key` is `str(Path(video).resolve())`, so the address
`synthetic:frames=40,access=forward` became
`…/antscihub-SIEVE-v4/synthetic:frames=40,access=forward`. `Entry.available` is
`Path.is_file()`, so a present stills directory and a live synthetic source both
report **"not where it was"**. `footage.kind` returns `''` for a directory;
`footage.size` stats the directory entry and reports **4 KB for twelve images** —
wrong rather than absent, which is worse.

**2. `patterns` cannot express a directory or a scheme, so two of three sources
are unreachable from the + button.** `dialog_filter(FRAME)` still offers only the
video suffixes, and `QFileDialog.getOpenFileName` cannot pick a folder at all.
Both new sources had to be opened by calling `_open_source` directly. `Source`'s
own docstring says a too-narrow pattern costs a click through "All files"; that
is true only for sources whose address is a file.

**3. `Extent` is a query and the store made it a constant.** `edges.py` says so in
as many words — *"a file is closed when it opens, a directory being written into
and a stream are not"* — and both new sources answer differently on a second call.
`Store.positions` is read once in `__init__`. A folder that grew from 12 to 13
while open, and a synthetic extent revealing 3 positions per call, are both
invisible to everything above the store. This is the first time `closed=False` has
been produced by anything.

**4. `Access` is declared, and nothing in `src/` branches on it.** A FORWARD-only
source opened, staged a frame, and looked identical to the video file at every
point in the window. Asking for a position behind the head then raised
`ValueError: 0 is behind the head; this source is forward-only` straight through
`Store.frame` into the drawing code. The contract already carries the fact that
would have prevented it.

**5. The form is nailed to the edge, so a valid frame reads as a missing one.**
`Edge.spec.form` is fixed at open from the first image, so a directory holding
images of two sizes cannot be described. A 300×200 image among 640×360 ones reads
back `None` and lands in `Store.missing` — reported as a frame that could not be
delivered, when it is a frame that could not be delivered *in the declared form*.
Same root as the cost gap: `Store.frame` receives 5312×2988 BGR (47.6 MB) from the
video source because the source form is the only form a read can produce, while
the tier stack this ports from never holds anything but a 1 MB luma crop.

**6. An open extent has no stable identity.** The image directory fingerprints
names and sizes, which is cheap and correct at the instant it is asked, and
changes the moment a still lands. The video source's fingerprint is stable only
because its file is finished. Anything durable filed under an open source's
identity is filed under a name that will not be there tomorrow, and the contract
cannot say which kind it is holding.

**7. `None` now carries three different facts, and only one of them is its own.**
Writing the synthetic source is what surfaced this. `nodes.py` defines `None` as
the producer admitting it cannot supply something its extent listed. But:

- the mid-GOP prefix means *this position cannot be decoded, ever, by anyone*;
- the odd-sized image means *this position is fine and is not in the form I declared*;
- behind the head on a forward-only source means *this position is deliverable, and not to you, now*.

The third could not be reported as `None` without lying, which is why the
synthetic source raises instead — and a raise is not in the contract either, so it
arrives at the GUI as an unhandled exception. One return value is doing three
jobs, and a coverage record built on it cannot tell a hole from a refusal.

## What did not break

The three-way split the contract does draw held up. `Registry.offering(FRAME)`
found all three sources, `source_for` picked correctly per address, and
`Source.offers` did its job with no change. `Frames`' LRU is form-agnostic and
needed nothing. `read_form`'s canonical construction was never wrong — only
expensive, and only because it runs after the decode rather than instead of it.

## How to recreate

```
uv run --group tools python -c "from sieve.registry import load; print(load())"
```

The stills directory is built from the tracked-but-gitignored footage:

```
uv run --group tools python - <<'PY'
import av, glob
from pathlib import Path
out = Path("video-tests/stills-test"); out.mkdir(parents=True, exist_ok=True)
src = sorted(glob.glob("video-tests/*.MP4"))[1]
with av.open(src) as c:
    s = c.streams.video[0]
    for n, frame in enumerate(c.decode(s)):
        if n >= 12: break
        frame.reformat(width=640, height=360, format="rgb24").to_image().save(
            out / f"frame-{n:05d}.png")
PY
```

The synthetic source needs nothing: `synthetic:frames=300`, plus `access=forward`,
`grow=N`, `drop=k`, `latency=ms` to reproduce gaps 3, 4 and 7.
