`orchestrator2-experiments` README question 3 asked whether the callback model
makes `Step.sequential` load-bearing or leaves it a field with one legal
value. Neither branch wins as written. The constructed case that was supposed
to need the flag **dissolves into the contract the tree already has**, and
what remains is a cost problem rather than a scheduling one.

The tree contains no sequential step, so the step here was built: the one
`tools.lag_mhi`'s docstring names as its sequential twin, a decayed motion
history `acc_n = max(alpha * acc_{n-1}, m_n)` at `alpha = 0.85`, offsets
`(0,)`, everything else in state. 160 rows, the sweep declaring the window
attention-first from its midpoint so rows genuinely arrive out of ascending
order. Compared against an ascending single-threaded loop, on the 120 rows
past the reference's own warm-up:

| arm | wall | peak concurrent | ready depth | rows wrong | max abs diff | mean abs diff |
|---|---:|---:|---:|---:|---:|---:|
| reference (ascending, 1 thread) | 1.807 | — | — | — | — | — |
| shared instance, parallel | 1.748 | 2 | 1 | 120/120 | 5.45 | 0.193 |
| ordered (serial, ascending) | 2.322 | 1 | 83 | **0**/120 | 0.0 | 0.0 |
| bounded, reach 2 | 1.910 | 2 | 3 | 120/120 | 1.44 | 1.067 |
| bounded, reach 5 | 2.968 | 2 | 72 | 120/120 | 0.284 | 0.164 |
| bounded, reach 10 | 5.080 | 2 | 109 | 120/120 | 0.0196 | 0.0073 |
| bounded, reach 20 | 8.818 | 2 | 121 | 120/120 | 0.000225 | 0.00008 |
| bounded, reach 40 | 15.046 | 2 | 111 | 90/120 | 0.000002 | 0.000001 |

**The parallel arm's wrongness is a data race, not a result about
scheduling.** One tool instance, two recorder threads, one mutable
accumulator, no synchronisation. It is in the table because it is what a naive
port writes, and it is labelled because an earlier version of this experiment
reported it as evidence that parallel dispatch breaks stateful steps. It is
not evidence of that. AviSynth+ has said so since `MT_MULTI_INSTANCE`: state
implies *unshared* state, and only sometimes implies serialization.

**The recurrence is a scan, so it was never intrinsically sequential.**
`acc_n = max(alpha·acc_{n-1}, m_n)` is first-order linear in the max-plus
semiring; composing two steps gives `a -> max(alpha^2 a, max(alpha C_1, C_2))`,
the same shape, so the operator is associative and the whole pass is a prefix
scan — computable in any order with a constant-size summary per chunk. This is
Blelloch's decomposition and it is old.

**The effective reach is real and converges geometrically.** Because
`alpha < 1`, row `n - j` reaches the answer scaled by `alpha^j`, so past some
`j` the history cannot move the result. Restated as a *stateless* step at
offsets `(-k .. 0)` — no state, nothing to race, nothing to order — the
disagreement with the unbounded reference falls by roughly an order of
magnitude per five rows of reach: 1.44 at k=2, 0.284 at k=5, 0.0196 at k=10,
2.25e-4 at k=20, 2e-6 at k=40, where 30 of 120 rows agree *exactly*. The exact
agreements are the tell that this is truncation and not approximation: the
error is `max(0, tail − retained)` under a max, so it is zero whenever no old
motion outranks a recent one, and it stops appearing at all once `alpha^k`
shrinks the tail below the retained maximum.

That is the same structure as a keyframe bounding a seek. This tree already
measured the video version in
`2026.08.21-uncut-seek-costs-a-gop-not-a-frame`; the signal-processing name is
IIR warm-up. A step with bounded reach is an ordinary step: `offsets`
expresses it, `first_honest` trims its warm-up rows, `residency` sizes its
hold, and the dispatcher needs to know nothing about it.

**So the flag is not needed for this tool, and `lag_mhi` already knew.**
`tools.lag_mhi` is the same picture at sparse offsets with no state — the
bounded form, chosen before this experiment existed. The case constructed to
justify `sequential` turns out to be the case the contract already covers,
which is evidence that the flag has no instance rather than evidence that it
has one.

**What does not dissolve is the cost, and the naive restatement is bad at
it.** Bounded reach k recomputes k absdiffs per row, so the wall goes 1.91 s
at k=2 to 15.05 s at k=40 — eight times the sequential reference — while the
sequential version pays one absdiff per row and the ordered arm costs only
2.32 s. Correctness moved to the stateless form; efficiency did not follow it.
The scan decomposition is what recovers both and was not built here. Anyone
reaching for bounded reach as a way to avoid ordering should price it: past
about k=5 this step stops being fetch-bound and becomes arithmetic-bound, and
the ready depth in the table (3 at k=2, 72 at k=5, over 100 beyond) is that
crossover being crossed.

That crossover is also where `2026.08.30-re-entry-removes-the-poll-interval-
and-not-the-wall` predicted its own knob would start earning: request depth
bought nothing there because the step's arithmetic was about 3% of its row's
decode. These arms are the other regime, and the two results agree about where
the line is without having been run against each other.

## What this does not establish

**That `sequential` should be deleted.** A step whose history is genuinely
unbounded — no decay, or a state machine with no forgetting — is untouched
here, and would still have to say so. What is established is that the one case
this tree could name for the flag is not such a step, so the field still has
no instance and should not acquire scheduling machinery on the strength of a
hypothetical.

**That ORDERED is wrong to have.** It works, exactly, at both anchors it was
run at, and cost 28% of wall and a hold of 83 activations here. It is the
right mechanism if an unbounded step ever arrives. It should not be reached
for before one does.

**Anything about `recorders=1`.** With a single recorder thread the race
disappears and only ordering remains as a question. That configuration was not
run, and a reader who wants the flag to be about ordering alone should run it
first.

**The scan.** Asserted from the algebra, not measured. The associativity is
checkable by hand and the decomposition is standard, but no arm here computed
the accumulator by parallel scan, so its cost in this tree is unknown.

**One tool, one alpha, one window, one machine.** 160 rows at a 1024² crop,
`alpha = 0.85`, anchor at the window midpoint, one reader, two recorders.
Walls are one run each on a machine that
`2026.08.30-re-entry-removes-the-poll-interval-and-not-the-wall` shows drifting
by more than small differences; the value comparisons are exact and do not
depend on timing.

## How to recreate

```
uv run --group tools --group experiments python experiments/orchestrator2-experiments/03-sequential.py
```

`REACHES` is the sweep that finds the effective reach. Comparisons start past
the reference's own warm-up, because the reference began with an empty
accumulator and a bounded arm reaching behind that point would otherwise be
scored against the reference's artefact.
