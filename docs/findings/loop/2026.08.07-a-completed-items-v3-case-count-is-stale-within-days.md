# A completed item's v3 case count is stale within days

The counts move because later items are supposed to move them.
`the-dag-propagation-cases-answer-a-mutation.md` is open against
`tests/unit/test_dag.py` and will add cases to a file 03.3 states a total for;
`test_executor.py` gained one between 03.6's review and this measurement. So a
`cases:` declaration that stayed checked would fail the index build on the day
some *other* item did its job, and the only way to clear it would be to edit a
finished item's frontmatter until it agreed with a tree it never described.

What would have to be true for the check to survive `done`: the number would
have to be a claim about the file's whole life rather than about what the item
delivered. Nothing in the repo says that, and the item that added the
declaration is the one that says the opposite — a re-derivation item's total is
its own arithmetic, stated so a reviewer does not re-do it by hand.
