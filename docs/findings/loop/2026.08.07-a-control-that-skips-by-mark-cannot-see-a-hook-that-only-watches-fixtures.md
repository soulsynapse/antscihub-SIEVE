# A control that skips by mark cannot see a hook that only watches fixtures

This is a new vacuity shape, and it is nastier than the ones already listed
because the control was deliberate and its reasoning was written down. The item
minting it argued correctly that a gate turning skips into failures is
trivially satisfied by a gate that fails always, and asked for a control. The
control that landed does refute *that* mutant. What it cannot refute is a gate
that is too wide, because the only non-guarded skip it exhibits is raised by
`@pytest.mark.skip` during call phase, and `pytest_fixture_setup` is never
invoked for it. The guard clause could be deleted outright and every assertion
in the file still holds.

The generalisation worth carrying forward: when a control exists to prove a
guard is *narrow*, the thing it exercises has to enter the guard. A negative
case that never reaches the code under test is indistinguishable from no case
at all, and reads as coverage in the diff. Ask, for any control, which line of
the implementation it executes — if the answer is "none of them", it is
checking that the rest of pytest still works.
