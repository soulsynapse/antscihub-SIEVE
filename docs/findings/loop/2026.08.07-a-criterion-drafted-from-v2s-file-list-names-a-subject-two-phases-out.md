# A criterion drafted from v2's file list names a subject two phases out

The item is a port, and the natural way to write a port's criterion is to name
v2's test files under v3's names. That is right whenever the port is of the
module those tests cover. It goes wrong at exactly one seam: a v2 test file
sits beside the module it tests in the *directory*, not in the dependency
graph. `test_filter_contract.py` tests `filter_base.py` and imports nothing
outside `core`. `test_filter_discovery.py` sits next to it and imports the
whole shelf — `sieve.filters`, its scan, its guidance reader, and one concrete
filter. Adjacency in v2's `tests/unit/` predicted neither.

The detectable signature is available at item-writing time and costs one
command: read the imports of every v2 test the criterion names, and check each
against what the item's own file list builds. Here the first import block
answers it — `from sieve.filters import GUIDANCE_SECTIONS, discover,
guidance_for, guidance_path` names three things 01.2 never had a reason to
build, and `from sieve.filters.downsample import DownsampleParams` names a
phase.

What makes this a loop finding rather than a one-off is that the worker did
the right thing and it was still expensive. It built the item, stopped at the
criterion, wrote the argument, and left the file unwritten — which is exactly
what PLAN.md's porting discipline asks for and cost a full run to reach a
conclusion one `grep '^from' ` at drafting time would have produced. The
deferral path works; it is not free.
