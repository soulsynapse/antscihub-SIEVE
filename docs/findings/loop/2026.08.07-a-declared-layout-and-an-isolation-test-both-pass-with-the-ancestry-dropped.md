# A declared layout and an isolation test both pass with the ancestry dropped

The module's first paragraph names the asymmetry it is built around: an input
left out is a wrong answer served from cache and never noticed, an input wrongly
included is a miss. Both surviving mutations are the first kind, and they are
the two the suite was written to refuse.

The reason `editing_one_branch_leaves_its_sibling_valid` misses the fold is that
isolation and propagation are complements and only one of them is uncomfortable
to state. "An edit here does not reach there" is three equality assertions over
keys that did not move; "an edit here reaches everything below it" needs the
graph walked downward, which is the thing the key exists to do. A suite that
holds the first and not the second is consistent with a `node_key` that ignores
its `upstream` argument entirely — which is what the probe built, and it passed.

The rename probe is the sharper one, because the pin was supposed to be the
guard. `NODE_KEY_POSITIONS` names `upstream`; nothing says what an upstream *is*,
so `f"{upstream}{replicate.name}"` fills the position as legitimately as
`upstream` does. The pin is worth keeping — it caught the added-position case on
the first try — but its verdict is "these five positions, in this order", and a
verdict about what a key is made of does not follow from it.

For the vacuity list: **a pinned layout is an assertion about names, and a
mutation that keeps the arity is invisible to it.** It sits beside
[2026.08.06-one-red-per-contract-certifies-the-contract-not-its-lines.md](2026.08.06-one-red-per-contract-certifies-the-contract-not-its-lines.md)
— same step from a sample to a quantified claim, one level down.
