# A dropped row is dropped for its tool, and its claim goes with it

The re-derivation table on 03.8 is accurate. Six v2 cases, four verdicts of
survives-or-replaced, two drops, and both drops name a real blocker: `crop` and
`span` are Phase 4 tools and this build's shelf holds one tool. Nothing in the
table is wrong. What it does not carry is that a v2 case is a fixture *and* a
claim, and the blocker was only ever about the fixture.
`a_hand_written_crop_node_runs_with_no_replicates` needed `crop` to be
interesting as a crop test; the words `with_no_replicates` are the rest of the
name and they need no tool in particular. `downsample` would have served, and
the result is that `sieve run` on a project with no replicates — the plainest
thing the command does — never runs in the suite that certifies it.

This extends
[a re-derivation table certifies v2's coverage, not v3's](2026.08.07-a-re-derivation-table-certifies-v2s-coverage-not-v3s.md)
rather than repeating it. That finding is about the rows a table cannot have,
because v3 grew a guard v2 never had. This one is about a row the table *does*
have, correctly reasoned, whose verdict still costs coverage — so a reviewer who
checks the table for completeness and arithmetic, as that finding's remedy
implies, comes away satisfied either way.

The second survivor has a different cause and the same shape. Every invocation
in the file passes `--frames`, for a reason the module docstring argues well:
schema v1 records no tuning range, so a project cannot narrow itself and the
flag is how a test says which frames. The consequence is that the flag's absence
is exercised exactly once, in the dry-run case, where it is expected to *refuse*.
The branch where it falls back to the container and reads the video's length —
named in the commit subject, defended in a docstring paragraph — has no case at
all. This is the known "fixture too uniform to disagree with itself" shape moved
up a level: not the data the fixture holds, but the shape of the command line
every case types.

What would have refuted this: if the surviving branches had been ones a
one-tool shelf genuinely cannot reach. Two of the five survivors are exactly
that — the chroma format selection, which no tool yet varies, and the lead-in
shortfall warning, which needs a tool declaring lead-in. Those are honest and
they are why the sweep is worth running rather than assumed: it separates the
branches Phase 4 will reach from the branches nobody looked at.

The mechanical form of the check, for the next review: mutate every branch the
diff introduces, not just the refusals. The earlier finding's remedy —
substitute `pass` for each `raise` — would have killed neither of these two,
because neither is a refusal.
