# A fold has two maxima and one fork fixture exercises the inner one

`_fold`'s docstring is precise about both halves: "a node's output requirement
is the maximum of what its downstreams ask of it, which is where the
max-over-paths happens. The answer is the maximum over the roots, whose input
space *is* the source's." The test file argues the first sentence hard — the
fork fixture exists so that `max` and `sum` give 6 and 9, and the case even
re-derives 6 by hand from `source_warmup_frames` over each chain. The second
sentence is asserted nowhere, because every one of the file's fourteen
pipelines has one root, and over a single root `max`, `min`, `sum`, and "the
only element" are the same function.

The reason it reads as covered is that a fork *is* a branching fixture. The
worker's own mutation list has "max→sum over downstreams" on it, killed; the
mental model that produced the list was "does the fold sum where it should
max", and the fork answers that question. `dag.roots` is a second collection in
the same expression, and nothing in the item's table or the module's prose
distinguishes them, so the fixture that proved one was allowed to stand for
both.

What would have refuted this: if schema v1 forbade a multi-root pipeline, the
outer maximum would be structurally single-valued and both mutants would be
equivalent rather than uncaught. It does not — `Dag.roots`' own docstring says
"a graph with nodes always has at least one", not exactly one, and two
edgeless nodes build cleanly.

The generalisable check is cheap and mechanical, and it is a fixture question
rather than a mutation question: for each aggregation in the diff, name the
collection it aggregates over and find the fixture where that collection has
two unequal members. Where there is none, the aggregation is a lookup wearing
an aggregation's clothes, and the mutation sweep is the instrument that says so
— but only if the sweep's list comes from the source rather than from the
author.
