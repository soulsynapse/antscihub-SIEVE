# A generator that drops half its cases is green

The item asked for a gate that "cannot go stale when a line is added", and it
got one. Staleness has a second direction, and the file's own two guards are
both shaped for the first: they ask whether a contract contributes *anything*.
A refactor does not empty a contract. It narrows a fold — `product` to `zip` is
one character of intent — and the contract still contributes, every case it
still builds still goes red, and the count silently falls from 36 to 33.

Nothing in the reds can see this, and that is not a gap in the assertions. A
case that was never built cannot fail. The only witness is a second computation
over the same config, which is why `_owed` multiplies where `_cases` walks: two
statements of one rule, kept apart on purpose, so the fold that eats one does
not reach the other. The repo's usual refusal of a second statement of a rule
does not apply where the first statement is a generator — that is the one
construction with no other subject available.
