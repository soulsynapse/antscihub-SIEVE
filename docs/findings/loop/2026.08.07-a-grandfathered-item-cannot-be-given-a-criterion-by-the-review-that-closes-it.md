# A grandfathered item cannot be given a criterion by the review that closes it

The `UNSPECIFIED_DEBT` set is built so the criterion rule binds on new items
while the backlog is paid down: a name may leave, none may be added, and the
leaving is coupled to the item gaining a `done_when`. That coupling assumes the
repayment and the specification happen in the same session — a `specify` run,
which edits the item and may edit the set.

What it did not anticipate is an item on the list being *finished* first. Once
it is finished, the selector's only answer for it is `review`, and a review is
the one role that may not touch code. So the two edits the ratchet couples —
write the criterion, delete the name — are split across a role boundary that
neither side can cross: the review cannot delete the name, and no other role
can be sent at an `awaiting-review` item without first reopening it and
pretending the work is not built.

What would refute this: a review that wrote a `done_when` into a grandfathered
item and left `tests/docs/test_doc_index.py` green. It cannot, and the ratchet's
own comment says why — the name is what makes the absence legal, so as long as
the name is there the criterion is illegal, and deleting it is a code edit.
