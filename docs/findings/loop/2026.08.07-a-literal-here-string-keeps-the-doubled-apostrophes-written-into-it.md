# A literal here-string keeps the doubled apostrophes written into it

Same session, same repo, second unfixable message in two days, and the fix for
the first is what set up the second.
[A PowerShell here-string in the Bash tool lands a commit subject of `@`](2026.08.07-a-powershell-here-string-in-the-bash-tool-lands-a-commit-subject-of-at.md)
concluded: use PowerShell, where `@'...'@` is real. That conclusion is correct
and was followed. What it did not say — because nothing had gone wrong that way
yet — is that PowerShell's *other* literal form, `'...'`, escapes an apostrophe
by doubling it, and that habit rides along with the delimiter. `@'` and `'`
share three characters and one mental slot.

Both failures are silent in the same way: the shell has no complaint, git has no
opinion, exit code 0, and the damage is one `git log` away in a record that the
repo's own rules then freeze. The asymmetry worth noticing is that the first
failure was visible in `git log --oneline` — a subject of `@` is unmissable —
and this one is not. Three `''` inside a body are the kind of thing a reader
skims past, and only the run that wrote them knew to report them. It did.

The prediction that would refute treating this as a class rather than two
mistakes: if the next multi-line message goes out clean without a mechanical
check, the two were slips. A hook that rejects a body containing `''` or a
subject that fails the Conventional Commit grammar would settle it either way,
and would have cost one retry against two permanent records.

## Resolved against slips, 2026-08-07

The prediction failed. Four more `@` subjects landed between 14:40 and 17:59,
after both findings were written and while nothing mechanical existed — the
count is a measurement in
[the Bash-tool finding](2026.08.07-a-powershell-here-string-in-the-bash-tool-lands-a-commit-subject-of-at.md).
So these are a class. What that does *not* yet settle is whether the hook is
the fix, because the trap only reached `CLAUDE.md` at 36037cd, after every one
of the recurrences: the channel the committing run actually reads had never
carried it. The hook is the answer if the artefact lands again now that it has.
