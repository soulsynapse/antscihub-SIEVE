# A live gate asserting a collector is empty passes for a collector that collects nothing

The vacuity shapes already in the review prompt are all about a case that
cannot disagree with itself. This one is about a case that *can* disagree and
never gets the chance, because the only tree it is ever run against is the
healthy one. `assert doc_index.gates() == []` is a real gate — it is what stops
a stale ADR-6 stray or a dead word reaching a commit — and it is also, as a
test of `gates`, satisfied by `def gates(repo): return []`. The four predicates
underneath it each have their own tmp-tree cases with non-empty expectations,
so the file reads as well covered; what nothing reaches is the wiring that
calls them.

The tell is the direction of the assertion. A case that asserts a *non-empty*
result has to construct the condition and therefore proves the code path runs;
a case that asserts empty proves only that today's tree is clean, which is a
fact about the tree. Both are worth having, and a file that has only the second
for a given function has no case for that function at all.

This generalises past `doc_index`: any `assert collect_problems() == []` run
against the live repo — an import-contract sweep, a spelling gate, a budget
check — is in the same position the moment it is the only case its collector
has. What would have to be true for the conclusion to flip is a second case on
a tree that *does* trip the collector, and that is exactly what the amended
item now asks for.

A second, smaller thing this measured: an extraction that only moves passing
code is the refactor most likely to arrive untested, because every existing
case stays green by construction and the run reads that as coverage. `ae49e8f`
was scrupulous about red-before-green for the two behaviours its item named,
and shipped a third behaviour — gates no longer block a write — with no case,
in the same commit.

## 2026-08-08: the budget check named above is one of these, and widening what it reads did not change that

The generalisation this file offered — "an import-contract sweep, a spelling
gate, a budget check" — has now been met in the budget check. `f1bc0fd` moved
`Reading.misses()` from the fixture's narrowed per-gate series onto the run's
whole published series, which is a real correction and the reason the item was
opened. It cannot be regressed silently, though, only in one direction: a review
mutant putting `misses()` back onto `gated` (`tuple(sample for ss in
self.gated.values() for sample in ss if not sample.within_budget)`) SURVIVED the
whole module, while the two mutants attacking the *collection* — rebuilding
`published` from the narrowed map, and dropping the `bus.subscribe(run.append)`
that fills it — were both KILLED.

The asymmetry is this file's point restated at a finer grain. The run's new
count assertions on `published` are non-empty expectations, so they prove the
collection is whole; `assert not missed` is an empty expectation over a healthy
clock, so it proves nothing about which collection it read. Which collection
`misses()` consumes is the *entire subject* of the item, and it is the one part
of it no case can fail on. A worker can therefore satisfy an item about wiring
by rewiring correctly and leave the wiring itself uncovered, with a green
criterion and a mutation sweep it never thought to point at the assertion's
subject rather than at the data feeding it.

The tell generalises: when the change under an item is *which* collection a
guard reads, the guard's own assertion cannot witness it unless the guard can
fire. Fold that need into whatever item owns making it fire — here
`docs/todo/a-budget-miss-is-an-exit-code-once-something-can-force-one.md`, which
already argues that nothing in this repo can drive a real clock past its
ceiling — rather than treating the correct rewiring as covered because the
criterion is green.
