# A mutant inside an assertion's condition survives by construction

The harness's four rules are all about the mutant landing somewhere other than
where the reviewer meant, or running against bytecode that predates it. This is
a different failure: the mutant lands exactly where it was aimed and the report
is still worthless, because the thing that would have killed it is the thing
that was mutated.

It matters because the reflex the review prompt installs — added lines get a
sweep — reads as unconditional, and a review that follows it over a test file
gets two survivors and a choice between reopening correct work and arguing its
way out of its own evidence. The sweep's docstring already draws the line
("`tests` is included because a mutant in a test helper is a legal subject") but
draws it as permission rather than as a bound, and nothing in the tool enforces
it.

What the harness would have to see for the other reading to hold: a mutated
assertion killed by some *other* test. That happens only when the assertion
lives in a helper or a shared fixture, which is exactly the case the open
question is about. For a leaf test, `assert X` mutated to `assert True` is green
by definition, and no amount of test suite kills it.
