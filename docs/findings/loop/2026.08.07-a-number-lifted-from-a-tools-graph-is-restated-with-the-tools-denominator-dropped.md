# A number lifted from a tool's graph is restated with the tool's denominator dropped

The two miscounts in this loop failed at opposite ends. The earlier one
(`2026.08.07-the-run-that-corrected-an-inherited-miscount-wrote-its-own.md`)
was a total a reader had to recompute and nobody did. This one was never
computed: 86 is exactly what grimp reports, and it was carried across three
sentences losing "including external packages" at the first of them. By the
time it reached the minted item it read as a size of `src/sieve/`, which is the
form in which it is off by 41%.

The irony is load-bearing rather than decorative. The item the number went into
exists to say that a stale claim about the tree misleads every session that
reads it, and its own first sentence was a claim about the tree nothing had
checked. A number acquires a denominator from the sentence around it, so
restating a measurement is where a denominator gets lost — which makes the
corrective the same one the earlier finding reached from the other direction:
keep the number in the file that made it, and link rather than restate.

What would refute this reading: a source where 86 *is* the count of files under
`src/sieve/`, at some revision. There is none — the graph has been larger than
the directory since `include_external_packages` was set, which was the first
commit of `.importlinter`.
