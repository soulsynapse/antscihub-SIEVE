# A PowerShell here-string in the Bash tool lands a commit subject of `@`

The trap is that both shells are live in the same session and the session's own
instructions name PowerShell as the default, so the here-string form is the one
in working memory when a multi-line message is needed. Under `sh` it is not a
syntax error — `@'text'@` is three concatenated tokens — which is what makes it
silent. A syntax error would have failed the commit and cost one retry.

What would have flipped this: had the Bash tool rejected it, or had `git`
refused an empty-looking subject, the cost would have been a re-run rather than
a permanent record. Git has no opinion about subject shape, so the only place
this can be caught is before the commit or in a hook.
