# A re-derivation table certifies v2's coverage, not v3's

PLAN.md's re-derivation clause asks a worker porting a v2 component to account
for every v2 case with a verdict: survives, replaced, or dropped with the rule
that dropped it. It is a good discipline and it worked — the 39 rows in
`schema-v1-is-rederived-with-nodes.md` are accurate, the arithmetic closes, and
the six v3 cases with no v2 ancestor are named. The table's frame of reference
is the problem, not its quality. It answers "did anything v2 checked stop being
checked", and a reviewer reading it comes away feeling the coverage question
has been asked.

It has not been. The module under review is a re-derivation, not a port; it was
written as if v2 never existed and it grew refusals v2's two files never had.
Those refusals appear in no row, because there is no v2 case to give them a
verdict against, and the reader's attention has already been spent on the rows
that are there.

What would have refuted this: if the untested guards had turned out to be the
ones v2 also left untested, the finding would be about inherited debt rather
than about the table. They are not — the ten include checks the module's own
docstrings argue for at length, like the stale-sink reference that
`with_pipeline` exists to catch.

The check is cheap enough that there is no reason for a review not to run it.
Substituting `pass` for each `raise` in the diff and re-running the criterion
is one script, and it reads the tests against the code rather than against the
source the code was derived from — the same correction
[a verbatim port carries the buried vocabulary past review](2026.08.07-a-verbatim-port-carries-the-buried-vocabulary-past-review.md)
made for prose, arrived at independently for behaviour.

## A port's table has the same blind spot, and it is a whole module wide (2026-08-08)

07.6 ported v2's `gui/transport/` and `gui/timeline/` and wrote a nine-row
class-by-class table for `test_timeline.py`, a paragraph for
`test_player_scrub.py`, and an eight-bullet list of what the port left behind.
The table is accurate and the arithmetic closes. It is also, like the
re-derivation table above, an audit of v2 — and the port needed a module v2 had
no equivalent of, because v2's canvas was a different widget. `src/sieve/gui/
canvas.py` therefore appears in no row, and it is held by nothing:
`--mutant "self._frame = image ==> pass  # "` survives the whole 868-test suite,
as do the never-upscale clamp in `frame_rect` and `clear`. The item's headline
sentence — the canvas plays and scrubs footage through the decode path — is
checked as far as `frame_changed` and no further.

The correction to the reading above is one word. The finding was written about
*re-derivation* items, where the module is new by construction; a *port* item
looks like the case that does not need it, because the module is supposed to be
v2's. The rule is the same either way and is easier to apply from the diff than
from the table: every file in the diff that has no row is a file the table is
silent about, and the sweep goes there first. Here that would have named
`canvas.py` and `timeline/geometry.py` in one pass.
`todo/the-gui-skeletons-argued-branches-have-no-case.md` carries both.

One operational note: rewriting the file with Python's `read_text`/`write_text`
converts CRLF to LF on this repo's checkout, so the restore has to be
`git checkout --` rather than writing the original string back, or the tree is
left dirty in a way that looks like an unrelated whole-file change.
