# A review that rules on one line launders the other twenty-seven

The 03.2 run read the gate's 28 red lines by module: `decode/` talks to FFmpeg,
therefore `decode/`'s dead spellings are FFmpeg's. That is a reasonable first
pass and it is wrong in one direction only — a module speaking a foreign
vocabulary also speaks its own, and the two are not separable by which
directory the line is in.

The review that followed had a narrower job: 03.2 had declared `reader.py:135`
a standoff only Kendrick could break, and the review correctly re-derived that
it was not one. Having ruled, it wrote the remaining 27 forward as the item's
subject. Nothing in the review's own procedure asked it to; the criterion under
test was a pytest invocation, and the 27 were prose in the item body. But the
item is what the next worker reads, and a sentence that survived a review reads
differently from a sentence a work run wrote — the 03.2.1 worker had to spend
its opening argument dislodging a classification, and flagged the disagreement
for review rather than treating it as an ordinary read of the tree.

The check that would have caught it is cheap and it is the same check this
review ran to confirm the fix: reproduce the count, then print the lines. Under
the by-module reading `LoweredScale.filter_id` is FFmpeg's word; on the line it
is `filter_id: str`, which is ADR-1's canonical example of the rename. A
classification stated as a number is a claim about lines, and it is checkable
against lines in under a minute.

What generalises past this item: when a review carries forward a claim it did
not test, it should say which claims those are. A review's verdict is read as
covering the item it closed, and everything the item still asserts rides along
with it.
