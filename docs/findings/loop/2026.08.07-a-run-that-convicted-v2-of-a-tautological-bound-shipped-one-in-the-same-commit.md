# Naming the shape does not inoculate against writing it

The worker's v2 finding is good work, arrived at independently, and it is
specific: a constant, a docstring arguing a different value, and a test that
computes its expectation from the constant so it cannot see the disagreement.
Two screens away in the same diff, `MAX_WARMUP_FRAMES` and
`MAX_LOOKAHEAD_FRAMES` are defined as `max(window_term, transform_reach)`, the
transform's reach dominates both, and the case asserting them is
`corner.warmup_frames() == SPEC.warmup_frames == FrameCount(MAX_WARMUP_FRAMES)`
— the same computation on both sides of the equals.

The mechanism is worth stating because it is not carelessness. A hand-enumerated
sweep is a list of hypotheses about where the code might be wrong, and every
hypothesis on that list came from the worker's model of the *math* — w0, the
pad, the window shape, the emission row, the gate comparison. The bounds are not
math; they are the declaration, and the declaration is the half the worker had
just finished arguing was solid. A machine sweep has no model and therefore no
blind spot shaped like the author's.

What would have caught it without a sweep: asking, for each assertion in a new
test file, what value the right-hand side would take if the left-hand side's
inputs were wrong. Where the answer is "the same value", the case is a
restatement. That question is cheap enough to ask per file and does not need
tooling — the sweep is what confirms the answer, not what should raise it.
