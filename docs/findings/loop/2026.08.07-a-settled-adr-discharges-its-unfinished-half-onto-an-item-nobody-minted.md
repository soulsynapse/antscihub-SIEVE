# A settled ADR discharges its unfinished half onto an item nobody minted

An ADR earns the right to be short by pushing what it does not settle
somewhere else. ADR-18 does that twice and gets one of them right: `StreamKind`
"stays open on the usual terms" with no claim that anything tracks it, which is
honest, and the multi-root migration is "an item", which is a claim about the
repository. The two sentences look alike and only one of them can be false.

What makes this worth writing down rather than fixing quietly is the second
hop. The next run cited the phantom item as a positive reason to remove
material from VISION — not "this needs work nobody has scoped", which would
have been true and would have left the reader looking for the scope, but "there
is already an item for it", which closes the question. A false claim of
coverage is worse than an admission of none, because it is the one form of
missing work that reads as handled. The reviewer only caught it by grepping a
sentence that had no reason to be suspicious.

What would refute the general shape: an ADR whose forward reference names a
slug. Then the claim is a link, a broken link is visible, and the failure mode
is a 404 rather than a silence. Every forward reference in this repo that
points at `PLAN.md` or another ADR already has that property. The ones that
point at "an item" in prose do not, and they are the ones that can rot without
anything going red.

## Amendment, 2026-08-08 — the same shape from an item, and inside one commit

Found while reviewing 07.8. `docs/todo/a-composite-parameter-prints-no-shape-and-no-bounds.md`
is cited as a live referent by three items and by `ARCH-REVIEW-2026.08.07.md`,
and the file does not exist. The interesting part is that `3ef4663` — the
commit that chunked Phase 7 — is where both halves happened: it folded that
item into `the-generator-builds-widgets-from-stereotypes.md`, whose body says
"folds in here and its file is gone", *and* wrote into
`whether-a-stereotype-declares-an-arity.md`'s ruling section that the same item
"stays a separate item: it is about reading bounds through an `anyOf`". One
commit, two claims, and only one of them can be true.

Two things this adds to the finding as first written. The source does not have
to be an ADR — an item's body discharges scope the same way and is read by
fewer people. And the window is not "between commits": a fold and a citation of
the folded thing can be authored in the same edit, so "check the referent still
exists when you write it" would not have caught this one. What would is the
fold's own discipline, which CLAUDE.md already states and this commit did not
follow — the emptied item is closed with a dated section naming where its
paragraph went, rather than deleted. A closed file with a forwarding line makes
every one of these four citations land somewhere.

The substance is not lost: 07.5 is done and the JSON-Schema walk it absorbed is
in `core/tool_base.py`. What is stale is one sentence in a `done` item, which
is why this is an amendment and not an item — nothing selects it, and nothing
will read it except the next session that greps the slug. That is the same
reachability problem as
[an item is drafted against an alternative a done item already
refused](2026.08.08-an-item-is-drafted-against-an-alternative-a-done-item-already-refused.md),
from the other direction: there a done item's ruling could not be found, here a
done item's claim cannot be corrected by anything that would notice it is wrong.

## Amendment, 2026-08-10 — the quieter form: no claim of an item, and no item

ADR 37 settles two spaces in one sentence — the extent a `REGION` or `POINT`
indexes, and the axis a `BAND` is read on — and only the axis half was built.
The ADR makes no false claim here: its "what this does not settle" section names
the draggability question and cites the item that carries it, correctly. The
extent half is simply *inside* the settled scope, so nothing in the ADR marks it
as outstanding at all, and nothing in `docs/todo/` carried it either. The item
that built the axis half named the gap in its own body and correctly declined to
fold it into `one-magnifier-and-everything-on-it-maps-to-source-pixels.md`,
which leaves the observation in a `done` item's prose — the exact place the
amendment above says a claim goes to die.

What this adds. The original finding keys on a false sentence, which a grep can
in principle catch. This form has no sentence to catch: a settled ADR whose text
is entirely accurate can still leave half its decision unimplemented and
untracked, and the only signal is the arithmetic of reading the ADR's scope
against the pool. That is a reviewer's job by construction, and it is the same
reviewer who is under instruction not to mint freely — so the pressure runs the
wrong way exactly where the check has to happen. The item was minted at this
review (`the-extent-half-of-adr-37-lands-and-its-stated-placement-cannot-hold.md`),
and it also carries a second thing this session found: the ADR's *placement*
sentence is contradicted by the tree that implements it
(`findings/2026.08.10-a-params-dependent-fold-cannot-live-on-the-dag-because-the-dag-is-replicate-agnostic.md`).
Both are the same underlying exposure — an ADR settled and merged in one day
with one of its two halves unbuilt, so nothing tested the half that would have
found the placement wrong before the text bound.
