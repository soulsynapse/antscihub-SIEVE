# A substring assertion is satisfied by the identifier printed beside it

The v2 audit's vacuity shapes are all about a test that cannot disagree with
itself — output compared to itself, `equal_nan=True`, a fixture too uniform to
fail. This one is different in kind: the test compares against a genuinely
independent expectation, and the expectation is just *also true for another
reason*. The assertion is not tautological, it is under-specified, and
under-specification is invisible in review because the string in the source
reads as exactly the concept being checked. A reader checking this file by eye
sees `assert "signal" in output` under a docstring about the selecting
parameter and agrees.

It is the mirror of
[a mutant anchored on a token that also appears in prose reports a false
survivor](2026.08.07-a-mutant-anchored-on-a-token-that-also-appears-in-prose-reports-a-false-survivor.md):
there a reviewer's mutation hit the wrong occurrence of a token and manufactured
a defect; here a worker's assertion hit the wrong occurrence of a token and hid
one. Both come from the same property of this repo — the vocabulary is small and
deliberately repeated, so tool ids, param names, enum values and prose all spell
the same words, and any match on a bare identifier has several possible sources.
The discriminator is the same in both directions: anchor on the fullest context
that only one thing can produce.

The generalisation worth carrying is that assertions on rendered text are the
place where this bites, because rendering is exactly where a value gets
surrounded by other values. A test on `spec.emissions[0].selected_by == "signal"`
could not have been fooled; the same word checked against a paragraph could.
