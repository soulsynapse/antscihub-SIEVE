# A tailored prompt works an item the selector would have sent to specify

The specify/work split exists so that no session both defines what finished
means and declares itself finished. `--next` enforces it by handing back a role
alongside a path, and the queue enforces it by starting the session that role
names. A tailored prompt bypasses both without touching either: it is a
paragraph, it names an outcome, and nothing in it resolves to an item at all.

That makes the failure structural rather than careless. The tailored prompt is
the *sanctioned* response to a diagnosis worth keeping, so the escape hatch is
open exactly when a previous session understood the problem best — and
understanding the problem is not the same as having stated a criterion for it.
Here the two came apart cleanly: the worker's diagnosis was right in every
particular, its execution was green, and the one thing it shipped wrong is the
one thing a criterion would have forced it to measure.

What would refute this framing: a tailored prompt that lands an item with a
criterion anyway, because its author wrote one into the paragraph. Nothing
stops that, and it is the cheap habit if the prompts are ever revised — a
tailored prompt that does not state its own `done_when` is a work run with the
specify step silently skipped.
