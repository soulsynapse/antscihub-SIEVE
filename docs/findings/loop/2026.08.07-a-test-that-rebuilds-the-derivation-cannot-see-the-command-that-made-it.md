# A test that rebuilds the derivation cannot see the command that made it

The vacuity shapes the review prompt already lists are all *local* — the
comparison is to itself, the fixture is too uniform, the guard has no caller. This
one is not local, and every part of it reads well: two real documents, two real
plans, real keys compared, and an explicit `assert set(keys[0]) == {CUT, DOWN}`
guarding against the empty-key vacuum. The worker even wrote the mutation it
believed it was catching into the docstring — "fails for any derivation that folds
the list, or its length, or its emptiness, into `source_key` or a node digest."

The defect is one line above that: the test's own `_plan` helper calls
`ExecutionPlan.build(dag, source=source_identity(...), span=..., replicate=...)`,
faithfully mirroring `run_cmd`. Mirroring is the problem. `build` has no
`checkpoints` parameter, so *no* implementation of it can make the assertion fail;
the proposition is decided by the signature, and the test restates it. The only
code that holds both the `Project` and the plan constructor is `run_project`, and
the test routes around it.

The general rule this yields: **an invariance test must read the value from the
production path, not construct one the same way the production path does.** When
a claim is "A does not influence B", the test has to obtain B from something that
was handed A. If the only way to get that is through the CLI, then it goes through
the CLI — which is what the file's own module docstring argues for elsewhere
("driven through `sieve run` rather than through `execute`, deliberately") and
then does not do for this one case.

What would have caught it at authoring time is the question the red-before-green
check does not ask. Red-before-green was performed here and was honest: the worker
reverted the implementation and reported that this case passed anyway, calling it
"a property assertion — it pins existing behaviour rather than new." That is the
finding stated and then filed as acceptable. A case in a new item's test file that
is green against the tree the item started from has not been shown to be worthless,
but it has been shown to constrain nothing the item added, and that is the point at
which the author owes a mutation rather than a label.
