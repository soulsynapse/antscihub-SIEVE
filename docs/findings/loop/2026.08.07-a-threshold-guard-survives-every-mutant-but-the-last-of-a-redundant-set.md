The reviewer's instrument and the guard's shape disagreed. A mutation sweep
assumes the subject is a single decision — flip the operator, change the digit,
and the tests either notice or they do not. A guard against a floor is not that:
its subject is a set, and a mutant that removes one member of a redundant set
leaves the assertion true, so SURVIVED is the correct answer and says nothing
about the guard's strength.

The direction is the opposite of the three sweep lies already recorded, which
print SURVIVED for edits the tests in fact kill and convict correct work. This
one is the sweep reporting truthfully about an edit that was never a test of
anything. It costs a reviewer the same way regardless: the survivor reads as a
hole, and the hunt that follows is for a defect that is not there.

Two things follow for a reviewer sweeping a guard of this shape. Read the
assertion for a floor before choosing mutants — `bool(x)`, `x >= 1`, `any(...)`,
`x != []` all say the guard's subject is existence and not count. Then mutate to
the floor: delete every instance, not one, because that is the only edit the
guard was written to catch. If the intended contract really is one-per-file
rather than at-least-one, that is a different guard and the sweep has found a
question worth asking rather than a defect.
