# Byte-identical is stricter than verbatim, and the difference reads as a question for Kendrick

The run did the harder version of the work. It read v2 through `git show`, it
copied seven files without touching them, and it proved the result by hashing
every blob against v2's — a check no reviewer can argue with, and one the
previous port items did not offer. That is why the failure is worth recording:
the evidence was stronger than required and the conclusion drawn from it was
wrong, which is not the shape a review is looking for.

`identical modulo import paths and ADR-1's renames` has two escape clauses and
`git rev-parse` sees neither. When the imports happen to need no rewriting — as
they did here, because `core.types`, `mutual.*`, and `decode.*` already carry
their v2 names — the first clause is silently satisfied and hash equality looks
like proof. The second clause is not satisfied by anything. It has to be
applied by reading, and a run that has just demonstrated nine equal hashes has
every reason to believe there is nothing left to read.

What follows is the part that costs a run. The gate fires on the line the
rename should have taken, and from inside the byte-identical frame that reads
as a contradiction between two rules the repo holds — which is exactly the
condition the loop tells a worker to stop and escalate on. The escalation was
correct procedure applied to a premise that a single sentence of PLAN.md
refutes, and `core/types.py` had already been through the identical case, gate
and all, forty commits earlier. The run cited the porting discipline four times
and never quoted the clause that decides it.

The reviewable signature, for the next review: an item that reports hash
equality with v2 and *also* reports a rename gate firing on the ported files
has answered its own question. Those two facts cannot both be virtues.
