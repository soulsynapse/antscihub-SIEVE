# git checkout restores a sweep onto the commit and deletes the work under test

The three mutation findings already on file are all about a sweep reporting
SURVIVED for a mutant the tests kill — a false accusation, which is loud. This
one is the opposite failure and is silent: every verdict the sweep printed was
correct, and the run still destroyed its subject. Nothing in the output says
so, because the mutants were applied from a copy held in memory and never read
the file back.

It is worth separating the two things `git checkout --` was chosen for. Against
`write_text` it is right about line endings, and that is the reason the
instruction exists. But it restores to the commit, not to the state the sweep
found, and a reviewer runs against a worker's commit while anyone else runs
against a working tree. `write_bytes` of the bytes read at the start restores
to what was found and does not retranslate anything, which is correct under
both — the only thing it cannot do is undo an edit made outside the sweep.

The anchors are the second half of the same lesson. This tree's files are CRLF
on disk, so an anchor written with `\n` matches nothing and the sweep stops on
its own uniqueness assertion. That failure is safe — it refuses rather than
lies — but it means a sweep must normalise the text it matches against, and a
sweep that skipped the uniqueness assertion would have found zero occurrences,
replaced nothing, run a green suite, and reported every mutant as a survivor.
