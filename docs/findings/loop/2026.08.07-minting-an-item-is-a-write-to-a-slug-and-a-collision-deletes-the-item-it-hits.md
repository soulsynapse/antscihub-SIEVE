# Minting an item is a Write to a slug, and a collision deletes the item it hits

The v2 audit's vacuity shapes are all about a check that cannot fail. This is
the other direction: an edit that should have failed and had nothing to fail
against. The run did everything the loop asks of a worker that finds a gap
outside its item — it did not fix the gap, it wrote it down, it kept its own
scope — and the writing-down silently destroyed the earlier record of the same
gap, including whatever an earlier run had reasoned about it that this run
would not have reproduced.

What makes it a loop finding rather than a slip is that the recovery was not
mechanized. The run noticed because it happened to ask for untracked files at a
moment when it expected to see one, and read the mode letter. Had it run plain
`git status --short`, the modified path would have sat in a list of five other
modified paths — four of which it had legitimately modified — and been staged
by `git add -A` with the rest. The commit would have carried a silent revert of
an earlier run's item body under a message about parameter stereotypes, and the
only trace would be in `git log --diff-filter=M` on a path nobody had reason to
look at.

The prediction that separates this from ordinary carelessness: if the index
generator were the guard, a clobber would leave `.index.md` disagreeing with
the tree and `tests/docs/test_doc_index.py` would go red. It cannot. The
generator's contract is that the index matches the files, and a replaced file
is a file — regenerate and the two agree again, whatever the row now says.
Consistency with the tree's *history* is not something anything in the loop
reads, which is why the reviewer's check has to be the commit's diff rather
than the commit's result.
