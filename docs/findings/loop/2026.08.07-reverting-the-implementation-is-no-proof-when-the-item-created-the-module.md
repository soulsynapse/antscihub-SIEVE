# Reverting the implementation is no proof when the item created the module

This is the same defect as
[one red per contract certifies the contract, not its lines](2026.08.06-one-red-per-contract-certifies-the-contract-not-its-lines.md),
arrived at from the opposite direction. There the sample was five edges standing
for 23; here it is one import error standing for seven assertions, and the ratio
is worse because the single failure is not even a member of the set it claims to
cover — a `ModuleNotFoundError` is not any test failing, it is every test not
running.

What makes it easy to miss is that the worker's account is accurate. 03.7 said
"all seven were shown failing first," and they were. The claim is true and
certifies nothing, which is exactly the shape a review that only checks
claims-against-diff will pass.

The prediction that would have refuted the concern: a mutant of the landed
implementation that no test caught. Six mutants and every test moved for at least
one, so this file's assertions are real — the finding is about the *proof*, not
about 03.7's tests, which hold.

## Second instance, same shape, and the remedy held (2026-08-08)

06.6 created `src/sieve/pipeline/series_collector.py` and its six tests in one
commit, and its account of red was the same single collection-time
`ModuleNotFoundError` — accurate, and certifying none of the six. The review did
not re-run it. Three mutants of the landed module instead, each anchored on a
sentence the module docstring makes: `self._series = self._stacked()` moved
outside the `measure` context (the span closing before the array exists),
`refill` no longer clearing `_start`/`_rows` (a second drag's graph carrying the
first's frames), and the frame-gap comparison short-circuited to false. Each
killed exactly one test and a different one — the three claims separate, which
is what the import error could not show.

Two things this instance adds. The mutant set was drafted from the *docstring*
rather than from the diff, which is what made the one-mutant-one-test mapping
checkable: a module that states three claims should have three tests that move
independently, and a claim with no mutant that isolates it is either untested or
not really a separate claim. And the cost was about three minutes of a review
that had already re-run the criterion — cheap enough that the open question
below (whether the burden should move to the worker, red against an importable
stub) still has no forcing argument on either side.

## Third instance, and the mapping is the reusable part (2026-08-08)

07.2 created `src/sieve/session/session.py` and its eight tests in one commit,
and its account of red was the same pair — `file or directory not found` for the
missing test module, then one collection-time `ModuleNotFoundError` for the
missing implementation. Accurate; certifying none of the eight.

Seven mutants of the landed module, drafted from its docstring and its method
docstrings as in the 06.6 instance: `open` seeding `_past` with the loaded
project, `commit` not clearing `_future`, `commit` not pushing the present,
`undo`'s bottom-of-stack guard forced true, `undo` not pushing onto `_future`,
`redo` not moving the present, and `save` writing the redo top instead of the
present. All seven killed by
`uv run pytest -q tests/unit/test_session.py`.

What the run of the sweep once per test adds — eight further sweeps, `-k` on one
test name each — is the mapping, and it is worth the extra couple of minutes
because it is the thing that answers *is any test in this file vacuous*, which
the aggregate KILLED column does not. All eight tests moved for at least one
mutant and all seven mutants died to a distinct subset of tests, so nothing in
the file is vacuous and no two mutants are testing the same thing.

The reading worth carrying is of the near-miss rather than the result.
`a_reopened_project_round_trips` — one of the two tests the criterion selects —
is killed by exactly one of the seven, and it is the mutant that seeds history
at `open`, which the test asserts against directly. Its actual subject, that the
document comes back off disk as the one the session was holding, was reached by
none of the seven, because at the moment that test saves, the redo stack is
empty and even the deliberately misdirected `save` writes the right value. An
eighth mutant, `save ==> pass`, kills it. So a mutant that fails to separate is
usually a fact about *when* the fixture reaches the mutated line, not about the
test — and the sweep is only proof for the claims some mutant actually reaches.
Reading the survivors, and noticing which claim no mutant touched, is where the
review earns the sweep.
