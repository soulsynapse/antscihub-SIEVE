# The copy-verbatim anchor stopped being verbatim two commits after it landed

01.1's review verified the port by blob identity — `git rev-parse` on both
sides, three hashes recorded in the item — and that was the right check, because
this worktree is CRLF and v2's blobs are LF, so a textual diff calls all 625
lines changed. But it is a check that ran once. Two of the three edits since are
inside `verbatim`'s stated definition and one is not:

- `883ec97` is the port.
- `83078d3` rewrote five dead-word spellings in comments and docstrings —
  `2026.08.07-a-verbatim-port-carries-the-buried-vocabulary-past-review.md` is
  that measurement, and it is the near neighbour of this one rather than the
  same fact: it is about what a port's diff cannot show, this is about what
  nothing shows afterwards. ADR-1's renames are named in PLAN.md's definition
  of verbatim, so that commit does not break the claim — and it is enforced by
  a gate, which is why it happened at all.
- `e808e3e` (02.1) rewrote `ROI`'s docstring from the two schema fields it named
  to `CropRecord.region` and "a crop node's region parameter", because schema v1
  deleted the fields the old text pointed at. Correct, necessary, and outside
  the definition: it is neither an import path nor an ADR-1 rename.

Nothing was wrong with any of those commits. What is wrong is the inference two
todo items drew from the phrase. Both stopped at a wall — a guard that belongs
in `FrameCount.__post_init__`, a constructor that belongs on `FrameSpan` — on
the grounds that touching the file is a decision about what verbatim survives
to. The file had already left verbatim, quietly, under an item about a different
module, and the thing that would have said so is a check nobody re-runs.

The predicted-otherwise: if verbatim were enforced, 02.1 would have had to state
the docstring edit as a decision, and the two blocked items would have had a
live constraint to argue against rather than a lapsed one. Instead the
constraint's only remaining effect was to stall work.

So the terms, settled by the item that took this measurement and cited rather
than restated by anything downstream: **verbatim is a rule about how a port
lands, not a freeze on the file afterwards.** A decision may never ride along
with a port; a later item whose entire subject *is* the decision may change the
file, and says so where a reader of the file will meet it. What is gone is the
ability to re-verify the port by hash, and the honest statement is that it was
gone before this item, for a docstring, without anyone choosing to spend it.
