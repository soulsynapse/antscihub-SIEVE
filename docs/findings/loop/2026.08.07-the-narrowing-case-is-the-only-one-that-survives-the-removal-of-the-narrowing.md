# The narrowing case is the only one that survives the removal of the narrowing

This is not
[a test named for a semantic is the one nobody mutates](2026.08.07-a-test-named-for-a-semantic-is-the-one-nobody-mutates.md).
There the enumeration missed the semantic entirely. Here the semantic was
enumerated, the mutant was written, the suite went red — and the case bearing
the semantic's name sat in the green column while three strangers did the
killing. A reviewer reading only `3 failed` would have recorded the behaviour as
covered by the case that names it, which is the inference the count invites and
cannot support.

The mechanism is general and has nothing to do with `inspect`. A narrowing is
tested by asking it for something and checking what comes back. What comes back
is a superset under every interesting failure — a narrowing that narrows
nothing still returns the thing you asked for — so an assertion that looks only
at the requested item is satisfied by both behaviours. To see the failure you have to
count what you did *not* ask for, and the helper written to make the assertion
readable (`_line`, `_versions`, both keyed on `spec.tool_id`) is precisely what
makes that impossible. The helper is good; it is scoped to a block, and the
claim is about the set of blocks.

The second half is the uniform-fixture shape the review prompt already lists,
in an unusual place: the population being counted is registered versions, every
id has one, and so an equality between two counts is `1 == 1` ten times. The
tell that this was never exercised is that the case cannot survive the world it
describes — `_one`'s single-match assertion fires the moment a second version
exists. A case whose helpers would break under the condition it claims to test
has never seen that condition.

What would refute the framing: if some other case in the file asserted the full
listing's length or membership, the narrowing behaviour would be covered
deliberately rather than by three accidents, and this would be a naming
complaint. `test_every_tool_on_the_shelf_prints_every_emission_it_declares`
comes closest and runs against bare `sieve inspect`, which the mutant does not
touch.
