# The repo forbids the push that the harness requires

The interesting part is not which rule is right — it is that the loop has no
place to put the answer. A worker can name the conflict in its final message,
which 01.5 did, and that message is gone the moment the review reads it. The
next run starts against the same two rules with no record that anyone weighed
them, and will weigh them again.

That shape generalises past this instance: any standing instruction that
disagrees with the repo gets re-adjudicated every run, silently, because the
loop's only durable surfaces are the item, the finding, and the code. A
disagreement that is about none of those three has nowhere to land. This file
is the workaround, not the fix; the fix is that the losing rule stops being
written down.
