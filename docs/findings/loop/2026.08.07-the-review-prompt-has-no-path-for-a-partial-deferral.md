# The review prompt has no path for a partial deferral

The prompt's two branches are shaped by whether the run produced a commit:
"if the run made no commit, or deferred its item, its final message is the
thing under review." 01.2 did both. It committed 1,922 lines that pass every
gate, and it deferred on the one file the criterion named that it could not
build. The confirmed-contradiction branch then says amend and reopen, and the
amendment here deletes the only reason to reopen.

Reopening would not have been harmless-but-wasteful. `--next` serves the
lowest `open` step, so 01.2 would have preceded 01.3, and a worker handed an
item whose criterion already passes has two readings available: report it done
untouched, or find something to add. The second is the one the loop cannot
detect, and it is the shape this whole apparatus exists to avoid — a run with
a green criterion and an incentive to justify itself is how scope arrives
without an item asking for it.

The safeguard the branch is really protecting is that a reviewer must not
loosen a criterion until it passes. That is a narrower rule than "always
reopen", and it survives the split: the test is whether the amendment struck a
*subject* the item could not have built, or struck an assertion the item was
supposed to satisfy. Here the struck file's every case imports a module that
does not exist — the strongest available form of the first.

## 2026-08-09 amendment: a third case, where nothing was amended at all

09.7 (`173d535`, `the-outputs-reach-down-behind-the-cards`) is the shape this
file's open question asks about, arriving without the amendment that names it.
The criterion was never wrong: `-k reaches_down` was minted for the drawing and
the run built five cases that satisfy it. What was left unbuilt is a *body*
clause the criterion never reached — the port named at an arrowhead where a step
has more than one input — and it was unbuilt for the reason 01.2's struck file
was, that its subject does not exist in the tree. Schema v1's `Edge` carries no
port and `Pipeline` refuses the second inbound edge, so building it meant
inventing both the fan-in and the word beside it.

So the three-answer test this file's open question proposes — after the
amendment, is there work an ordinary work run could do — holds, but "after the
amendment" is the wrong hinge. There was no amendment. The hinge is whether the
residue is a subject the item could not have built, and whether some item
carries it: this review set `done` and folded the clause into 09.2, which
already owns the labeling. `open` would have served a work run a green criterion
and an incentive, which is the failure the body above already names.

The one thing this case adds that 01.2's does not: the residue was never
visible in `done_when`, so the reviewer's question is not "does the criterion
still bind" but "does the *body* have a clause the criterion never covered".
Nothing surfaces that except reading the item's prose against the diff. The
review that wrote the narrowing note in the first place could not have surfaced
it either, and was wrong about which clauses were in the residue —
[2026.08.09-a-reviews-partial-deferral-note-narrows-the-item-on-a-prediction-nothing-checks.md](2026.08.09-a-reviews-partial-deferral-note-narrows-the-item-on-a-prediction-nothing-checks.md).

## 2026-08-09 amendment: a fourth case, where the residue arrived by a fold

`the-stream-a-position-produces-is-resolved-not-declared` at `119fb2c` reached
this review with its criterion green and two residues, and the interesting one
is not the deferral. The worker's own residue — `_offer_over` still returning
`()` at the root — was handled the way the amendment above prescribes: it named
the subject, argued the root offer is the chooser's shape rather than the add
box's, and folded a paragraph into `the-source-is-a-card-in-the-walk`, which
already owned that distinction. Nothing about that needed the review to notice
it.

The second residue was already in the item before the work started. An earlier
session had *folded* the other half of VISION's scenario — a source param that
names a folder, several files ceasing to be an error, and window focus as a
re-read trigger — into this item's body, and said in the fold that `done_when`
did not reach it. So a clause the criterion never covered was sitting in the item
at the moment the criterion went green, and the only thing standing between it
and vanishing into a `done` file was that the fold had written down its own
non-coverage.

That is a residue-generator the three cases above do not have. A deferral is
announced by the run that defers; a fold is announced by a session that has since
ended, into an item some later run will close on a criterion that predates the
fold. CLAUDE.md's fold rule anticipates the gap and offers one remedy — "say in
your final message that the criterion may no longer cover the whole of it, so the
review can widen it" — and widening was the wrong move here. Widening would have
reopened a finished item to carry work that is a subject of its own, which is the
`open`-with-an-incentive failure the body above names. This review split the
folded half back out as its own item and closed the parent. The fold rule's one
remedy should be two, and which one applies turns on the same hinge the 2026-08-09
amendment found: whether the folded clause is a subject the item could have built.
That is Kendrick's edit to CLAUDE.md, not a reviewer's, so it is recorded here.
