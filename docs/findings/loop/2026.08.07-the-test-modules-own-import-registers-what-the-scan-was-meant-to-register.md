# The test module's own import registers what the scan was meant to register

The worker's four mutations were real and each killed exactly one test — that
part of the run holds, and it is the discipline
[2026.08.06-one-red-per-contract-certifies-the-contract-not-its-lines.md](2026.08.06-one-red-per-contract-certifies-the-contract-not-its-lines.md)
asked for. What the sweep did not contain was a mutation of `discover()`'s own
body, and that is where the vacuity is. The enumeration was drawn from the four
tests, so it found four ways to break them; the function they exist to prove was
never the subject.

The mechanism is ordinary import side effects, which is precisely why it is hard
to see. `@register_tool` populates `REGISTRY` when `sieve.tools.downsample` is
imported, by whatever route. Two of the four tests need `DownsampleParams` as a
fixture, so the module imports it at file scope, so by the time
`test_discovery_imports_no_tool_module` calls `discover()` the shelf is already
stocked. The assertion `"downsample" in {spec.tool_id for spec in discover()}`
is then true of a `discover()` that does nothing but read the shelf someone else
filled — which is the exact failure the test's own docstring says it was written
to catch, one level down: it warns against checking "that the registry ended up
populated" instead of the import list, and then does that as its last line.

This is a new entry for the vacuity list, distinct from the four the review
prompt carries: **a fixture the test file imports supplies the state the
subject under test was supposed to supply**. It generalises past discovery to
anything registered by import — kernels, codecs, any decorator-populated shelf.
The tell is that the assertion names a global container rather than the
function's own return path, and the file imports something that writes to that
container.

The prediction that would refute this: if `discover()` were the only route by
which `DownsampleParams` could reach the test process, the assertion would be
sound and the mutant would have failed. It did not — the mutant's `discover()`
returns `()` in a clean interpreter while the suite stays green, so the two
routes are genuinely independent and only one of them is under test.
