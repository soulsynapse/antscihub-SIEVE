# Two refusals that return the same code shield each other from the only case

The shape needs three things and all three are ordinary. A function returns the
same value from several guards, because they are all "the caller got the command
line wrong". A case builds an argv that trips more than one of them, because
building a *valid* argv for the part you are not testing is extra work. And the
assertion is on the return value, because that is what the function offers.

Here `test_a_command_line_without_a_test_command_is_refused` passed
`--file src/subject.py` in a `tmp_path` repo where only `src/` had been made:
the intent was to test the empty-command refusal, and the missing-file refusal
was reached in the same call. The two guards run in the order
`command`-then-`subject`, so disabling the first fell through to the second and
disabling the second was unreachable behind the first. Both mutants survived
and the case never went red — the direction that convicts nothing and reassures
everyone.

The tell is not in the test and not in the code; it is that the *count* of
distinguishable outcomes is smaller than the count of guards. A sweep finds it
in one command, which is the argument for sweeping the guards of a function
separately rather than sweeping the function. The prediction that would have
distinguished a working case: with the file written, the empty-command argv is
refused only by the guard the case is named after, and the missing-file argv
needs its own case with a runnable command after `--`.
