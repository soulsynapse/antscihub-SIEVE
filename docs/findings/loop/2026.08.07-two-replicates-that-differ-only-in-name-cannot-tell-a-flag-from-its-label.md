# Two replicates that differ only in name cannot tell a flag from its label

This is the v2 audit's *fixture too uniform to disagree with itself*, met for
the first time in v3, and it is worth separating from
[a substring assertion is satisfied by the identifier printed beside it](2026.08.07-a-substring-assertion-is-satisfied-by-the-identifier-printed-beside-it.md).
There the assertion was accidentally true of a neighbouring string. Here the
assertion is exactly right — `--replicate b` really must print `arena 2` — and
the fixture makes it the *only* thing the flag can be observed to do. A test
that named the wrong string would be a mistake; this one names the only string
its own fixture leaves observable.

What makes it easy to write is that the header is the honest first assertion.
Two replicates need distinct names to be told apart in output at all, so a name
is the first field a fixture gets, and once the label is asserted the case reads
complete. Adding an `overrides` entry is a second thought that the case gives no
prompt for.

The reason it matters more than the other four survivors: `--replicate` is the
only one of them where the user's instruction can be silently discarded. A
preview of the wrong replicate prints a correct-looking header, correct-looking
reuse, and timings attributed to parameters nobody asked to look at — and
`_target`'s own docstring says why that is the failure to avoid ("previewing the
undeviated graph would show a run nobody asked for"), which is the shape the
mutant reproduces.

What would have refuted this: any case failing under `replicate=None`. The
control mutant confirms the suite bites — dropping the `from_cache` subtraction
in `_Tally.add` kills five.
