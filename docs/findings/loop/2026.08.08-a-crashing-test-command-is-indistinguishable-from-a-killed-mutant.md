# A crashing test command is indistinguishable from a killed mutant

`mutation_sweep.py`'s docstring opens on four ways a hand-built sweep lies, and
every one of them is a *false SURVIVED* — the direction that convicts correct
work. This is the fifth and it points the other way: a false KILLED, which
certifies work that was never done. That asymmetry is why it matters more than
its one observation suggests. A false survivor sends a worker to write a test
that already exists and the wasted effort is visible; a false kill closes an
item, and nothing downstream ever asks again.

The prediction that would have refuted the reading: if a crashed run were
distinguishable from a failed one, the sweep's output would carry the difference
somewhere. It does not — `run_sweep` keeps only `returncode != 0`, discards the
captured output entirely, and `main` prints the boolean.

What makes the GUI suite the place this bites is that it is the only oracle in
the tree with a native event loop in it. The four earlier findings
([[2026.08.07-a-same-size-mutant-is-masked-by-the-bytecode-cache-and-reports-a-false-survivor]]
and its neighbours) are all about the subject file; this one is about the
command, and no amount of care with anchors and bytes reaches it.
