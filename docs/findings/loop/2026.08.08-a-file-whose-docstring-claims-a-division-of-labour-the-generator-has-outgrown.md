# A file's docstring claims a division of labour the generator beside it has outgrown

The shape is not "a comment went stale". It is that the stale sentence was the
only written record of a split between two files, so it was the thing a later
worker consulted to decide what its file owed — and consulting it was correct
practice. `tests/unit/test_import_contracts.py` predates the generator; when it
was written it really did hold the only proof that
`pipeline -> sieve.core.ops` could go red, against a copy of the tree with the
ADR-deferred package planted in it. `test_contract_lines_go_red.py` then landed
and generalised exactly that: the copy, the planted package, one red per line,
read out of `.importlinter` so a line added later is covered the day it lands.
The item that landed it named precisely what survived — the supported-path case,
which asserts what `allow_indirect_imports` leaves *legal* and has no generated
form. The docstring in the older file was not updated to match, and it is the
file a worker adding an edge opens first.

The prediction that would have refuted this reading: the generator skipping the
lines this file holds, by name or by contract. It does not — it takes the
`itertools.product` of every contract's sources and forbidden modules with no
exclusions, and `test_every_line_contributes_every_case_it_owes` exists
specifically to stop it silently dropping any.

What makes it invisible is that redundant coverage is green coverage. Every
gate the repo has passes on both files; `mutation_sweep` would find both cases
killing the same mutant and report a kill. The only signal is the collection
listing of two files side by side, which nothing in the loop asks anyone to
read. A reviewer re-running a criterion sees the criterion pass, and the
criterion here — `-k session` — selects the redundant cases among the ones it
certifies.
