# A folded item outgrows a criterion that cannot be widened to match

The fold rule is right and is what produced this. Every one of the six reviews
that added a section had a real observation about a module the item already
named the shape of, and minting six items would have paid the backlog cost the
rule exists to refuse. What none of them could do is widen a `done_when` that
is one shell command over one subject file, so each fold widened the item and
left the criterion where it was.

What makes this worth a file rather than a shrug is the direction it points.
The prompt's step 1 reads as a two-way branch — criterion passes, set `done`;
criterion fails, set `open` and queue the fix — and the passing branch is the
dangerous one here. A review following it literally would have closed an item
whose body carries fifteen surviving mutants, and nothing downstream ever asks
a `done` item anything again. The failing branch has no equivalent hazard: an
item wrongly left open costs a run.

The prediction that would have refuted this reading: if the criterion did bound
the item, the mutants named in the folded sections would mostly be dead by now
— killed incidentally by the six commits that followed. Fifteen of sixteen are
alive, and the one that died was killed by a *different* item's work
(07.12's), not by anything this item's criterion asked for.

## Amended 2026-08-09: a second instance, unwidenable for a different reason

`docs/todo/a-truncated-unpinned-set-is-pinned-and-duplicates-the-fast-class.md`
took a fold in the review of 12217da whose subject is a *measurement* — a
colour-path core-count sweep, owed because the `CORES_PER_WORKER` floor that
commit shipped rests on the mechanism rather than a reading below 16 CPUs — under
a `done_when` that is a unit test on the sweep command's axis. Widening is
unavailable here, but not for this file's original reason: it is not that the
harness takes one `--file` per invocation, it is that a reading produces a
finding and no command goes green for it.

The rotation this file settled still applies and the review recorded it in the
item. What the second instance adds is that the unwidenable case is not a
property of `mutation_sweep`, so the open question about accepting several
`--file`s would not have prevented it, and a fold rule amended only against that
script would miss this one.
