# A re-measurement explains a gap that one more pass of its own probe covers

The run did the hard part correctly. It moved a number out of a scratch probe
into the pass that takes the timings, proved red for both new tests, and mutated
each afterwards. Then it compared the new number to the old one, saw 0.25-0.30
where the hand probe had said 0.22-0.26, and wrote down *why the two methods
would differ* — an instrumented probe versus a subtraction over the samples an
ordinary pass already publishes. The sentence is plausible, which is the
problem: it is a mechanism proposed for a difference nobody had established was
one.

Establishing it costs one more run of the thing that was just committed. The
review did that and the range moved to ~0.22-0.30, straddling the number the
mechanism was invented to account for. Five samples of a quantity around a
quarter of a millisecond, taken once, do not resolve a 0.03 ms shift; two passes
of the same probe disagree by more than the two probes did.

The shape generalises past timings. A run that re-derives a value by a new route
has two candidate explanations for any disagreement — the route, or the
variance the old route never characterised — and it is holding the only cheap
discriminator between them, because the new route is committed and can simply be
run again. Reaching for the first explanation is attractive precisely when the
run has just finished arguing that the new route is better; the mechanism
flatters the work. The check is not "is this explanation plausible" but "does
the probe reproduce its own range".

Two things make this cheap to get right rather than a general demand for
replicates. The probe is committed by construction — that was the item — so a
second pass is one command. And nothing forces the run to explain the gap at
all: "0.25-0.30 against 0.22-0.26, and no attempt was made to say whether that
is the method or the noise" would have been an honest row, and a shorter one.

A negative result would have looked like this: the review's brackets landing
wholly above 0.26, with the minimum at or above the reported 0.25. Then the two
methods really would disagree, and the paragraph explaining why would have been
the right thing to write.

## Amended 2026-08-09: the same shape over a pass/fail, where the variance is invisible in one sample

Recurred at `8d5a300`, and the binary case is worse than the timing one rather
than milder. A work run added a GUI case that showed and activated a window, and
`tests/gui` reported every case passed and then exited `0xC0000409`. It ran three
comparisons — the file alone, the directory without the file, the case rewritten
to set activation without showing — each once, each exiting 0, and filed
[2026.08.09-a-shown-window-in-one-added-case-aborts-the-gui-run-at-exit.md](../2026.08.09-a-shown-window-in-one-added-case-aborts-the-gui-run-at-exit.md)
naming showing as involved. The abort was a player held to interpreter exit,
present in the tree before that case existed and measured at 3 of 10 full runs
nonzero on the same commit
([2026.08.09-a-player-held-to-interpreter-exit-fail-fasts-the-process-on-a-green-suite.md](../2026.08.09-a-player-held-to-interpreter-exit-fail-fasts-the-process-on-a-green-suite.md)).
Every green run it read as a difference was the likelier outcome of changing
nothing.

Why the pass/fail case is the harder one. A timing hands over its own spread —
five samples printed a range, and the range was the discriminator the run was
already holding. A crash at process exit hands over one bit, so a single run
carries no evidence at all about its own variability, and there is nothing on the
screen to prompt the question. The run then did the honest thing in the wrong
direction: it named its falsifier in advance — "what would refute this is the
abort surviving the rewrite" — and accepted one green run as having passed it,
which turns a good habit into a laundering step.

The discriminator is still the cheap one and it is still the same discriminator:
run it again. `tests/gui` is seconds; three runs of the *unmodified* tree would
have shown the abort with no case added, and that is the measurement the whole
attribution rests on — the base rate of the thing you are about to explain,
taken before you explain it. The rule the review prompt already states for a
disagreeing criterion ("run it at most once more; if the two passes differ, stop
there") is the same discipline read from the other end, and nothing states it on
the work side: a worker meeting an intermittent failure has no instruction that
its first sample is not a reading.

A negative result would have looked like this: the unmodified directory exiting 0
across several runs while the directory with the new case aborts across several.
Then showing really would have been implicated, and the paragraph naming it would
have been the right thing to write.
