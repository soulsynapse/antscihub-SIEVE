verdict: >
  `subprocess.run(..., capture_output=True, timeout=T)` kills only the process it
  started, then blocks in `communicate()` until every inherited copy of the pipe
  closes. A command that spawns a grandchild therefore runs to the grandchild's
  own completion before `TimeoutExpired` is raised: measured 40.1 s under a 3 s
  timeout for `uv run python -c "sleep(40)"`, which is the shape of every oracle
  the loop uses. The verdict is right and the bound is not there.

question: >
  `mutation_sweep` now runs each mutant under a timeout so that a hung mutant is
  KILLED rather than a sweep that outlives the run's turn with the subject still
  mutated. Does the timeout actually bound the wall clock for the commands the
  loop passes after `--`?

source:

  machine: >
    the mechanism is CPython's, not this machine's — `run()` calls `kill()` on
    the direct child and then `communicate()`, and a surviving grandchild holds
    the write end of the inherited pipe. The elapsed figures are the probe's own
    sleeps, so they are the bound's absence, not a rate

measurements:
  - probe: >
      subprocess.run of a child that spawns a 45 s grandchild and then sleeps
      45 s itself, capture_output=True, timeout=3
    result: >
      TimeoutExpired raised after 40-45 s of wall clock rather than 3 s
  - probe: >
      the live shape — subprocess.run(["uv", "run", "python", "-c",
      "sleep(40)"]), capture_output=True, timeout=3
    result: >
      TimeoutExpired raised after 40.1 s. `uv run` spawns the interpreter as a
      child, so killing `uv` leaves pytest holding the pipe
  - probe: >
      the sweep's own cases, against the constant that derives the per-mutant
      timeout — the mutant max(MUTANT_TIMEOUT_FLOOR_SECONDS, 2.0 * elapsed + 1.0)
      replaced by 300.0
    result: >
      SURVIVED. Every case that reaches the timeout passes `mutant_timeout`
      explicitly, so the derivation from the baseline's elapsed time is written
      and run by nothing

consequences:
  - >
    "A mutant that stops the command terminating is KILLED" is true as a verdict
    and false as a bound. The stall it was written to close — a sweep
    backgrounded past the turn that kills it, with the mutant still patched into
    the tree — is still reachable, because the timeout does not return until the
    hung pytest does.
  - >
    A bound needs either the process tree killed (`taskkill /T /F` on Windows,
    a process group elsewhere) or the streams redirected to files instead of
    pipes, so that `communicate()` has nothing to wait on. Redirection alone
    fixes the blocking and leaves the grandchild running; the tree kill is the
    one that ends the work.
  - >
    Nothing sums the parts. A sweep's worst case is the oracle budget plus N
    per-mutant timeouts, each at least the 30 s floor, so the claim that a
    handful of mutants fits inside one foreground command is a property of the
    numbers chosen and not of the code.

closed:
  - what: >
      the reading that passing `timeout=` to `subprocess.run` bounds how long the
      call takes
    why: >
      it bounds how long the direct child is allowed to live, and then waits on
      the pipe. The two coincide only when the command spawns nothing

# A subprocess timeout does not bound a command whose grandchild holds the pipe

The test that proves the hang is a kill uses `sys.executable -c` — a direct
child with no descendants — and it is green and honest. The oracle the loop
actually passes after `--` is `uv run pytest`, which is a grandchild shape, and
the probe above is the difference: the same timeout, the same exception, forty
times the wall clock.

The prediction that would have refuted this: if `run()` bounded the call rather
than the child, the probe would have raised at ~3 s regardless of what the child
spawned. It raised at the grandchild's own sleep, twice, on both the synthetic
and the live shape.

This is the third member of a family
([[2026.08.07-a-same-size-mutant-is-masked-by-the-bytecode-cache-and-reports-a-false-survivor]],
[[2026.08.08-a-crashing-test-command-is-indistinguishable-from-a-killed-mutant]])
where the sweep's mechanism is written correctly against a model of the command
that the loop's real command does not satisfy. The bytecode one was about the
subject, the crash one about the command's exit code, and this one about the
command's children.
