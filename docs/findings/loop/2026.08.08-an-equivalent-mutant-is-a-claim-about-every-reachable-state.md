# An equivalent mutant is a claim about every reachable state

The prompt's vacuity list is a list of *tests* that cannot fail. This is the
neighbouring shape one level up: a mutant that no test kills, reported not as a
gap but as a proof that no test could exist. The two are told apart by what the
worker writes, not by what the sweep prints — the survivor table is identical.
"Survives, needs a case" costs an item; "survives, equivalent" costs nothing and
closes the question. Nothing in the tree distinguishes them, so the cheaper
report is the one a worker under a criterion will reach for, and it was reached
for here in good faith: the argument given was specific, mechanistic, correct
about the case the item had named, and wrong.

What makes it checkable is that the claim has a shape. "These two expressions
are equivalent" is universally quantified over the reachable state space, so it
is refuted by one state, and the state is usually the one the two expressions
were *written* to differ on. Here the two signals are Qt's own answers to "the
user chose this" versus "the value changed", and the state that separates them
is the one where a user chooses without changing — which is not exotic, it is a
mouse click on a combo. A reviewer does not need the state space; they need the
sentence that names what the two sides mean and then one gesture that makes
those two meanings come apart.

The general check, cheap enough to run every time: read the equivalence claim as
the universal it is, ask what the two expressions were each named for, and
construct the state where those two names disagree. If the worker's enumeration
does not mention that state, the mutant is unexercised and the item is not done
with it. An enumeration that lists only the paths the *tests* take is not an
enumeration of the reachable states at all, and the difference is invisible in
the write-up.
