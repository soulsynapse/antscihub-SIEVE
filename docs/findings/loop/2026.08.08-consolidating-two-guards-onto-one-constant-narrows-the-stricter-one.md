# Consolidating two guards onto one constant narrows the stricter one

The commit's own message states the equivalence — "the checkpoint writer keeps
its guard but stops spelling its own pattern" — and it is true for every
character either author had in mind. `../escape`, `a/b`, an embedded newline: all
refused before and after. The one input the two spellings disagree on is a *final*
newline, and Python's `$` was never a shorthand for `\Z`; it is a shorthand for
`(?=\n?\Z)`. The deleted constant had `\Z` written on it deliberately, and the
constant it was replaced with had `$` written on it by analogy with
`TOOL_ID_PATTERN`, which guards a cache key rather than a path.

What makes this a loop shape rather than a typo is that nothing available to the
worker could have gone red. The mutation sweeps kill every mutant, including a
sweep of the pattern literal to `r".*"` — the guard is real and its tests reach
it. Full suite green, ruff green, criterion green. The defect lives in the gap
between two rules, and a suite only ever holds cases for one rule at a time: the
old writer's tests asserted refusals inside the intersection, and the new schema
tests were written after the merge and so inherited the merged rule as their
definition of correct. The green is not a false green about the guard; it is a
true green about a rule nobody compared to the one it replaced.

The check that would have caught it costs one command and does not need the
suite: match both patterns against the same handful of strings and look for a
disagreement. Any commit that deletes a regex, a threshold, a comparison, or a
default and points its caller at an existing one owes that diff of *behaviour*,
not of text — the two spellings will usually look alike, which is why the commit
was written in the first place.

## Closed at the schema, 2026-08-08

`NODE_ID_PATTERN` anchors `\Z`, and the case the item's criterion selects gained
the trailing-newline id in both routes — a direct `Node` and a `from_yaml` whose
quoted scalar carries the newline. Red first for the reason predicted below
(`DID NOT RAISE ValidationError`), green after. The sweep that says the suite now
holds the difference rather than the intersection: mutating the constant back to
its `$` spelling against `tests/unit/test_pipeline_model.py` and
`tests/integration/test_checkpoints.py` is **KILLED** — the mutant this finding
exists because nothing could kill.

The separate question in `consequences` above — whether the `$` in
`TOOL_ID_PATTERN` and `SEMVER_PATTERN` is reachable — is now answered and the
answer is yes, from a document. A project whose `tool_id` is the double-quoted
scalar `"downsample\n"` and whose `version` is `"1.0.0\n"` loads clean and keeps
both newlines; a *bare* newline inside a quoted scalar folds to a space and is
refused, so it takes the escape to write one, which is what a hand edit is. The
consequence differs per field and neither is a path: `tool_id` misses the
registry and refuses with a message whose two spellings look identical on a
terminal, and `version` reaches `SEMVER_PATTERN.match(...).group()` in the cache
key, so one tool version keys two entries. Carried to
`todo/two-ids-anchored-with-dollar-take-a-trailing-newline-from-a-document.md`.

The review re-ran both halves per call against a locally reverted `$` and both
are red: the direct `Node` fails `DID NOT RAISE`, and the `from_yaml` document
loads with `node_id == 'abc\n'`, which is the assertion the worker's single quote
of red could not have reached. `status` moves to `closed` here — both
consequences above have been acted on, one in the code and one into an item.

## Closed at the other two constants, 2026-08-08

`TOOL_ID_PATTERN` and `SEMVER_PATTERN` now anchor `\Z` as well, so the class of
whole-string id patterns in `core` — the three of them, and the grep for
`re.compile` finds no fourth — no longer holds a spelling that admits a trailing
newline. The case is `test_a_tool_id_or_version_ending_in_a_newline_is_refused`,
both fields by both routes: a direct `Node`, and a document whose quoted scalar
carries the escape. Red first with `DID NOT RAISE ValidationError`; sweeping each
constant back to its `$` spelling against `tests/unit/test_pipeline_model.py` is
**KILLED** for both.

The question the item left open — whether the honest fix is broader than two
constants, since "a rule tested per-constant is the shape that let the first one
through" — resolves against a class-level test, and the reason is that no such
test exists to write. A test iterating a hand-written tuple of the three patterns
is per-constant testing in a loop: the fourth constant is absent from the tuple
for exactly as long as it is absent from anyone's mind. A check that could see it
would have to read the module's source for `re.compile` and judge the literal,
which is a lint rather than a case, and this tree has no lint that reads Python
as text. What generalises here is not a test but the finding above: a spelling
adopted by analogy owes a diff of behaviour against the thing it was analogous
to. That check is the same command whether the class has three members or ten.

The prediction that would have distinguished a working change: with the writer's
old `\Z` still in force, a project hand-edited to `node_id: "abc\n"` is refused
with the id named. Today it loads clean, plans, and reaches `open_memmap` with a
file name containing a newline — an `OSError` on Windows, and on POSIX a real
file whose name breaks every shell quoting rule the field's own docstring says
it must not depend on.
