# The tree is half LF and two durable instructions still call it CRLF

The rule this cost is `CLAUDE.md`'s "Mutation testing is
`uv run python scripts/mutation_sweep.py`, never a scratch harness", and the
interesting part is why a reviewer talks itself out of it. Neutering two
branches to prove four tests can fail does not feel like a *sweep* — there is no
enumeration, no survivor table, nothing the harness's ceremony is obviously for.
So the work gets hand-rolled, and the reviewer writes the patch from the other
sentence in the same file: the working tree is CRLF, match through bytes.

That sentence is where the tree moved and the instruction did not. It was true
when it was written; it is now true of 64 files and false of 60, and the file
under review was on the false side while its dependency was on the true one. A
hand patch is anchored per file, so it does not get one answer — it gets one
answer per subject, and the reviewer has to notice mid-review that the rule it
was handed cannot be applied uniformly.

`mutation_sweep.py` already absorbed this. `_match_eol` translates an anchor's
`\n` to `\r\n` only when the data it is matching against contains `\r\n`, which
is the conditional form: it does not know or care what the tree is, only what
the file is. Four anchors written in one spelling landed correctly across both
subjects. The knowledge that made the sanctioned harness right is not restatable
as a fact about the tree, which is exactly why "never a scratch harness" has to
hold for a two-line neuter as much as for a twenty-mutant sweep — the harness
is not carrying rigor here, it is carrying a conditional the instructions state
unconditionally.

The near neighbours are
[a mutation harness restores the bytes and not the line endings](2026.08.07-a-mutation-harness-restores-the-bytes-and-not-the-line-endings.md)
and
[git checkout restores the content and rewrites the line endings under autocrlf](2026.08.07-git-checkout-restores-the-content-and-rewrites-the-line-endings-under-autocrlf.md),
and this is the third of the same family: each found a hand-rolled restore or
patch step that a remembered platform fact made wrong. Those two were absorbed
into the harness. This one is not absorbable — the harness is already correct —
so it lands on the sentence instead. A durable instruction that quotes a
tree-wide value cannot be made right by the tool it points at, because the
failure happens in the session that decides not to reach for the tool.

What would flip this: a `.gitattributes` line normalising `*.py`. Then the CRLF
claim becomes true again and this finding is a note about a window rather than a
standing hazard. Until then the sentence is wrong for half the files a session
will open, and it is wrong in the direction that produces a silent miss rather
than an error — a `data.count(anchor)` of zero is a mutant that never applied,
which reads identically to a test suite that has nothing to say.

## 2026-08-09 — it recurs outside `src/`, and the docs half is LF too

08.3's worker hit the same sentence on a different kind of file. Editing
`status: open` in a `docs/findings/` markdown file, it wrote the byte patch
`b"status: open
"` from `CLAUDE.md`'s claim, and the guarding assertion
fired; the LF spelling applied. The item file it edited a minute later *was*
CRLF, so the same session met both halves again — this time in `docs/`, which
the original probe never counted.

Two things follow. The split is not a property of the Python tree: the probe
above measured 124 `.py` files, and the sentence a session actually reaches for
is tree-wide, so the ratio it should be judged against includes `docs/`. And the
sanctioned-harness escape does not exist here — `mutation_sweep.py` is for code,
and a frontmatter edit has no tool holding the conditional, so the only defence
is the shape the worker eventually used: read the file's own bytes and branch on
what is in them. That is the standard the sentence should state, and until it
does this will keep costing one failed call per session that tries.
