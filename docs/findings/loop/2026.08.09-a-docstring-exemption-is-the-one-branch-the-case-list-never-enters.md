# A docstring exemption is the one branch the case list never enters

The near miss is what makes this worth recording. The commit does have an
element case —
`test_offering_drops_the_tool_whose_elements_would_lose_their_meaning` — and it
is a good one: it moves `element` between `PIXEL` and `BLOCK` and asserts the
aggregator appears under one and not the other, which is the leg's whole point.
It just never passes the third value the parameter is annotated to accept. The
one case that does pass `None` pairs it with a `TableSpec`, where the array
tools are already refused by `match_slack` and the element leg is unreachable —
a fixture too uniform to disagree with itself, in a variable other cases vary
correctly.

The reachability is not hypothetical. `node_element`'s own docstring says `None`
"propagates and never recovers", so a pipeline with an aggregator over blocks in
it makes every downstream position an element-less one. The add-tool box there
would be empty — the same user-visible symptom as
`findings/2026.08.09-the-shelf-declares-too-little-for-eight-of-ten-positions-to-offer-anything.md`
measured for a different and legitimate reason, which is the second thing that
would have hidden this: the wrong behaviour and the right one look identical
from the GUI, and the finding already sitting in the tree explains the empty menu
before anyone asks whether this leg caused it.

What would have refuted this reading is the docstring hedging — if it had said
"a `None` refuses what cannot survive it" the code would be an implementation of
the sentence rather than its negation, and the gap would be prose imprecision
rather than a defect. It does not hedge: "a `None` refuses nothing … not one
where every tool is implausible" is the exact case the code implements.

## Amended 2026-08-09: the code consequence is discharged, the loop question is not

`77e5182` took the code side of the item's fork — the element leg is skipped
entirely at `element is None` — and the review re-ran the probes above. The
array side of the `None` branch is red at `[] == ['aggregator', 'narrow',
'wide']` against the reverted clause and green with it, so the branch this
finding named now has a case. `status` stays `open`: what this file's
`question` asks is the loop question, not the code one, and nothing in the loop
yet reads a diff for its "refuses nothing" sentences.

Re-measuring the ten-position table in
`findings/2026.08.09-the-shelf-declares-too-little-for-eight-of-ten-positions-to-offer-anything.md`
against the fixed predicate returns it unchanged — offers of 2, 2, 2 and seven
zeros, same tools. That is expected and worth stating: `node_element(decl,
PIXEL)` is `None` only for a table emitter, so no depth-one position on the real
shelf reaches the branch. The element-less position needs two hops
(`block_signal` → `downsample` or `rescale`, the shelf's only `AGGREGATED`
tools), and `matches` does not itself offer that edge, so no add-tool box on
today's shelf renders differently either side of the fix. The defect was real
and the input reachable through `admits`-legal construction; it was not yet
visible in the GUI, which is a third reason nothing went red for it.
