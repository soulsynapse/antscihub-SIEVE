# A proof of red is red for the harness and reads as red for the defect

The vacuity shapes this loop has collected are all about green: a case that
cannot fail, a mutant killed by the oracle's own crash, an invariant with no
implementation to break it. This is the other end. The work run under review
wrote its case, ran it against the unfixed tree, watched it fail on exactly the
assertion the item named, fixed the defect, and watched it fail again — twice —
before finding that the key it was sending was bound as a window shortcut and
never reached the combo. Both reds are `assert not window.graph.is_stale`. One
is the defect announcing a write that did not land; the other is the walk
redrawing. Nothing in pytest's output distinguishes them, and nothing in the
criterion could.

What separated them was a signal neither the item nor the assertion mentions:
`ParamForm.edited` fires on the defect's path and is silent on the walk's. That
is the general shape of the remedy — the artefact and the defect agree on the
case's own assertion and disagree somewhere upstream of it, so attribution is an
observation at the point where they part, not a second run of the same
assertion.

The prediction that would refute this as a general concern: if a harness
artefact reliably produced a *different* failure — a timeout, an exception, a
different line — then the target assertion failing would carry the attribution
by itself. It does not, because the assertion reads a state the whole surface can
reach. Any surface with a dispatch layer between the gesture and the subject has
this property.

The case as shipped is attributable, and by a construction worth keeping: it
drives the same combo twice, once with a value the document already holds and
once with a real change, and asserts the absence of the mark and then its
presence. A stolen key breaks the second half, so the pair fails loudly in
exactly the case where the first half alone would pass for nothing.
