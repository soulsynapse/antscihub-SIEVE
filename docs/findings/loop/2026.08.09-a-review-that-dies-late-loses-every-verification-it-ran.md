# A review that dies late loses every verification it ran

The shape is specific to reviews and not to workers. A worker's run leaves code
and tests behind and can be resumed from what landed; its intermediate state is
the tree. A review produces one commit — a status byte, a regenerated index, a
findings file — and produces it last, after all the reading that justifies it.
Everything before that commit lives only in the transcript, where the next
review can read it but is told, correctly, not to trust it.

So the cost of a review dying is not proportional to how far it got. It is
total, and it is worst for the review that got furthest, because that is the one
that spent the most to learn what it can no longer say. The successor here paid
for the same criterion run and the same mutant a second time and reached the
same answer, which is the cheapest possible version of the loss and still a
third of a run.

If this were about the items, the failed review would have stalled somewhere
early — an unreadable criterion, a diff it could not attribute. It stalled at
the end, holding a green criterion and two killed mutants.
