# A review widens with the shape a loop finding had already closed

The prior finding is not subtle and not old: it was committed the same day, it
names the exact command form, and its consequences section says in as many words
that a criterion *widened* with `-k` is prose rather than a criterion. The
review that then widened one had read the directory it sits in.

What that says is where the blind spot is. The review prompt's checks all point
outward — at the transcript, at the diff, at the tests, at the pools — and the
one artifact with no check on it is the review's own edit, which is also the only
edit in the loop that nobody downstream reviews. A worker's `done_when` is
re-run by a reviewer; a reviewer's `done_when` is re-run by the next worker, who
takes it as the specification and has no standing to doubt it.

The prediction that would have refuted this as a loop failure rather than a
one-off slip: had the widening been written by a session that never read
`findings/loop/`, the remedy would be to make it read. It did read, and wrote a
paragraph justifying the shape the directory had already ruled on — so the gap
is not access to the lesson but the absence of any moment where the lesson is
turned on the reviewer's own line.
