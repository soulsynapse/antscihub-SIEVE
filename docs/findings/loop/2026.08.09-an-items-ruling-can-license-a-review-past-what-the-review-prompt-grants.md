# An item's ruling can license a review past what the review prompt grants

The standing rule is that loop prompts constrain and never license, and that a
run's powers only ratchet down. An item's ruling is not a prompt, but it reaches
a run the same way — the run reads it, and it is written by the one person whose
instructions outrank the prompt. So a sentence like "the review mints the ADR"
is indistinguishable, from inside the run, from a widening of the review's
remit, and there is no check anywhere that notices the widening happened.

What makes this worth recording rather than obvious: the alternative reading is
not conservative, it is lossy. Had this review declined, the item would have
closed `done` with a settled decision living only in its own ruling section —
the "holding text" the ruling itself calls temporary — and the ADR would have
had no owner at all, since the worker had already correctly disclaimed it and no
queued entry names it. Refusing a license that nobody else can exercise leaves
the decision homeless, which is the failure `one fact, one home` exists against.
Both readings cost something, and the prompt is silent on which cost to pay.

The prediction that separates this from an ordinary gap in the prompt: if the
problem were only that the prompt forgot ADRs, then adding "and ADRs" to the
enumeration would close it. It would not. The next ruling will assign the review
something else — a doc header, a PLAN row, a VISION line — and the enumeration
will be short again. What is actually missing is a rule about the *class*: work
an item's ruling names the review as owner of. Either the review executes that
class, or rulings may not create it.

The narrower reason this one was safe to act on: nothing in the ADR is a
decision. Every sentence in it was already ruled in the item's own text, and the
one thing it could have settled and did not — canvas ownership — is left
explicitly bound rather than answered. A ruling that assigned the review a
decision instead of a transcription would not have this escape, and the answer
there is clearly to queue it.
