# A case whose oracle is talkative at the baseline is refused before any mutant is scored

The loop shape, stated without the subject: a case written from an item's own
sentence inherits the sentence's silence about *which invocation* the mechanism
fires on. `run_sweep` invokes its oracle once per sweep on the original bytes
and once per mutant; the item's rotation says a full pipe buffer makes a mutant
score KILLED, and the case supplies a command that fills the buffer — but a
command supplied to `run_sweep` is supplied to both invocations, and the earlier
one wins. The red is real and the line is covered; the *reason* recorded beside
the red belongs to a different invocation than the one that produced it.

What the refuted reading would have produced: a failure whose message is an
assertion on `[killed for _, killed in results]`, `[True] != [False]`. What
actually comes back is `SweepError` from the baseline, three frames above the
assertion, which the run log's "1 failed" summary does not distinguish from it.
That is the second half of this: red was shown by sweeping the line rather than
by reverting an implementation, and a sweep reports KILLED for *any* red, so the
sweep could not have told the two failures apart either. A proof of red through
a tool whose alphabet is {KILLED, SURVIVED} cannot check that the red is the
red the case is named for — the case has to be run directly at least once, and
its failure message read.

## Amendment 2026-08-10: the asymmetric oracle reaches the verdict, and it was read directly

`test_an_oracle_talkative_only_on_the_mutant_is_not_scored_killed` lands: the
oracle exits 0 immediately while `limit = 100` is in the subject and writes 1 MiB
to each stream once the mutant has removed it. The refutation this file asks for
was run outside the sweep's alphabet — `run_sweep` called in-process with
`_run_bounded` replaced by a `PIPE` twin of itself, `SweepError` caught and
printed distinctly from the verdict — and it returned `[True]`, a scored KILLED
against a mutant whose true verdict is SURVIVED. The baseline is green in that
run, so no refusal fires and the false KILLED of the item's title is reached for
the first time by a case rather than by argument.

Through the sweep, the same case turns red on the combined redirection mutant and
on each of `stdout=out,` and `stderr=err,` alone (three KILLED, zero SURVIVED),
which is the capacity result unchanged — but the sweep's red is not what
establishes the mechanism here, and on this file's own reading it could not have
been.
