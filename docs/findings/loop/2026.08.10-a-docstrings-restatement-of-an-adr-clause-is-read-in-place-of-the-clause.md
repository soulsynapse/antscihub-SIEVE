# A docstring's restatement of an ADR clause is read in place of the clause

Every mechanism the loop has for catching a wrong claim was pointed at the code.
The criterion ran, the revert proved the case could fail, the suite was green,
the goldens were argued, and the item's own body was the thing that carried the
error into the run — so the run had no reason to reopen the ADR at all. The
review caught it only because re-reading the ADR's exclusion clause is what
step 4 makes it do to check the diff against the item's scope.

The near miss worth naming: the run's own amendment is careful, measured, and
correct about the behaviour. It renames a directory to isolate the path field
from mtime, it prices the result against `source_identity`'s docstring, and it
warns the next reader off the wrong claim. All of that is right. The single
sentence it gets wrong is the one it inherited — that the ADR asked for the
thing it measured missing. A finding this well-built is exactly the kind that a
later session cites rather than re-derives, which is what makes an inverted
clause inside one expensive rather than merely wrong.

The distinguishing test for the shape, cheap enough to run every time: when a
document is cited for something it *forbids*, check that the sentence being
leaned on still has its polarity word attached. "Neither X nor Y" and "X and Y"
differ by one word that a faithful-sounding paraphrase drops for free.
