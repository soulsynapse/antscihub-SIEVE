# A repointed item's head and its own dated section ask for different things

`a-mint-lands-wherever-the-app-was-launched.md` was repointed under ADR 35 on
2026-08-09. Its rewritten head says NEW PROJECT is "a file dialog whose answer
is the path the empty document is written to" — a save dialog, which takes the
document's *name* from the user. A section lower in the same file, written by
the same repointing session, says the `mint` docstring's no-name argument "is
still true about the *name* — the ask is for a location, and the name comes from
it" — a folder picker, which leaves the name to `mint`'s `untitled_N`. The two
readings produce different dialogs, different `mint` signatures, and different
answers to whether `mint` is touched at all.

Nothing in the loop can see this. `done_when` names two test names that do not
exist yet, so it is red under either reading and green under either
implementation. The doc index checks frontmatter, not whether an item's prose
agrees with itself. The selector hands the item to a worker on its `status` and
`gated_on` alone.

What kept it cheap was the worker: it named both readings, argued the folder
one from specificity and from the ADR's own arithmetic — a source path is stored
relative to the document's *directory*, so a directory is what the ADR needs —
implemented that, and wrote the fork onto the item as a dated section pointing
out that a save dialog remains reachable by editing `ask_where` alone. The
review re-ran the criterion and agreed. The failure mode this avoids is the
worker picking the reading that is easiest to implement and saying nothing,
which leaves a settled-looking item whose head still describes the other design.

The generalisable shape: a repoint is a rewrite of the head *plus* a record of
why, and the record is written from the old item's vocabulary while the head is
written from the ADR's. Where the ADR is coarser than the item — ADR 35 rules on
*whose* the location is and not on what widget asks — the two can land on
different sides of a distinction neither document names. A worker meeting an
item whose head and dated sections disagree should treat the more specific
statement as the ruling, say so on the item, and name what a reversal would cost.

## 2026-08-10 amendment: it recurs without a repoint, and a review's arbitration is not the ruling

`the-canvas-shows-the-result-over-the-input.md` reached the same state by a
different route, so the shape is not the repoint's. Its head paragraph 1 ("a
source step shows its result alone") and paragraph 3 ("at a root the input is
`result.source`") disagreed from minting. A review met the disagreement, named
both readings, arbitrated for paragraph 3 in a dated section — "that reading
stands" — split the multi-root residue into a child, and closed the item `done`.

Two things the original file did not say. First, the arbitration a review writes
into a dated section can be wrong on the merits and still look settled:
`adr/the-walked-step-owns-the-canvas.md` contains paragraph 1's sentence
verbatim ("A source step has no input, so its composite is its result alone"),
so the fork was never the item's to arbitrate and the review's ruling was a
preference stated where a binding one already existed. The advice to "treat the
more specific statement as the ruling" is only the tiebreak of last resort; the
ADR the item cites in its own first line comes first, and both readings of a
self-disagreeing item should be checked against it before either is written down
as standing.

Second, the reversal leaves no mark. The child run (`ee5420c`) implemented
paragraph 1 correctly and cited the ADR, but the parent was `done` and nothing
requires a closed item to hear that the reading it certified has been repealed —
its head and its first dated section would have gone on asserting the transport
proxy indefinitely. The review that closes a child written to hold a parent's
fork owns writing the outcome back onto the parent; a dated section there is the
whole cost, and without it the tree's most-read account of a decision is the
losing one.
