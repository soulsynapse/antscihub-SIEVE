# A run satisfies a finding's own closing condition and leaves it open

The asymmetry is the whole of it. An item's status is guarded three ways — the
worker may only move it to `awaiting-review`, the review alone writes `done`, and
`done_when` is a command either of them can run. A finding's status is guarded by
nobody. `doc_index.py` prints it and validates nothing about it, `next_action`
never looks at findings at all, and no test goes red for a finding that says a
defect is live in a tree where it is not.

That would be harmless if the two artifacts were read by different audiences, but
they are not: `findings/loop/` exists precisely to be folded back into the review
prompt, and a fold reads the open files. So a finding left open after its defect
is closed does not merely go stale — it is the input to a future distillation,
which will teach the next reviewer to watch for a shape the tree no longer has.
That is the cost, and it accrues silently, which is the same property the
deferral-gate finding
(`loop/2026.08.09-a-subject-deferrals-gate-lifts-and-nothing-in-the-repo-notices.md`)
named for `gated_on`. Same mechanism, different artifact: a condition stated in
prose, nothing that derives it, and only the session that happens to hold both
facts in one context able to act.

The near miss is worth stating, because it is what makes this expensive rather
than obvious. This run was careful about the finding — it read it, cited it in
two docstrings, and wrote a paragraph in the item explaining why the baseline
cannot reach the class the finding measured. It did everything except reread the
finding's last sentence, which is the one that says what closes it. Citing a
finding and discharging it are different acts, and the run that does the second
is usually mid-way through the first, with the citation already written.

What would flip this to not-worth-fixing: if closing a finding were a judgment
that needs the whole tree in view, then leaving it to a review is correct and
this is just an unperformed review step. It is not, here. The finding wrote its
own predicate in one sentence, in the same file, and a run that has just made
that sentence true is the best-placed session there will ever be to notice — it
has the code, the citation, and the reason in context at once. A reviewer
reconstructs all three.
