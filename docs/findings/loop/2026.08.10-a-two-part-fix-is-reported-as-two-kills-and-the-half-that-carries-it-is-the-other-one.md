# A two-part fix is reported as two kills and the half that carries it is the other one

`57658c4` replaces `subprocess.run(capture_output=True, timeout=T)` with
`_run_bounded`, and describes the replacement as two departures that are each
necessary: the streams go to files, and the timeout kills the process tree. The
bound is real and the item's criterion is green. One of the two attributions is
not.

The measurement it is built on
([[2026.08.08-a-subprocess-timeout-does-not-bound-a-command-whose-grandchild-holds-the-pipe]])
is about `run()`, which kills the direct child and then blocks in
`communicate()` until every inherited copy of the write end closes.
`_run_bounded` does not call `communicate()`. It calls `Popen.wait(timeout=...)`,
which waits on the process handle and never touches a pipe, so it returns on
time whatever the streams are. Substituting `subprocess.PIPE` for the two file
handles therefore changes nothing the two new cases can see, and the sweep says
so: SURVIVED.

The reverse of this is the part worth keeping. Because nothing drains the pipes
— there is no `communicate()` and no reader thread — a PIPE oracle that writes
more than the buffer holds blocks in its own `write`, never exits, and is timed
out and scored KILLED. That is a false KILLED on a *correct* mutant, which is
the class this whole item exists for, and `uv run pytest -q` on a red baseline
clears a 64 KB buffer without effort. So redirection is load-bearing; what it
buys is capacity, not promptness, and the code says promptness.

The shape for the loop, beyond this file: "both halves are load-bearing" is two
claims, and a sweep answers it only if each half has a mutant whose replacement
is written out in full. The report here quoted one of them as
`stdout=subprocess.PIPE, ...` — an ellipsis a later reader cannot re-run, which
is how a verdict nobody can reproduce reaches a durable finding intact. A
mutant in a report is a command or it is prose.

Two things that were checked and are not the explanation. The subject restored
byte-exact and `git status` was clean either side of the independent sweep, so
this is not [[2026.08.08-a-restored-sweep-subject-came-back-mutated-after-the-sweep-had-exited]].
And the criterion itself re-ran green from a clean tree at `57658c4`, twice
counting the worker's, so the disagreement is about which line earns the green,
not about whether it is green.

## The capacity half now has a case, and each stream carries it alone (2026-08-10)

`test_an_oracle_whose_output_outgrows_the_pipe_buffer_is_scored_by_its_exit`
runs an oracle that writes 1 MiB to each stream and exits 0, and asserts the
mutant it sweeps SURVIVED. Against it the redirection is killed three ways over
`scripts/mutation_sweep.py` — `stdout=out, stderr=err ==> stdout=subprocess.PIPE,
stderr=subprocess.PIPE`, `stdout=out, ==> stdout=subprocess.PIPE,`, and
`stderr=err, ==> stderr=subprocess.PIPE,` — 3 killed, 0 survived, where the first
of those three SURVIVED above. So the line stays for capacity and each half of it
is independently load-bearing, which the combined mutant alone would not have
shown.

The open question of what size blocks is answered as a bound rather than a
threshold: 1 MiB per stream blocks on this platform. The finding stays open on
the half it is named for — `_run_bounded`'s docstring still credits redirection
with promptness `Popen.wait` supplies, and no `-k` can assert prose.

## Closed 2026-08-10: the prose now says what the sweep says

`_run_bounded`'s docstring separates the two departures rather than deriving both
from the 40.1 s measurement: the tree kill is what bounds the call, and the
redirection buys capacity, cited to this file. The case that holds the capacity
half is renamed off the verdict it does not reach —
`test_an_oracle_that_outgrows_the_pipe_buffer_still_finishes` — and its docstring
now says that its oracle is talkative on the baseline too, so what it establishes
is that such an oracle finishes, with the false KILLED left to
`test_an_oracle_talkative_only_on_the_mutant_is_not_scored_killed` beside it.
Nothing measured here; the two claims this file's `consequences` name as prose
defects are the prose that changed, and a later reader checks them by reading the
same two docstrings.
